# Awesome LLM Agents

### 从研究方向到独立选题：LLM 与 Agent 的科研地图

**理解一个领域，不只是知道有哪些论文，更要知道问题从何而来、已有方法走到了哪里，以及下一步值得研究什么。**

本仓库面向正在进入 LLM 与 Agent 研究的读者，以关键问题为线索，连接领域综述、经典工作、前沿方法与研究机会。内容覆盖 **16 个研究专题、综述导读、Hot Words 和 2050 条文献记录**，希望为建立个人研究框架、比较技术路线和形成研究想法提供起点。

项目以 Agent 为主线，同时纳入模型训练、架构、效率、多模态与具身等相关研究。持续完成任务的能力既取决于模型，也取决于工具、记忆、环境和执行框架；理解这些层次之间的联系，是这张地图的重要部分。

## 科研地图：从了解工作，到形成判断

科研地图是一套能够不断修订的理解框架。它不仅记录论文，还组织问题、方法与证据之间的关系，帮助读者逐步形成六个层次的判断：

1. **领域结构**：辨认主要研究方向，以及它们在系统、方法和应用层面的联系。
2. **问题结构**：找到社区持续投入的关键问题，理解其价值、困难与研究对象。
3. **历史脉络**：追踪问题如何形成、方法如何演变，以及里程碑工作改变了什么。
4. **前沿边界**：比较近期方案解决了哪些困难，又受到哪些假设、成本和失效条件限制。
5. **研究机会**：将尚未解决的困难转化为能力目标、可检验的假设或新的实验对象。
6. **选题判断**：结合问题价值、已有证据与自身资源，判断哪些机会更值得投入。

**建立地图，为独立提出研究想法提供基础，但不会自动给出一个好的选题。** 从“还有什么能做”到“为什么现在值得做”，仍需要具体问题分析、基线实验与持续验证。本仓库提供组织信息的框架和线索，鼓励读者在此基础上形成自己的判断。

## 内容设计：六类材料怎样共同支撑这张地图

### 1. 分类目录：先看见领域的覆盖面

文献库以整理时 AlphaXiv 近 90 天按点赞数排序的高关注论文为基础，保留 **2050 条记录**，并按主要研究问题归类。关注度用于发现值得追踪的线索，不作为论文质量或研究价值的排名。完整条目见 [catalog/](catalog/README.md)。

这里采用便于浏览的粗粒度分类，而不是唯一的学科划分。例如，循环 Transformer 属于计算架构，编码 Agent 属于任务与系统方向，两者处在不同维度，也可能在同一项研究中交叉。主归属与关联方向共同支持检索；没有独立成章，并不意味着某个问题不重要。

### 2. 综述与经典工作：理解问题为什么走到今天

[综述导读](chapters/00_surveys.md)优先连接较新的领域综述与研究路线图，各专题的发展脉络则回到不限发表时间的经典工作，解释关键概念、技术转折与方法之间的继承关系。

寻找重要工作时，可以留意它是否在多篇综述中反复出现、是否承担关键论证，以及是否改变了后续研究的任务、方法或评价方式。引用次数是线索之一，真正需要理解的是它解决了什么问题，又为后来的工作留下了什么。

### 3. 前沿关键问题：把近期论文放回研究上下文

综述帮助建立全貌，但快速变化的方向还需要继续追踪具体工作。[chapters/](#topics)围绕近期论文组织前沿分支，为每个问题补充背景、方法比较、局限与研究机会，而不是仅按发布时间排列题名。

例如，在技能库扩展后，系统如何低成本找到适用技能，并在没有合适候选时选择不用？在自改进系统中，模型与执行框架怎样共同更新，收益又如何迁移到新任务？这些问题连接多篇论文，也为进一步设计实验提供了更具体的对象。

### 4. Hot Words：从新名字找到具体机制与机会

[Hot Words](chapters/17_hot_words.md)整理 JEV、harness、Agent Skills、OPD、递归自改进与 long-horizon 等概念，追溯其来源、背景和相关工作。

新术语可以帮助发现正在聚集的研究问题，但名称本身并不构成技术贡献。本章重点区分模型名称、系统组件、训练方法与能力目标，让读者能够从一个热词继续追问：它改变了哪个环节，与已有方法有什么关系，还有哪些问题需要解决。

### 5. 技术报告：理解前沿模型的能力起点

判断一个研究问题是否仍有价值，需要了解前沿模型已经能做什么，以及这些能力通过怎样的训练与系统设计获得。[前沿技术报告](chapters/15_frontier_reports.md)连接各家通用旗舰，以及语音、多模态、表格、推荐等专门系统的技术报告、模型卡与发布博客。

讨论围绕模型结构、数据与后训练、推理配置和任务能力展开，帮助区分底座模型已有的能力、执行框架带来的收益，以及仍值得单独研究的缺口。它为选题和基线选择提供背景，而不是把不同条件下的分数合并为一个总榜。

### 6. 基础资源：在问题驱动下补足知识

阅读前沿工作不必以读完全部基础文献为前提。遇到强化学习、蒸馏、注意力或缓存等概念时，可以先查[前置知识](docs/llm_primer.md)与[术语表](docs/glossary.md)，再按需进入[经典论文与学习资源](#foundations)。

也可以借助大模型解释术语、梳理前置依赖和比较阅读笔记，再用原论文、代码与实验核对关键判断。目标是补足理解当前问题所需的知识，并及时回到研究问题本身。

## 如何使用：沿问题深入，而不是按目录读完

刚进入领域，可以先从[综述导读](chapters/00_surveys.md)和 [Agent 全局总览](docs/overview.md)认识主要方向；已有研究兴趣，则可以直接进入对应专题。各章的经典脉络、前沿分支与研究机会可以交叉阅读，无需从第一章依次通读。

一条可行的路径是：**选择方向 → 锁定关键问题 → 追溯代表工作 → 对照近期方法 → 提出并检验研究假设。** 查找更多相关论文时使用[全量目录](catalog/README.md)；需要跨方向连接时，可参考[研究问题](docs/research_questions.md)、[跨方向研究机会](docs/learning_path.md)和[跨专题研究进展](docs/after_snapshot.md)。

### 从研究机会到选题，还需要哪些判断？

“现有方法存在局限”只是起点。进一步判断是否值得做，可以从四个方面检查：

- **问题价值**：解决它会改变什么能力或使用条件？它是关键瓶颈，还是某个设置中的局部现象？
- **实际缺口**：在合适的强基线、工具和预算下，问题是否仍然存在？新的模型进展是否已经改变了前提？
- **可检验性**：能否提出清楚的假设，设计对照，并让正面和负面结果都提供有效信息？
- **投入与积累**：数据、算力、环境和验证成本是否可承担？工作能否留下可复用的方法、任务或经验？

## 整理原则与共同维护

本项目侧重广泛覆盖与问题之间的联系，通过人工整理与大模型辅助构建。分类、概念解释和研究机会都需要持续修订，尤其是涉及定义、方法归因与方向判断的内容。正文尽量保留原始引用和影响结论的实验条件，便于结合原文、代码与领域经验继续检查和深化。

欢迎把这里当作构建个人科研地图的起点：重新组织方向、补充遗漏工作、修正已有解释，并根据自己的实验不断更新判断。地图的价值在于帮助理解和探索，而不在于把某一种分类或某一次整理固定为标准答案。
