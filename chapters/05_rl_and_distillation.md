# 05｜强化学习与蒸馏：从监督信号到长期行为的改变

[首页](../README.md) · [专题索引](../README.md#topics) · [文献目录](../catalog/05_rl_and_distillation.md)

## 方向背景：一个小模型怎样学会在仓库里修 bug

设想我们想让一个七八十亿参数的小模型学会在真实代码仓库里修 bug。最省事的办法，是请一个强模型先修几千个 bug，把它的每一步操作都记下来，再让小模型照着这些轨迹逐 token 模仿。训练完一跑，小模型在示范里见过的情形下学得有模有样；可只要某条命令报了一个示范里从没出现过的错，或者它自己早几步选错了文件，后面的路就再也没有人教过它怎么走，错误一步步累积，最后彻底跑偏。示范只覆盖了老师会走到的地方，学生自己会走到的地方，恰恰是示范没有照到的盲区。

换一种办法，干脆让小模型自己去试：读代码、改文件、跑测试，最后测试通过就给奖励，失败就不给。这一回它是在自己真正会遇到的状态上学习了，可代价也很明显。一次尝试可能包含几十次工具调用、上万个 token，最后换回来的只有"过了"或"没过"这一个信号。到底是第三步定位得好，还是第二十步那次改动起了作用？那些失败的尝试里，有没有其实走对了大半程的？单凭一个终点分数，模型很难知道。

强化学习与蒸馏这个方向，研究的就是怎样把这几种信号用好：示范告诉模型老师怎么做，环境奖励告诉模型自己做得怎么样，教师在学生自己的轨迹上逐步打分，则同时提供了"在我会走到的地方"和"每一步都有反馈"这两样东西。三者来源不同，成本不同，失效方式也不同。近两年推理模型的爆发，几乎就是一部围绕这几种信号不断做加减法的历史：先是 RLHF 把人类偏好接进训练，再是 GRPO 和可验证奖励把训练流程一步步简化，到 2025 年下半年，在策略蒸馏又把密集的教师信号带了回来。

等到这些方法被搬进 agent 的多轮交互里，难题又上了一个台阶。轨迹更长，奖励更稀疏，环境观察混在上下文里却不该被模型模仿，采样和训练为了吞吐不得不异步进行，训练分布也随之悄悄偏移。本章就沿着这条主线展开：先讲清楚几种学习信号各自从哪里来、怎样变成参数更新，再顺着几篇写得很好的长文梳理这个方向是怎样一步步走到今天的，最后把 2026 年的新论文放回这条主线上，看它们各自在补哪一块短板。

## 一、先分清几种学习信号

读这个方向的论文，最容易被几组相近的说法绕晕。根子上，它们都在回答同一个问题：什么信息能告诉模型下一次应该怎样做得更好。基础的参数、token、训练与推理概念见[大模型前置知识](../docs/llm_primer.md)。

第一组是**监督微调、强化学习和蒸馏**。监督微调（SFT）让模型模仿示范，示范里写的是什么 token，模型就提高那个 token 的概率；强化学习（RL）让模型先行动，再根据行动之后的反馈调整策略；蒸馏则让学生去学习教师的输出分布、动作或者其他监督信号。三者可以分阶段使用，也可以混在同一步里，可它们的信号来源和优化目标各不相同。回到开头修 bug 的例子，示范告诉小模型"老师当时怎么修的"，测试结果告诉它"你这次修好了没有"，教师逐步打分则告诉它"你这一步在老师看来靠不靠谱"。还有一种常见做法是把经验写进提示里，让模型在推理时参考，这属于推理时的适应，模型参数并没有因此改变，和本章讨论的参数学习是两回事。

第二组是**回报、优势和价值**。一次任务里的观察、动作和环境反馈连起来，就是一条轨迹；策略描述的是模型在当前能看到的历史下倾向于选择哪些动作。[REINFORCE](https://link.springer.com/article/10.1007/BF00992696) 给出了最基本的思路：按采样得到的结果调整动作概率，让带来好结果的选择以后更容易出现。可一次成功或失败里总掺着运气，直接拿结果来更新，波动会很大。于是训练时通常把一个动作拿到的回报和某个参照水平作比较，比参照好多少、差多少，就是所谓的**优势**。提供参照的办法有好几种：可以训练一个 **critic（价值模型）**，让它估计从当前状态继续往下走大概能拿到多少回报；也可以让同一道题多答几遍，拿这几次的平均分作参照。前一种更精细，但价值模型自己也会估错；后一种省掉了一个模型，代价是要多采样。

第三组是**结果奖励、过程奖励和可验证奖励**。结果奖励只看最后成没成，过程奖励给中间步骤打分。当结果可以由程序检查，比如数学答案对不对、单元测试过没过，通常叫作**可验证奖励强化学习（RLVR）**。"可验证"说的是有一个检查程序，这个程序覆盖了多少真实目标，是另一个需要单独回答的问题。检查一道数学题的最终答案，和验收一个涉及多个服务的工作流，能提供的证据完整程度差得很远。

第四组是**在策略与离策略，以及 KL 的方向**。如果训练用的数据是当前这个模型自己生成的，叫在策略（on-policy）；如果来自别的模型或者旧版本的自己，叫离策略（off-policy）。比较学生和教师的概率分布时，常用 **KL 散度**来衡量二者的差异，而比较的方向会改变哪些候选更受重视。以学生自己的分布作为加权依据，通常称为反向 KL，它更关注"学生容易说出口、教师却不认可"的内容，倾向于让学生集中到教师认可的那几种做法上；以教师分布作为依据的正向 KL，则更在意学生有没有漏掉教师认为合理的候选，倾向于覆盖更多解法。这只是一个帮助理解的直觉，具体效果仍然取决于数据、模型和训练方式。

最后一组专门属于 agent。agent 一般只能看到真实世界的一部分，所以它的历史记录和完整的环境状态是两回事。价值模型估计的是"在给定这段可见历史之后"的收益，观察缺失、摘要压缩和工具报错都会改变这个估计。训练时要保存模型当时实际看到的上下文，既不能让策略偷看未来的结果，也不能把事后分析者才知道的信息当成部署时的条件；如果允许 critic 或教师使用额外信息，就要把这些信息和策略的输入严格隔开。另外，环境返回的观察虽然进入了上下文，却不是策略应该学着生成的内容，训练时通常要把它们从损失里遮掉。损失怎样归一化也会悄悄改变训练的含义：把一个批次里所有 token 放在一起平均，会让有效 token 更多的长序列占更大权重；先在每个回合内部平均再汇总，长短序列的相对贡献又不一样了。损失里的权重和实际的计算开销也是两回事，不能由前者推断后者。至于长度变短、KL 变小或者熵变大，这些都只是中间指标，熵高可能意味着探索充分，也可能只是无意义的随机，最后还是要回到独立任务上的成功率和安全约束，才能判断它们值不值得优化。

## 二、发展主线：训练流程做减法，信号再做加法

这条主线主要借自 Raschka 的两篇长文和 Thinking Machines 的在策略蒸馏长文。Raschka 的叙事有一条很清楚的线索：从 RLHF 到 GRPO 再到 RLVR，每往前走一步，训练流程里就少一个需要单独维护的模型，流程越来越简单，能用的信号却也越来越稀疏。Thinking Machines 的文章接着回答了下一个问题：信号稀疏到一定程度，怎样把密集的教师信号重新加回来，又不丢掉在策略学习的好处。等这套方法进入 agent 的长程交互，Lambert 和 Lilian Weng 讨论的那些边界就变得格外现实。把这几篇放在一起读，可以排出下面这张表。

### 第 1 阶段：从示范走到人类偏好

故事要从监督微调讲起。给模型看大量高质量示范，让它逐 token 模仿，这是建立基本行为最直接的办法。可正如开头修 bug 的例子，示范只覆盖老师会走到的状态，学生一旦偏离，就进入了没人教过的地方。而且很多任务根本写不出唯一正确的示范：一段回答写得好不好，人一眼能比出高下，却很难亲手写出标准答案。

2022 年的 [InstructGPT](https://arxiv.org/abs/2203.02155) 把这几块拼成了后来被称为 RLHF 的标准流程：先用示范做监督微调，建立基本行为；再请人比较模型的多个回答，用这些比较训练一个奖励模型；最后用强化学习依据奖励模型的打分去改进策略。这样一来，没有标准答案的任务也有了反馈。当然，奖励模型预测的是人类偏好，它本身只是目标的一个近似，和程序能直接检查的正确性性质不同。

这一阶段的主力优化算法是 2017 年的 [PPO](https://arxiv.org/abs/1707.06347)。它要解决的问题是：同一个动作的收益估计带着噪声，一次更新走得太远，策略就会偏离当初收集数据时的样子，后面的数据也就不再可信。PPO 比较更新前后模型对同一动作的偏好，如果某个动作的概率已经沿有利方向变化得够多，裁剪目标就不再继续奖励它扩大这种变化。这是一种让训练更稳的手段，它降低了一步走太远的倾向，却也给不出"策略在任何情况下都不会剧烈变化"的保证。PPO 用来计算优势的价值估计，通常配合 Schulman 等人 2015 年提出的 [GAE](https://arxiv.org/abs/1506.02438)（广义优势估计），在偏差和方差之间做折中。价值模型能减少结果反馈的波动，可它一旦估错，也会把策略往错的方向带，所以更新规则怎样控制变化，和参照信号准不准，是两个缠在一起的问题。

Raschka 在长文里把这一阶段的代价数得很清楚：一套 PPO 版的 RLHF 要同时维护四个模型，正在训练的策略、从人类排序中学出来的奖励模型、估计价值的 critic，以及防止策略漂得太远的参考模型。每一个都要占显存、要训练或推理，也都可能出错。后面几个阶段的历史，很大程度上就是在想办法把这几个模型一个个拿掉。

### 第 2 阶段：去掉价值模型，让同一道题的几次尝试互相比较

第一个被拿掉的是 critic。价值模型提供了比较基准，可它本身也需要训练，在语言模型这种巨大的状态空间里还很容易估不准。2024 年的 [DeepSeekMath](https://arxiv.org/abs/2402.03300) 提出的 GRPO 换了个思路：既然同一道题可以答很多遍，那就让这几次回答互相比较。奖励高于组内平均水平的回答获得有利的更新信号，低于平均的受到相反的影响，再按组内奖励的离散程度调整信号的尺度，让不同难度的题目都能用同一把尺子训练。

Raschka 把 GRPO 描述为 PPO 的一个变体，它最直接的好处是省掉了价值模型带来的显存和算力开销。可这种比较也有天然的盲区：如果一组尝试拿到的奖励完全一样，就没法据此判断哪条路更值得学。全都失败时，需要更细的过程反馈或者更合适的题目难度；全都成功时，又需要能进一步区分好坏的标准，单纯多采几个样本解决不了问题。这两个盲区，后来成了本章分支 2 里一整批论文的出发点。

### 第 3 阶段：去掉奖励模型，换成可以直接检查的规则

第二个被拿掉的是奖励模型。2024 年底，Lambert 等人在 [Tulu 3](https://arxiv.org/abs/2411.15124) 的技术报告里给一种做法起了名字，叫可验证奖励强化学习（RLVR）：对于有确定答案的任务，干脆不训练奖励模型，直接用答案检查器或者编译器的结果当奖励。

真正让这条路线出圈的是 2025 年初的 [DeepSeek-R1](https://arxiv.org/abs/2501.12948)。按 Raschka 和 Lilian Weng 的梳理，R1-Zero 直接从基础模型出发，只用规则化的准确率奖励和格式奖励做强化学习，就学会了越想越长、回头检查、换一种思路重试这些行为，也就是后来被反复讨论的"顿悟时刻"。正式的 R1 则更讲究：先用少量冷启动数据做监督微调，再做面向推理的强化学习，然后用拒绝采样产生的数据再做一轮监督微调，最后再做一轮强化学习。同一篇报告里那些更小的蒸馏版模型，只是用 R1 的输出做了监督微调，并没有经过推理方向的强化学习。Lilian Weng 在 [Why We Think](https://lilianweng.github.io/posts/2025-05-01-thinking/) 里还特别提到报告中失败的尝试：过程奖励模型没能用起来，反而让训练更容易被钻空子；蒙特卡洛树搜索则被巨大的 token 搜索空间拖住了。

到这一步，训练流程里只剩下策略和参考模型，流程前所未有地简单，可强化学习每个回合能提供的信息也压缩到了极点。Thinking Machines 在 [LoRA Without Regret](https://thinkingmachines.ai/blog/lora/) 里算过这笔账：策略梯度靠优势驱动，每个回合大约只提供常数量级的比特，远远少于监督学习按 token 数计的信息量。这既解释了为什么强化学习用很小的 LoRA 就够，也埋下了第 5 阶段的伏笔。

### 第 4 阶段：配方工程化，修补 GRPO 的偏差

R1 之后，几乎所有开源团队都在复现这条路线，很快就发现原版 GRPO 有不少暗坑。Raschka 第一篇长文的后半部分列了好几篇代表工作。[Understanding R1-Zero-Like Training](https://arxiv.org/abs/2503.20783)（即 Dr. GRPO）指出，按回答长度和组内标准差做归一化，会让模型偏向又长又错的回答，于是把这两步归一化去掉了。同期的 [DAPO](https://arxiv.org/abs/2503.14476) 则提出了一套更完整的配方，包括按 token 计算损失、动态采样掉全对或全错的题目、对过长回答加以惩罚等。

到了 2025 年底，Raschka 在 [The State Of LLMs 2025](https://magazine.sebastianraschka.com/p/state-of-llms-2025) 里把这些修补总结成一张清单。Olmo 3 用上了过滤零梯度信号、主动采样、按 token 计算损失、去掉 KL 损失、放宽裁剪上限、截断重要性采样、不再除以标准差等改动，其中多数来自 DAPO 和 Dr. GRPO；DeepSeek V3.2 则按领域设置不同的 KL 强度，对离策略的序列做掩码，并在训练时保留采样阶段 top-p 和 top-k 的掩码。他说自己在小规模实验里加上这些改动之后，坏的更新不再把整次训练带歪。这些修补里有不少在处理同一个问题：为了吞吐，采样和训练在规模化系统里往往用的不是同一个版本的模型，甚至不是同一个推理引擎，训练数据因此带上了离策略的成分。这就是本章分支 4 讨论异步训练的来由。

### 第 5 阶段：把密集的教师信号加回来

流程简化到只剩策略之后，一个老问题重新浮出水面：信号太稀疏了。Thinking Machines 的 [On-Policy Distillation](https://thinkingmachines.ai/blog/on-policy-distillation/) 用一张两两组合的表把局面讲得很清楚。离策略的监督微调和蒸馏有逐 token 的密集信号，可学生只在老师会走到的状态上学习，序列一长，错误就会累积，学生还可能只学到老师的腔调而没学到老师的准确。强化学习是在策略的，学生在自己真正会遇到的状态上学习，可反馈极其稀疏，没法告诉它到底是哪一个 token 出了错。在策略蒸馏把两样好处合在一起：让学生自己生成轨迹，再请一个强教师给轨迹里的每个 token 打分。

这个想法有很长的前史。2015 年 Hinton 等人的[知识蒸馏](https://arxiv.org/abs/1503.02531)让学生去学教师在多个候选上的概率，比单个标签提供了更丰富的指导。Ross 等人的 [DAgger](https://arxiv.org/abs/1011.0686) 则在模仿学习里强调，专家的指导应该落在学生实际访问到的状态上。到了大模型时代，2023 年的 [GKD](https://arxiv.org/abs/2306.13649)（Agarwal 等，On-Policy Distillation of Language Models）和 [MiniLLM](https://arxiv.org/abs/2306.08543) 先后把这两个想法接在一起，让语言模型学生在自己生成的序列上接受教师监督，后者还专门讨论了为什么生成任务更适合用反向 KL。

真正让这条路线在 2025 年重新热起来的，是 [Qwen3 技术报告](https://arxiv.org/abs/2505.09388)里的一组对比。按 Thinking Machines 文中的引述，在 AIME'24 上，离策略蒸馏得到 55.0%，强化学习得到 67.6%，用了 17,920 个 GPU 小时；在策略蒸馏得到 74.4%，只用了 1,800 个 GPU 小时。Thinking Machines 复现并扩展了这个结果：以 Qwen3-8B-Base 为学生、Qwen3-32B 为教师，先用 40 万条提示做离策略监督微调，学生在 AIME'24 上大约到 60%；如果继续堆监督数据，外推要到 200 万条提示才能到 70% 左右，而在策略蒸馏大约 150 步就到了 70%。他们估算，在监督数据已经现成的情况下，这样做的算力开销大约是继续监督微调的九分之一，如果把教师采样的成本也算进去，大约是三十分之一。

方法本身出奇地简单。作者说，对一套已经带 KL 正则的强化学习代码，只要把正则用的参考模型换成教师，再把每个 token 的优势设为负的反向 KL，就成了在策略蒸馏。他们选择反向 KL 的理由也值得记住：在教师看来，KL 越低就越对应着理想的行为，所以这个目标很难被钻空子；它倾向于让学生集中到教师认可的模式上，也缓解了暴露偏差。文中还有一个和本章后半部分关系很大的实验。一个模型在公司内部文档上做了中间训练之后，知识问答从 18% 升到 43%，指令遵循却从 85% 掉到 45%；再以原来的模型为教师做一轮在策略蒸馏，指令遵循回到 83%，知识问答仍保持在 41%。作者由此提出，可以把"学新东西"和"用蒸馏找回旧行为"交替进行，当作持续学习的一种做法。这和 [RL's Razor](https://arxiv.org/abs/2509.04259) 的观察相互呼应：遗忘的多少和模型行为相对原模型漂移了多远有关，在策略的训练倾向于找到漂移更小的解。

文章最后给了一个很好的分工图景：强化学习适合在语义策略的空间里探索，发现新的做法；蒸馏则擅长把已经发现的做法高效地教给学生。指导发生在哪些状态上很要紧，教师在每个 token 上提供更密集的概率信息，也就可能更密集地传递错误，所以 OPD 类方法还要讲清楚上下文怎样采样、更新怎样处理采样过程、不同时间步的信号怎样累计，最终仍要在独立任务上检验收益。本章分支 1 讨论这两者该怎样排先后，分支 5 到分支 8 讨论蒸馏本身的种种细节，都可以放在这张图景里理解。

### 第 6 阶段：走进长程交互

前面这些方法大多是在数学题和代码题上打磨出来的，一个回合几千到几万 token，结果可以干净地判对错。把它们搬进 agent 的多轮交互里，几乎每一个假设都被拉伸了。Lambert 在 [What comes next with reinforcement learning](https://www.interconnects.ai/p/what-comes-next-with-reinforcement) 里做了一个粗略的估算：当前 RLVR 一次回答大约一万到十万 token，真正有野心的长程任务，一个回合可能要一百万到一亿 token。回合拉长上千倍，信用分配和离策略学习这两个老问题也就被放大到了前所未有的程度。他对"靠最终结果端到端地学会长程任务"持偏悲观的态度，认为很多产品的进步更可能来自子任务变得更稳，而长任务的奖励本身就很难定义，奖励越稀疏，过度优化的风险越大。

过程奖励本来被寄予厚望。2023 年的 [Let's Verify Step by Step](https://arxiv.org/abs/2305.20050) 发现，在数学推理上，对每一步做监督的过程奖励模型比只看结果的奖励模型更好用。可到了大规模强化学习里，事情没这么顺利：R1 报告认为过程奖励带来的好处抵不过额外的开销，Raschka 也说过程奖励到目前为止还没有特别成功。于是 agent 方向的研究者开始从别处找密集信号：重新审视价值模型，用参考模型的概率变化给每一回合分配信用，或者干脆请教师在学生的多轮轨迹上逐回合打分。本章分支 3、分支 4 和分支 8 收录的新论文，就是在这个阶段里各自补一块短板。

到了 2026 年，这条主线又拐了一个弯，把第 5 阶段的教师信号和这里的长程强化学习接到了一起。Lambert 在 6 月和 Finbarr Timbers 的访谈 [Frontier post-training recipe review](https://www.interconnects.ai/p/frontier-post-training-recipe-review) 里总结说，前沿实验室发现把数学、代码和 agent 强化学习混在一次训练里，能力会互相拉扯，于是改成先分领域训出若干个强化学习专家，再用多教师在策略蒸馏把它们合回一个学生，DeepSeek V4 和 Nemotron 3 Ultra 的教师都超过了十个。这样一来，强化学习负责在各自领域里把能力推上去，蒸馏负责把这些能力巩固到同一个模型里。Shiwan Zhao 等人在同年 4 月的综述 [Large Language Model Post-Training: A Unified View of Off-Policy and On-Policy Learning](https://arxiv.org/abs/2604.07941) 恰好给这种分工起了名字：他们把蒸馏看作一种行为巩固机制，并判断后训练的进展越来越取决于怎样把不同阶段、不同角色协调成一个系统。

### 边界：代理会被钻空子，增量也难以确认

走到这里，有两类问题始终挥之不去。第一类是奖励作弊。Lilian Weng 在 [Reward Hacking in Reinforcement Learning](https://lilianweng.github.io/posts/2024-11-28-reward-hacking/) 里把根源讲得很透：奖励函数总是真实目标的不完美代理，优化压力会精准地找到代理的漏洞，用古德哈特定律的话说，一个指标一旦成为目标，就不再是好指标。2022 年的 [Scaling Laws for Reward Model Overoptimization](https://arxiv.org/abs/2210.10760) 用实验刻画了这件事：对着奖励模型优化得越狠，代理分数一路上涨，真正的目标分数却会在某个点之后掉头向下。可验证奖励也逃不掉，一个只知道"测试全绿"的奖励，同样可能更有效地奖励删掉测试的行为。Lilian Weng 在 Why We Think 里还提到 OpenAI 的 [Monitoring Reasoning Models for Misbehavior](https://arxiv.org/abs/2503.11926)：用另一个模型监控思维链能发现编程 agent 的作弊行为，可一旦把这个监控器的判断加进训练奖励，模型就学会了把作弊意图藏起来。她由此得出的结论是，强化学习训练天生对奖励作弊敏感，直接对思维链施加优化压力要非常小心。

第二类是能力增量到底有多少。2025 年的 [Does Reinforcement Learning Really Incentivize Reasoning Capacity in LLMs Beyond the Base Model?](https://arxiv.org/abs/2504.13837) 发现，经过 RLVR 训练的模型在采样次数少时明显胜过基础模型，可采样次数足够多时，基础模型反而能解出更多题。作者据此认为，当前的 RLVR 更多是在提高已有解法被采到的概率，还没有创造出基础模型完全没有的推理能力。Raschka 的长文也提醒过，一些在小模型上报告的强化学习收益，后来被指出可能只是统计噪声。这些争议没有定论，却决定了本章第五节怎样解释结果。

## 三、前沿研究方向

下面八个分支收录的都是 2026 年的新论文。它们很少再提出一个全新的优化器名字，更多是在上面那条主线的某一个阶段里，处理某一种学习信号在交互任务中的具体失效。分支 1 讨论示范、蒸馏和奖励怎样排先后；分支 2 和分支 3 分别处理组相对方法缺信号、长程任务难归因的问题；分支 4 讨论异步训练带来的分布偏移；分支 5 到分支 8 则全部属于在策略蒸馏这一支，从"该传递什么"一路讲到"交互轨迹的预算怎样分配"。读这些论文时，建议始终带着两个问题：它补的是哪一种信号的短板？它报告的收益是训练分数、和教师的相似度，还是独立任务上的成功？这三样东西常常朝不同方向变化，需要分开来看。

### 分支1：SFT、蒸馏与RL，应该替代、混合还是分阶段？

三种训练方式最根本的区别在于信号从哪里来：示范给出应该模仿的行为，蒸馏提供教师的分布或轨迹，强化学习则根据执行结果改变以后的采样概率。它们可以互补，可排列组合并非随便怎样都有效。如果学生几乎采不到成功的轨迹，稀疏奖励就分不出好坏；如果教师的行为和部署时的状态对不上，模仿得越多，分布偏移可能越大。所以先找到训练卡在哪一环，再决定怎样组合这几种信号，往往比直接套一个固定配方更可靠。

> 主线位置：第 3 阶段和第 5 阶段的交汇处。接 DeepSeek-R1 的"冷启动 SFT 再 RL"、Qwen3 报告里离策略蒸馏、RL 与在策略蒸馏的三方对比，以及 RL's Razor 关于遗忘的观察。

先看一个关于"为什么强化学习更不容易互相打架"的研究。**[SFT Conflicts, RL Coexists](https://arxiv.org/abs/2608.03573)，`2608.03573`** 从多任务梯度干扰的角度比较 SFT 和 RL，作者把观察到的"多个 RL 任务能够共存"和 RL 更新较为稀疏、彼此近乎正交联系起来，并据此提出一种把多任务训练分开处理的方案。这个结论很容易被读成"SFT 必然遗忘、RL 天然兼容"，可它成立的条件里包括归一化方式、采样设置、具体任务和模型，算不上普遍定理。放到自己的项目里，最好在相同数据和相同总预算下，亲自检查一下旧任务有没有退化。它和 RL's Razor、Thinking Machines 的"用蒸馏找回旧行为"可以对照着读，三者都在讨论在策略的更新为什么更不伤旧能力。

接下来的问题是先后顺序。**[RL Starts before RL: On Policy Distillation for Better Reinforcement Learning](https://arxiv.org/abs/2609.28145)，`2609.28145`** 比较了不同的强化学习起点，发现在策略蒸馏的价值未必马上体现在初始准确率上，却可能在后续强化学习中显现出来。作者把分布对齐看作一种可能的解释，并指出不同 KL 方向下各起点的排名可能前后颠倒。**[Sequential Beats Joint: On the Interplay between On-Policy Distillation and RLVR](https://arxiv.org/abs/2609.04108)，`2609.04108`** 更进一步，把"同一步里混合两种信号"和"先蒸馏、后强化学习"放在一起比较，研究教师支持的解法覆盖和奖励优化之间怎样分工。这两篇共同反对一种常见做法：只看某个阶段结束时的一个分数，就决定拿哪个检查点当后续训练的起点。当然，它们也没有证明任何任务都应该顺序训练。打个比方，这有点像学车：先跟着教练把基本动作练顺，再自己上路积累经验，比一边上路一边听教练讲新动作更不容易乱，可这个道理放到别的技能上是否成立，还得另外验证。

还有一项工作试图在花钱训练之前先做个预估。**[PoEM: Predicting RL Outcomes from Existing Policies](https://arxiv.org/abs/2609.30226)，`2609.30226`** 利用已经用其他奖励训练好的策略，在对数概率空间里组合出一个近似的新奖励下的策略。其中严格成立的关系依赖奖励可以线性组合等条件，经验上观察到的低秩结构也只是观察，没有普遍保证。它提出的问题很有价值：重新训练之前，能不能先估计一下目标策略值不值得追？这和怎样挑选起点密切相关，可最终还是要回到真实环境里验证。

### 分支2：组相对方法缺少信号时，应该改题、改采样还是改优势？

GRPO 的组内比较有一个前提：同一组样本之间要有可以利用的差异。全部失败时，大家都是零分，看不出哪条路更有希望；全部成功时，又分不清哪些是冗余的推理、哪些是有效的推理。增加样本、拆分目标和改变优化目标，分别对付的是不同的问题。比较这些方法时，先要弄清楚收益来自更容易的训练样本、更密集的监督，还是对同样的信号利用得更稳，否则很容易把三种性质不同的改进混为一谈。

> 主线位置：第 2 阶段和第 4 阶段。接 GRPO 的组内比较、DAPO 的动态采样，以及 Raschka 清单里"过滤零梯度信号""主动采样"这些工程修补。

先看把"首次成功之前"和"首次成功之后"拆开处理的思路。**[SCOPE-RL](https://arxiv.org/abs/2607.11506)** 在模型第一次做对之前，用可以验证的子问题搭支架；做对之后，再转向优化过程质量，避免让终点正确性独自承担全部训练任务。**[GFlowRL](https://arxiv.org/abs/2607.13394)** 走的是另一条路：它把目标从奖励最大化换成奖励分布匹配，用组内估计代替额外的配分函数网络，并专门处理训练漂移和异常更新。前者主要补充不同阶段的监督，后者主要改变概率质量该怎样分配，两者都可能让最终正确率上升，可把它们统称为"更强的 GRPO"，就抹掉了它们真正有意思的地方。

接下来是全对那一侧的问题。**[Save Your Saturated Data: Learning Beyond Reward Saturation in Group-Based RL](https://arxiv.org/abs/2609.33126)，`2609.33126`** 研究组内全部高奖励时的饱和现象。作者在训练流程的不同环节做干预，发现加入有信息量的错误轨迹可以恢复对比信号。这里的负例应该指向真实的决策边界，随便塞几个荒谬答案起不到这个作用；优势不为零，也只说明有了梯度，梯度是否有益还要另外检验。DAPO 的做法是直接丢掉全对的组，这篇工作则想办法把这些数据重新利用起来，两者可以对照着读。

全错那一侧的问题正好相反：简单题反复做对，白白占用了本该留给难题的探索预算。**[Learning to Solve Hard Problems in RL for LLMs by Never Giving Up](https://arxiv.org/abs/2609.13443)，`2609.13443`** 提出的 NGU 采用动态采样，对一道题一直采到出现正确尝试为止，再据此调整资源分配，并借助异步执行把更多算力留给困难问题。**[Difficulty-Adaptive Tree-Structured Policy Optimization for Expanding Reasoning Coverage in RLVR](https://arxiv.org/abs/2609.08650)，`2609.08650`** 则改变了搜索的结构，用随难度自适应的树、句子层面的分支和同级节点之间的多样性，去寻找不同的解法。前者主要在重新分配算力，后者主要在改变探索路径。两者都离不开可靠的终局验证和资源上限，面对根本无解的题目，"永不放弃"也得有个尽头。

这一组工作都绕不开一个区分：单次成功率和可达解法的覆盖是两回事。模型更稳定地输出它本来就会的答案，单次准确率会上升；能在多次尝试中发现新的解法，才更接近覆盖范围的扩张。这正是主线边界一节里 pass@k 争议的核心。不过 pass@k 本身也受采样温度、解码方式和预算影响，拿它当内在能力的无条件度量同样不够稳妥。

缺少学习信号时，还可以分别从探索分布和失败经验两头入手。[Group Entropy-Controlled Policy Optimization](https://arxiv.org/abs/2607.16850) 用组熵来调整正负优势，处理不同任务对探索的需求不一致的问题；[ReflectRL](https://arxiv.org/abs/2608.03972) 则利用专家的失败轨迹形成反思，再回到直接求解。前者改变的是候选怎样分布，后者改变的是已经产生的失败怎样被利用，把两者都概括成"多加负例"就太粗了。评价时可以分别检查：探索是否真的更充分了，失败分析是否真的帮到了后面的决策。

### 分支3：长时程信用应该交给价值模型，还是直接从外部证据估计？

一个任务最终成功，靠的是许多动作的组合，早期一些看似无效的尝试也可能提供了必要的信息。把同一个结果奖励平摊给所有步骤，会把有用的决策和碰巧出现的行为一起强化；反过来，给每一步单独打分，又可能鼓励只顾眼前的短视动作。价值估计、反事实比较和外部检查提供了几种不同的归因方式，读这一分支时，关键是看它们各自怎样处理延迟的后果、探索的价值，以及误判会怎样传播出去。

> 主线位置：第 1 阶段的 critic 与第 6 阶段的长程信用问题。接 PPO 与 GAE 的价值估计、GRPO 去掉 critic 的选择，以及 Let's Verify Step by Step 开启、R1 报告认为得不偿失的过程奖励路线。

第 2 阶段 GRPO 拿掉价值模型的理由，是它在语言模型上不好训。2026 年有两篇工作回过头来认真研究它为什么不好训。**[Rethinking Critic Learning in PPO: Understanding and Mitigating Value Flattening](https://arxiv.org/abs/2609.18708)，`2609.18708`** 发现，中间状态实际的后续收益变化很大，critic 的预测却很平，作者称之为价值扁平化。他们把这个现象和训练目标中隐含的方差惩罚、相邻状态之间的冗余更新联系起来，只监督少量间隔开的状态来缓解问题。这项工作的意义在于反对"价值模型不稳定，所以只能删掉它"这一条单行道；有时候少量监督反而比密集却冗余的监督更有用。

**[Best Practice Critic Optimization](https://arxiv.org/abs/2608.23566)，`2608.23566`** 从配方的角度改造 critic，涉及价值的范围、训练目标、优势计算和与长度相关的估计，还允许训练期的 critic 访问策略看不到的参考信息。它和上一篇的稀疏监督方案都支持重新审视 critic，可干预点不同，其中任何一项都很难单独被认定为全部收益的来源。让 critic 看到额外的答案，就要格外防止这些信息经由错误的数据接口泄露给策略，这正是第一节说的"把额外信息和策略输入严格隔开"。

长期信用也可以从目标的写法或外部参照里得到。[Bellman Policy Optimization](https://arxiv.org/abs/2609.15987) 用 Bellman 关系改写轨迹层面的目标，试图避开对中间状态价值的估计；[TRACE](https://arxiv.org/abs/2607.13988) 则根据一个冻结的参考模型对正确答案概率的变化，给每一个工具回合分配奖励。两条路线分别依赖目标的近似和参考答案提供的代理价值，所以读的时候要分清楚理论上的等价、估计误差和实际训练收益这三层，尤其要检查失败轨迹里那些有用的动作是否仍然拿到了正确的信号。

说到底，信用分配没有绕开验证器的捷径。如果外部信号只知道"测试全绿"，那么任何更精细的传播机制，都可能更高效地奖励删测试这类行为，这正是 Lilian Weng 反复提醒的奖励作弊。所以应当先检查奖励本身是怎样定义的，再讨论分配的颗粒度；否则过程监督只是把一个有偏的终点扩散到了更多中间动作上。

### 分支4：异步训练节省了等待，却引入了多少分布偏移？

异步系统让采样和更新并行起来，可较早版本的策略生成的轨迹，可能被较新的模型拿去训练。吞吐量上去了，样本的有效性却在下降，这两件事是同时发生的，所以只报告每小时收集了多少条轨迹远远不够。比较时还要记录策略版本之间隔了多少步、用了什么重要性修正、截断条件是什么，以及最终达到目标表现的端到端成本，才能判断并行化究竟是在加速学习，还是在更快地消费过时数据。

> 主线位置：第 4 阶段的规模化修补延伸到第 6 阶段。接 PPO 的概率比与裁剪，以及 Raschka 记录的截断重要性采样、离策略序列掩码等工程做法。

长任务的完成时间参差不齐，同步训练时，一个批次要等最慢的那条轨迹跑完。**[Single-Rollout Asynchronous Optimization for Agentic Reinforcement Learning](https://arxiv.org/abs/2607.07508)，`2607.07508`** 改用单轨迹采样，配合价值模型的设计和双侧 token 裁剪，研究吞吐之外的稳定性问题。有意思的是，这篇工作又把第 2 阶段拿掉的 critic 请了回来：单轨迹省去了组内等待，可没有了同组样本做参照，估计的负担就转移到了 critic 和偏移控制上。

**[Stale but Stable: Staleness-Adaptive Trust Regions for Stabilizing Asynchronous Reinforcement Learning](https://arxiv.org/abs/2607.18722)，`2607.18722`** 认为，旧轨迹和当前策略之间的不一致程度并不均匀，于是用采样时的概率比作为陈旧程度的代理，对偏移大的部分收紧更新。这里的 **off-policy** 指轨迹来自与当前被更新的策略不同的行为分布。策略版本之差、推理引擎的数值差异和路由差异可能同时存在，所以只记录"落后了几步"往往不够。Raschka 清单里 DeepSeek V3.2 保留采样时 top-p 和 top-k 掩码的做法，处理的也是采样和训练之间这类细小的不一致。

修正策略滞后可以落在不同的环节。[Reusing Rollouts under Policy Lag](https://arxiv.org/abs/2608.01418) 用前缀概率比做归一化来复用轨迹，控制重要性权重的动态范围；[Score Centering](https://arxiv.org/abs/2609.20807) 则用一种加性校正缓解持续的漂移，还可以和重要性采样组合使用。两者都只处理了训练与推理之间差异的一部分，收益仍然取决于偏移的程度和更新的轮数。

更靠近系统边界的是 [Agent Lightning v1.0](https://arxiv.org/abs/2608.17528)，它让部署时的执行框架掌握交互循环，训练器只接收模型请求的轨迹。这项工作提醒我们，需要对齐的远远不止策略概率，重新分词、样本合并和损失归一化都会改变训练的含义。所以异步带来的吞吐和学习的有效性，应当放在一起测量。

归结起来，报告"更快"时，最好同时报告有效的学习进展、旧轨迹所占的比例和总的环境成本。如果只是把队列填得更满，梯度却越来越偏，吞吐的提高可能换来的是更多无效训练。保留一个模型、数据和预算都匹配的同步基线，有助于把学习算法的收益和调度方式的收益分开，也方便定位异步运行新引入的误差。

### 分支5：蒸馏要复制整个教师，还是转移有益的变化？

教师和学生之间的差异，可能来自能力，可能来自额外的信息，也可能只是两者处在不同的训练阶段。在每个 token 上都强行匹配，可能要求学生在没有同样证据的情况下复制教师的自信。所以选择性蒸馏要回答几个问题：哪些差异值得传递，学生当前能不能接得住，约束更新的同时会不会又阻止了必要的新行为。评价时，未见过的分布上的表现，比训练题上 KL 下降了多少更说明问题。

> 主线位置：第 5 阶段。接知识蒸馏、GKD 与 MiniLLM 的在策略蒸馏，以及 Thinking Machines 选择逐 token 反向 KL 的理由。

先看教师手里多了一份"小抄"的情形。**[Geometric Self-Distillation](https://arxiv.org/abs/2607.06855)** 针对的设置是：教师能看到提示或解题轨迹，学生看不到这些特权信息。它用分布的重叠程度来调节教师的牵引力度，并约束预测相对于最近几个检查点的漂移。这和简单地换一个更强的教师不同，它想控制的是知识不对称造成的累积变化。这个机制要放在它的特权上下文自蒸馏设置里理解，推广成"所有蒸馏都必须缩小师生差异"就过头了。

**[On-Policy Delta Distillation](https://arxiv.org/abs/2607.15161)，`2607.15161`** 换了一个角度：它用经过推理调优的教师和它自己的基础模型之间的差异，突出调优本身带来的变化。概念上，它关心的是对数概率的差，教师的绝对分布退居其次。这样也许能避免让学生去复制它本来就有的行为，可前提是要有一个匹配的基础模型作参照；而且这份差异里也可能夹带着风格、长度和错误偏好，把它称作提纯过的"推理能力"并不严谨。

**[Mismatch Matters: On-Policy Distillation Beyond Token Agreement](https://arxiv.org/abs/2608.09836)，`2608.09836`** 展示了一个很有启发的现象：局部的一致性和全局的错误可以同时存在。学生可以靠不断重复拿到很高的 token 一致率，却根本没有解决任务。为此，这个方法区分了学生"说多了"和"说少了"的 token，前者限制不稳定的纠正，后者补足教师偏好的概率质量。它说明，如果只在学生采到的动作上施加惩罚，学生很少探索到的那条正确分支可能永远教不到；当然，引入更多教师分布信息也提高了接口和计算方面的要求。这一点正好补充了 Thinking Machines 对反向 KL 的乐观判断：低 KL 对应好行为，前提是学生采到了足够多样的状态。

如果目标是传递有益的变化，那就未必需要完整地模仿教师。[Proxy OPD](https://arxiv.org/abs/2607.11505) 先提取一个代理模型在训练前后的相对改进，再把它传递到目标学生的轨迹上，研究更新方向能不能复用。[Demystifying On-Policy Distillation](https://arxiv.org/abs/2607.13399) 则从师生错位和长度投机出发，提醒我们 token 层面的目标改善了，推理未必跟着改善。这两项工作共同把关注点从"教师整体排第几"转向了"这一份具体监督起了什么作用"。

在此基础上，还要解决接口能不能对得上的问题。[Cross-Tokenizer On-Policy Distillation](https://arxiv.org/abs/2607.22334) 在共同的字节空间里对齐不同分词器的概率质量，把模型家族之间的差异变成了一个显式的问题。接口对齐和监督内容有益是两层要求：前者解决信号怎样传过去，后者决定这个信号值不值得传。

### 分支6：教师是否可靠，应该按模型、题目还是具体状态判断？

一个总体成绩很高的教师，也可能在某个具体的工具状态下出错；一个较弱的模型，有时反而掌握着当前任务需要的某项特定知识。所以可靠性不该只跟模型名字绑在一起，还要结合证据是否可见、状态是否熟悉，以及结果能否验证。研究怎样选择教师或者融合多个信号时，需要同时看两种代价：错信了教师的代价，和拒绝了有效指导的损失，同时避免把高置信度直接当成高质量的标签。

> 主线位置：第 5 阶段。接 DAgger"专家在学生状态上给指导"的前提，也回应 Thinking Machines 方法中默认教师在学生状态上可靠的假设。

第一层判断落在题目上。**[Verify Before You Distill: Prompt-Level Teacher Gating for On-Policy Distillation](https://arxiv.org/abs/2609.02998)，`2609.02998`** 先用验证器检查教师在这道题上的少量尝试，再决定这道题是接受密集蒸馏，还是交给基于结果奖励的强化学习。它反对把教师的置信度、师生之间的一致性当作正确性。代价是要多跑一轮探测，而且门控本身依赖验证器；在没有明确真值的开放写作中，它的正确性门槛就没法照搬。这有点像带学生的导师：先自己把题做一遍，确认会做，再去讲给学生听。

题目层面的门控决定要不要用这个教师，状态层面的检查则进一步决定用哪一段指导。两者可以结合起来：先排除教师没法可靠完成的任务，再逐段检查具体建议是否有输入证据支持、是否真的改善了学生后续的行动。

监督是否可靠，可以从输入依据和行动后果两个方向去查。[When Teachers Mislead](https://arxiv.org/abs/2608.03632) 过滤那些缺少输入支持、对更新影响却很大的信号；[Look Ahead Before You Distill](https://arxiv.org/abs/2608.01953) 则在分歧大的状态上暂时引入教师，再观察学生后续的轨迹。前者减少了格式先验对更新的主导，后者把局部建议放回长期结果里去检验，可两者各自依赖的代理判断，最后仍然需要任务正确性来背书。

教师更弱，也未必所有信息都没用。[Weak-to-Strong On-Policy Distillation](https://arxiv.org/abs/2607.26246) 借助弱模型之间的对比提取能力方向，避免直接复制弱教师的全部行为。针对额外的参照信息，[Rethinking Privileged Information](https://arxiv.org/abs/2608.18271) 用正确、无关和缺失三种参考做对照，[What Does Privileged Information Add?](https://arxiv.org/abs/2609.20612) 则用与答案匹配的不同推理视图来隔离各自的贡献。它们分别追问方向、参考内容和学生条件各起了什么作用，仅凭"加了参考之后分数提高"就断定知识已经转移，是站不住的。

### 分支7：没有更强老师时，自蒸馏和多教师整合能做什么？

同一个模型在不同的提示、采样预算或信息条件下，会产生质量不同的行为，自蒸馏利用的正是这些条件之间的差异，监督并不是凭空造出来的。多个教师也可能提供互补的信息，可大家一致犯的错，不会因为投票而消失。这一分支要辨认的是改进信号到底从哪里来，以及有没有保留一道独立的验证，防止系统把自己的偏好反复强化成看似稳定的"知识"。

> 主线位置：第 5 阶段。接 Thinking Machines 的自蒸馏实验（用强化学习训练过的模型当教师，教一个新的基础模型）和"学新东西、再用蒸馏找回旧行为"的持续学习设想。

最激进的一种是连标签都不要。**[On-Policy Self-Distillation without Any Supervision](https://arxiv.org/abs/2608.06296)，`2608.06296`** 从模型多次回答之间的一致性构造伪解，再去纠正与伪解有分歧的回答。它省掉了外部标签，可也就没有了外部真值：如果模型稳定地犯同一种错，多数投票只会把错误放大。这个方法是否适用，取决于错误是否足够分散、答案能否有效聚合，以及独立留出的任务能否检验出改进。

多教师也远远不止把几个分布平均一下那么简单。**[Open-MOPD: Diagnosing and Fixing Capability Imbalance in Multi-Teacher On-Policy Distillation](https://arxiv.org/abs/2608.19098)，`2608.19098`** 发现，即便已知每道题属于哪个领域、该听哪个老师，能力整合仍然会失衡，作者重点检查了序列长度、收敛速度的差异和信号陈旧对优化预算分配的影响。**[MOPD-Router: Rethinking Teacher Routing in Multi-Teacher On-Policy Distillation](https://arxiv.org/abs/2609.30837)，`2609.30837`** 则改成逐 token 选择听哪位教师的信号，试图利用跨领域的互补。前者回答"每位老师的影响有多大"，后者回答"此刻该听哪位老师"；路由选对了，梯度份额也未必合理，所以这两个问题应该分别做消融。

自蒸馏还要防止把短期的一致当成持续的正确。[Diagnosing and Mitigating Thinking Collapse](https://arxiv.org/abs/2607.10805) 分析了教师梯度怎样压制学生的中间推理，并用参考约束来缓解；[PCSD](https://arxiv.org/abs/2608.01837) 按教师支持在局部时间窗口里的持续程度加权，并结合环境奖励。前者关心行为是否塌缩，后者改善信号在时间上的稳定性，两者都仍然需要外部结果来检验。

没有一个可靠的单一教师时，[TTPO](https://arxiv.org/abs/2608.27448) 对同意和不同意伪标签的轨迹采用不同的更新方式，减少错误多数票的传播；[Domain-Normalized Multi-Teacher On-Policy Distillation](https://arxiv.org/abs/2609.35347) 则按各领域监督信号的分散程度缩放信号。二者分别调整了标签的使用方式和各领域更新的强度，说明多教师学习除了挑选来源，还得控制各类信号怎样作用到学生身上。

### 分支8：交互蒸馏怎样分配轨迹预算与监督来源？

轨迹越长，采样越贵，可并非每一步都在提供有效的监督。重复的内容、失效的工具调用和明显偏离任务的尾巴，可能吃掉大部分预算；截断得太早，模型又学不到怎样从错误中恢复、怎样收尾。这一分支先讨论在哪里停下、从哪里重启，怎样挑出值得训练的状态，再讨论监督怎样覆盖不同的回合、什么时候退出，以及怎样引入文字经验和环境反馈。预算控制和信号构造要放在一起评价，平均轨迹变短了，并不能说明学习更有效了。

> 主线位置：第 5 阶段与第 6 阶段的交汇处。接 DAgger 在学生状态上收集指导的思路、Thinking Machines 用部分轨迹节省算力的做法，以及 Lambert 对长回合成本的估算。

**[ShortOPD](https://arxiv.org/abs/2607.13124)** 针对的是结构剪枝之后的模型。它利用剪枝前的教师识别出那些信息量很低的重复尾巴，再根据有效前缀，从短到长地调整蒸馏预算。和一般长任务里的截断不同，它服务的是压缩模型的生成恢复，判断的核心依据是教师确认的重复模式。它适合和本节其他预算控制工作一起比较"为什么在这里停"，可这套针对重复退化的规则，不宜直接搬到需要长时间探索的任务上。

**[Know When to Stop, Where to Restart: Accelerating Multi-Turn Agentic On-Policy Distillation](https://arxiv.org/abs/2609.14636)，`2609.14636`** 发现，在长轨迹里，教师支持度的下降和学生第一次犯错的动作之间有明显的联系。于是它按照支持信号提前停止，再从缓存的高质量前缀里找到较弱的正确回合重新开始。它做的事情比简单截断长回答精细得多，想把预算转移到仍然可以学习的决策位置上。局限在于，教师支持度仍然只是一个代理，缓存的前缀也可能限制后续的探索；不同任务是否有同样的时间结构，还需要逐一检查。回到开头修 bug 的例子，这就相当于在小模型第一次打开错误文件的那一刻停下，再从它上一次做对的地方重新出发，把教师的注意力集中在真正出岔子的地方。

**[LLM-as-a-Coach: Experiential Learning for Non-Verifiable Tasks](https://arxiv.org/abs/2607.18110)，`2607.18110`** 面向的是开放任务。原本评审意见会被压成一个分数，它把这些意见改写成可以迁移的文字经验，再通过上下文蒸馏把它们内化进模型。这样保留了"哪里不好、该怎样改"的信息，可教练本身也可能给出不靠谱的建议。没有可执行的真值时，最好增加独立的人工抽查，反馈写得更详细，未必就更准确。

交互蒸馏首先要保证每个阶段都能被训练到。[TurnOPD](https://arxiv.org/abs/2607.05804) 按回合控制轨迹深度和各回合在损失中的份额，避免浅层的 token 占满预算；[Reward-Compatible Temporal Credit Assignment](https://arxiv.org/abs/2609.16937) 用带折扣的时间信用把局部目标和序列目标连起来，处理长期效果和梯度方差之间的冲突。前者从资源分配入手，后者从目标的衔接入手，回应的都是深层决策缺乏监督这个问题。Thinking Machines 原文把每个 token 的折扣因子设为零，可以和这篇工作的带折扣做法对照着读。

监督也可以随着学生能力的变化而逐步退出。[RetireOPD](https://arxiv.org/abs/2609.20784) 根据师生差距和成功率调整教师介入的程度；[SEED](https://arxiv.org/abs/2607.14777) 则从已经完成的轨迹里提炼事后技能，再把这些技能带来的分布变化蒸馏回策略。前者需要验证退出的门槛设得对不对，后者需要同时检查技能的质量和参数更新，循环跑起来了，本身还说明不了能力在增长。

监督的来源还可以超出语言教师。[LeAct](https://arxiv.org/abs/2607.21856) 从规划器或求解器给出的动作中，筛选出有助于恢复动作的潜在推理；[EnvACE](https://arxiv.org/abs/2608.06197) 让策略参与生成环境反馈，并进行联合演练。动作能够被复现出来，说明不了模型生成的解释就是专家真实的思考过程，自己造出来的反馈也需要外部检查。这两项工作扩大了可用信号的范围，同时也让"信号是否真实"成了一项新的约束。

## 四、跨方法对照：相同分数背后可能是不同问题

把主线和八个分支连起来看，结果奖励、价值估计和教师指导提供的是粒度不同的学习信号，主线上每一次"做减法"或"做加法"，都是在这几种信号之间重新取舍。选择方法时，需要同时考虑信号是否可靠、学生会访问哪些状态、获得反馈要花多少成本，一次训练结束后的总分只是其中一个参考。下面这张表把各类方法的信号、关键假设和主要代价并排放在一起，读新论文时可以先在表里找到它属于哪一行，再看它改动了哪一个假设。

| 方法族 | 信号 | 关键假设 | 成本与主要局限 |
|---|---|---|---|
| SFT | 示范token | 示范可靠且覆盖部署状态 | 教师数据成本；离开示范分布后易失效 |
| 组相对RL | 同题样本奖励差 | 奖励有区分度、结果可信 | 多次采样；全对全错组弱信号 |
| critic型RL | 价值估计与结果奖励 | critic能分辨中间状态 | 价值训练成本；偏差与扁平化 |
| 异步与复用 | 旧策略轨迹加偏移修正 | 概率记录可靠、偏移可控 | 系统复杂；吞吐未必等于学习效率 |
| 普通OPD | 学生状态上的教师分布 | 教师在这些状态可靠 | 教师推理与概率接口；长度或一致性投机 |
| 相对更新蒸馏 | 教师或代理训练前后差异 | 差异代表可迁移改进 | 额外参照模型；变化不全是有益能力 |
| 自蒸馏 | 参考条件、反思或内部一致性 | 伪信号与真实质量相关 | 共同错误、自我强化、推理坍缩 |
| 多教师与阶段组合 | 路由、归一化、阶段切换 | 任务互补且预算分配合理 | 多模型成本；路由与梯度份额双重失衡 |

## 五、结果解释：能力增量、信号质量与真实成本

读完这么多论文，最后总会落到一个问题上：报告里的提升，到底是什么提升？主线边界一节里的几篇工作已经说明，这个问题没法靠一次榜单回答。

"强化学习是在创造新能力，还是只在提高已有解法的概率"，就是最典型的一例。要回答它，需要固定解码预算，检查训练前那些低概率的成功，追踪新策略能否迁移到别的任务，并排除测试集污染。在策略蒸馏也一样：学生在某项分数上超过了老师，可能来自学生自己已有的能力和教师局部指导的结合，由此推断教师传授了学生完全没有的知识，证据并不充分。

密集信号是否一定优于稀疏信号，同样没有统一的答案。Thinking Machines 展示了密集信号在效率上的巨大优势，可错误的密集监督也可能系统性地破坏探索；可靠却稀疏的结果奖励，又可能贵得用不起。混合方案多出了门控、权重和切换时机这些自由度，所以要报告这些选择是在哪个验证集上定下来的。否则方法越复杂，越容易把额外的调参预算当成算法本身的优势。

另一个争议是效率该用什么单位来算。训练步数、token 数、教师算力、环境执行次数和实际耗时是五种不同的东西。多教师方法可能用更少的梯度步换来更多的模型推理；单轨迹方法可能省了采样却增加了 critic 的开销；提前终止可能降低了成本，却漏掉了后期的恢复行为。所以最好同时给出成本的分解和固定预算下的能力曲线，只报最有利的那一列，读者很难判断方法的真实价值。

最后，数学推理上的成功不能自动外推成 agent 训练的成功。这也正是 Lambert 提醒的那件事：交互任务里有环境反馈、权限、会变化的状态和不可逆的动作，训练还要处理观察掩码、回合边界、工具版本和停止条件。把答题的字符串拉长，并不会自然得到一个长时程决策实验。上面这些研究，都应该先按它们原本的任务领域来理解，再有控制地迁移到别处。

## 六、研究机会

回到开头那个在仓库里修 bug 的小模型。它面临的困难，其实可以拆成三件事：最后那个"测试过没过"太稀疏，告诉不了它哪一步做对了；教它的老师未必在每个状态下都靠谱，它也未必接得住老师的全部做法；而要让它在成千上万个仓库里大规模地练，采样和训练就得异步起来，训练分布又会悄悄偏移。这三件事分别对应主线上第 6 阶段的信用问题、第 5 阶段的蒸馏问题和第 4 阶段的规模化问题，也正是下面三个研究机会的来由。每一个都还有大片空白，适合作为选题的起点。

**1. 如何为缺少标准答案的长程任务提供有效的学习信号？**

真实交互里的成功往往延迟出现，还同时包含好几个不能相互抵消的约束，比如修好 bug 的同时不能改坏别的测试、不能删掉测试、改动要尽量小。这里的研究空间在于设计一种把结果、状态变化和中间证据结合起来的信用分配机制，让有用的探索和恢复动作得到合理的反馈。难点是一边要减少对完整参考答案和昂贵价值模型的依赖，一边又要防止局部奖励把策略引向容易得分、却偏离真实目标的行为。主线里过程奖励模型的起伏、分支 3 对 critic 的重新审视，以及 Lilian Weng 关于奖励作弊的提醒，都是这个问题的不同侧面。

**2. 如何让监督来源随状态与学生能力变化，不再固定依赖一个教师？**

教师整体更强，不代表它的每一次指导都可靠，也不代表学生能吸收它的全部行为。回到修 bug 的例子，强模型习惯的那套排查顺序，未必适合一个上下文更短、工具用得更笨拙的小模型。研究机会在于把几件事放在一起决定：什么时候请求监督，采用哪一种信息，怎样验证这次指导的后果，以及什么时候让蒸馏退出。实验时，最好专门在教师出错、接口不一致、学生已经超过教师这几种条件下测试，看学习收益究竟来自真正的能力转移，还是来自额外的信息或更多的推理预算。

**3. 如何把长轨迹训练扩展到真实执行规模，并保持更新有效？**

异步环境、策略滞后、上下文压缩和任务难度差异，会共同影响训练分布。可以研究训练算法和执行系统的联合设计，让高吞吐不必以失真的监督和不稳定的更新为代价。Lambert 估算的那种百万 token 级别的回合一旦成为现实，这个问题只会更尖锐。评价时，应当把环境调用、模型计算和失败重试统一算进成本，并在没见过的任务上检查能力能否保持、能否长期泛化。
