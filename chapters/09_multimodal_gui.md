# 09｜多模态理解与 GUI：从看懂屏幕到可靠办事

[首页](../README.md) · [专题索引](../README.md#topics) · [文献目录](../catalog/09_multimodal_gui.md)

## 方向背景：为什么多模态理解还需要行动闭环

大量数字任务的信息位于图像、视频和图形界面中，仅处理文本无法充分观察环境。多模态模型让系统能够读取这些信息，GUI 智能体则进一步把观察连接到鼠标、键盘和软件操作。这个方向的重要性在于扩大可访问的任务范围，尤其是没有稳定程序接口、需要通过界面执行的工作。

理解画面、定位操作目标、执行动作与确认结果是不同能力。屏幕显示的状态可能不完整或已经过时，正确识别一个控件也不保证点击时机、对象和后续流程都正确。因此研究必须把视觉证据、动作接口、任务记忆和环境刷新放在同一闭环中，而不能只用图片问答成绩推断执行可靠性。

本章从感知诊断与空间定位出发，讨论动作接口、训练反馈、工具增强、流式视频、模型压缩与跨任务安全。各分支都需要明确：输入保留了什么证据，动作改变了什么状态，以及最终结果如何在环境中得到确认。

## 先建立一张任务地图

LLM 是以 token 序列为主要接口的语言模型；VLM（视觉语言模型）增加图像编码，使视觉信息能与文字共同处理。编码器输出的 embedding 是数值向量表示，视觉 token 是模型据以计算的表示单元，并不等同于一个物体。模型拥有这些表示后，仍需外部执行器才能点击或写文件。蒸馏则让学生模型学习教师的输出分布或中间表示，教师可以是更强模型，也可以只是看到了更完整证据的同一个模型。相关前置可查[大模型入门](../docs/llm_primer.md)。

**理解**把图片、视频、声音变成可用信息；**GUI 操作**通过鼠标、键盘或界面元素改变软件状态；**生成**创造新的图片、音频或视频。读金额、填写表格、绘制流程图分别属于这三类。生成表示操作成功的图像，并不会实际改变应用或文件状态。统一模型可以承担多种工作，但它们的验收方式必须分开。

把一次操作写成“观察→状态估计→动作→执行→验证”，就能找到研究问题的位置。观察可能是截图，也可能包括网页 DOM 或无障碍树；状态还要包含已经处理的文件、未完成目标和授权范围。动作可以是坐标点击、元素操作或命令行调用。最后的验证最好读取真实文件、数据库或应用状态，而不是只听助手复述成功。

八个分支围绕这条闭环展开。感知和空间研究改善输入；动作接口、轨迹学习改善执行；工具与流式记忆改善证据获取；适配和安全决定系统能否在变化环境中持续运行。部分论文主类属于评测、空间理解或生成，纳入它们是为了分析闭环中的接口，而不是把静态问答、视频编辑都算成电脑操作。

## 经典发展：每一步增加了什么责任

视觉模型能够识别屏幕内容，并不意味着它能操作软件。完整 GUI 任务需要理解目标对象，找到可以行动的位置，再利用反馈持续推进。经典工作逐步连接这些环节：图文对齐扩大语义覆盖，视觉指令学习支持按需求理解，界面定位与交互环境再把理解接到行动。每多承担一层责任，都会出现前一层评测无法覆盖的错误。

为每种界面手写 OCR、按钮模板和脚本，可以完成固定流程，但一换图标、语言或布局就要维护规则。[CLIP](https://arxiv.org/abs/2103.00020) 学习成对图文之间的对应，使自然语言能够检索和描述更广泛的视觉对象。它解决表达覆盖，却主要提供匹配关系；“这像一张发票”离“把第三行税额填进指定单元格”仍很远。

[LLaVA](https://arxiv.org/abs/2304.08485) 用视觉指令训练把图像表示接入语言交互，让用户可以直接询问字段、布局和关系。问题从类别识别变为按指令作答，但问答的终点仍是文本。进入实际软件后，模型必须面对执行反馈、窗口变化、失败恢复和多步状态。[SeeClick](https://arxiv.org/abs/2401.10935) 所代表的界面定位研究，把语言目标与可点击位置联系起来；定位正确仍只是执行链的一环。

[WebArena](https://arxiv.org/abs/2307.13854) 和 [OSWorld](https://arxiv.org/abs/2404.07972) 把评测推进到交互环境。任务不再是选出正确答案，而是实际建立、修改或查找外部对象。于是数据也不能只有静态图片与答案，还要包含动作轨迹、环境复位和可执行验收。经典路线不是“识别已经解决，所以只剩规划”，而是从语义匹配到指令交互，再到可验证执行，每一步都增加了新的责任。

## 前沿研究方向

前沿研究可以沿一次交互的处理顺序展开：先判断模型是否看对，再检查能否定位和执行，随后研究轨迹与反馈怎样支持学习。工具增强、流式视频和适配机制则进一步扩展可见信息、时间跨度与部署条件。下面各分支对应不同失败位置，因此不是每个问题都能靠更强的视觉问答解决。论文比较应说明改进发生在感知、动作还是持续控制，以及局部收益能否保留到完整任务结束。

### 1. 感知与诊断：先找出最早的错误

屏幕任务同时需要识别对象、理解状态和选择动作。按钮名称识别正确，却可能忽略它已被禁用；文字识别错误，也可能通过其他布局线索补救。诊断应把输入可见性、语义理解和动作后果分开，避免把所有失败都归给视觉能力。只有知道哪个环节先限制表现，分辨率、提示和训练改动才有明确目标。

[2609.35718 · Hard Vision, Easy Vision: What GPT-6 Astra Reveals Across Computer Vision](https://arxiv.org/abs/2609.35718) 建立跨能力的视觉审计，把语义解释与几何度量、忠实重建、时序密集预测分开。方法上，它改变任务与输出类型，再与适当参考比较，观察优势是否稳定。对初学者最有用的是按任务画能力轮廓：同一个模型可能善于描述场景，却无法精确恢复距离。其局限是覆盖广不等于对每个部署流程都有诊断力；跨应用报销还需另测动作和状态。

[2607.24957 · PerceptionBench: Evaluating Atomic Visual Perception in Multimodal Large Language Models](https://arxiv.org/abs/2607.24957) 走相反方向：不追求大而全，而是从已有基准的最早失败步骤构造原子感知分类，再设计短答案题减少知识干扰。它把“看不见什么”变成可测子项。不过分类依赖当代模型与分析器，模型改变后，题目最先暴露的错误也可能改变。静态原子题适合查病因，不能直接换算整项任务成功率。

感知诊断还可以从视觉访问、设备捷径和训练覆盖三个角度细化。 [Visual Access Boundaries in Vision-Language Model Reasoning](https://arxiv.org/abs/2607.12815v1)（v1） 通过视觉访问的因果干预，检查长推理在哪些阶段仍依赖图像，帮助区分重新观察与纯文字延展。该文 [v3](https://arxiv.org/abs/2607.12815v3)已更改题名和摘要，进一步讨论属性表达与先前图像访问的影响；这里不把两个版本的实验证据混用，详见[版本说明](../docs/version_notes.md)。 [Invisible Shortcuts: Why Vision Encoders Know Your Camera](https://arxiv.org/abs/2608.05424) 研究编码器对相机、压缩等不可见痕迹的捷径依赖，提醒跨设备失效未必来自对象语义变化。

[WeVisDoc: From Coverage to Capability for Robust End-to-End Document Parsing](https://arxiv.org/abs/2609.20423) 从文档解析残余错误选择补充数据，比较增加页面覆盖与针对性修补能力的不同收益。

广域视觉审计与 PerceptionBench 的原子感知测试可以分层使用：先发现弱项，再缩小错误范围，最后通过输入干预和真实流程复测检查原因。还要保留原始输入、截图分辨率和模型配置，否则某次裁剪失误可能被误写成模型能力结论。

### 2. 空间定位：语义正确之后，还要点在正确位置

定位不仅是给物体画框，还需要处理缩放、滚动、遮挡和界面状态变化。某个坐标在上一帧有效，执行时可能已对应另一个对象。比较定位方法应区分静态截图精度与交互中的落点正确率，并检查刷新与重试策略；否则离线定位高分未必能转化为可靠操作。

“点击总额下方的输入框”混合了对象识别、相对位置和动作坐标。增加三维模型可以带来几何信息，但也增加部署开销；直接用空间问答微调，则可能在学会题目格式时损伤原有语言能力。这里的核心不是把所有视觉任务都做成三维，而是保留任务需要的空间关系。

[2608.01899 · SpatioLM: Towards General Physical Spatial Intelligence in Vision-Language Models](https://arxiv.org/abs/2608.01899) 用参数高效的空间模块激活视觉语言模型中的空间知识，并以伪深度、相机信息提供训练监督。它避免在推理时额外接入大型空间编码器，展示了“训练时补几何、部署时少加组件”的路线。局限在于伪标签质量与空间任务分布：空间问答上的改善，需要通过实际定位偏差和操作后果才能转化成 GUI 收益。

[2608.10864 · Multi-View Relational Distillation for Spatial Reasoning with Vision-Language Models](https://arxiv.org/abs/2608.10864) 不直接复制几何教师的特征，而是蒸馏跨视角图像块的相似关系。这样约束哪些区域应对应，却给学生保留适应原图文空间的自由度。它回应的是“学几何时破坏语言对齐”的冲突。代价是需要合适的多视角关系监督，且几何对应并不能解决界面语义歧义，例如两个同名保存按钮。

空间落地不仅依赖坐标预测，还涉及对象表示、证据检索以及感知与推理的衔接。 [Qwen-3D: A Generalist 3D Vision-Language Model for Spatial Understanding](https://arxiv.org/abs/2608.02980) 将描述对象与三维场景中的识别、分割联系起来，作为空间语义落地的对照，而非 GUI 成功率证据。 [ReToken: One Token to Improve Vision-Language Models for Visual Retrieval](https://arxiv.org/abs/2607.28627v1)（v1） 用轻量可学习 token 显式检索相关视觉信息，解决长上下文里“证据存在但找不到”的问题。[v2](https://arxiv.org/abs/2607.28627v2)已改名为 *ReToken: Improving Long-Context VLMs with Visual Retrieval Token*；引用时应注明所用版本。

[Mixture-of-Thought-Tokens: Unifying Perception and Reasoning for Free-form Multimodal Grounding](https://arxiv.org/abs/2607.24407) 通过空间落地的思考 token 协调细粒度感知和语义推理，适合比较定位与推理是否共享中间表示。

SpatioLM 改变空间模块，多视角关系蒸馏改变监督对象；两者都需要检验几何收益是否保留到实际任务中。公平比较应同时报告空间能力、通用问答是否退化、额外参数及延迟。还应区分语义目标选择错误与空间坐标偏移，两种失败需要不同修复。

### 3. 动作接口：纯屏幕与混合工具各付什么代价

纯屏幕接口接近人的操作方式，适用范围广，但许多步骤必须通过像素间接推断；原生工具能提供结构化结果，却依赖平台接口和权限约定。混合方案的关键不是谁更先进，而是哪些操作值得绕开 GUI、哪些必须保留可视交互，以及两种路径如何同步状态。

**[PalmClaw](https://arxiv.org/abs/2607.13027)**在手机本地管理会话、记忆、技能和执行循环，并将设备能力作为参数与结果明确的工具开放。它提供了与连续点击不同的系统边界，适合比较接口长度和权限可解释性。**[HumanCLAW](https://arxiv.org/abs/2607.27180)** 则来自身体行动评测，将高层原子技能选择与低层运动执行解耦。后者不是 GUI 基准，但能帮助理解同一个诊断原则：先控制执行端的干扰，再测模型是否选对了动作。

人能操作的软件未必提供标准 API，纯截图加鼠标键盘因而具有很广的兼容面。它的代价是每步都要重新理解界面，批量处理文件也可能很慢。引入命令行能够绕过一些界面摩擦，却同时增加权限、文件副作用和评测条件的差异。

[2607.28227 · Qwen-UI-Agent Technical Report: Toward Next-Generation Real-World Centric Foundation GUI Agents](https://arxiv.org/abs/2607.28227) 将移动端、电脑、网页和搜索环境放入统一工作流，动作空间交替容纳 GUI 与 CLI，并支持一轮产生多个动作。它还将环境与任务构建、失败诊断纳入训练迭代。方法的吸引力是把跨设备办事作为系统问题；限制是结果依赖环境基础设施和执行层，不能把整套工程收益都归到骨干参数上，批量动作也必须重新检查中途出现的弹窗。

[2608.02352 · Qwen-CUA: Native Computer Use for (almost) Everything](https://arxiv.org/abs/2608.02352) 则强调截图观察与键鼠事件，不使用 DOM、无障碍元数据和任务专用 API；它维护近期截图，并折叠更早视觉历史。这样更接近通用人类界面，却需要大量可验证交互经验。比较它与混合系统时，应先统一允许的输入和工具；否则“谁更强”可能只是“谁能直接访问文件”。其历史折叠还需要检查被压缩掉的细节是否再次成为任务关键。

对实际使用者，选择接口前先写权限表：可读哪些目录、可写哪些应用、哪些动作需要确认。效率不仅是少几次点击，也包括遇错能否恢复、是否留下可审计记录。

接口选择需要和适配数据、任务环境及可执行验收一起考虑。 [UI-Mate: Advancing Open-Weight Foundation GUI Agents with In-Context Demonstrations](https://arxiv.org/abs/2608.15930) 通过环境化训练和上下文示范帮助 GUI 模型适应新流程，比较示范提供与参数更新两种适配成本。 [CUA-Universe: A Scalable and Dynamic Environment for Hybrid GUI+CLI Agents](https://arxiv.org/abs/2609.05374) 用动态 GUI 与命令行混合任务训练，研究跨工具组合能否迁移到其他环境。

[RecreationWorld: Scalable and Verifiable Environments for Hybrid Computer-Use Agents](https://arxiv.org/abs/2609.22000) 运行参考应用产生轨迹和行为测试，把“看起来像完成”变成可执行结果检查。

### 4. 轨迹、奖励与停止：更多数据之前先保证反馈可信

交互数据会把策略和环境耦合起来。任务成功的轨迹里可能含大量无效动作，失败轨迹里也可能包含正确观察和有价值的恢复。奖励设计应区分动作有效、阶段完成和最终目标达成，并说明系统什么时候必须停下。若停止信号不可靠，模型可能在成功后继续操作而破坏结果。

静态截图标签不能告诉模型一次失败是如何发生的，成功轨迹又可能缺少恢复动作。在线强化学习能补充交互，但前提是任务可复位、奖励可信、采样预算用在有学习价值的地方。把所有状态都喂给模型，不等于增加有效经验。

[2607.11185 · SCALECUA: Scaling Computer Use Agents with Verifiable Task Synthesis and Efficient Online RL](https://arxiv.org/abs/2607.11185) 将可验证任务合成与在线训练结合，通过容器交互和多 agent 反馈构造任务，再按当前能力边界分配采样，并用视觉上下文分段缓解训练压力。这同时回应数据稀缺和训练吞吐问题。限制是自动生成的验收器也可能遗漏条件；应把独立人工任务与合成任务分开测试，确认优化的不是出题流程的固定模式。

[2607.28609 · OSReward: Instituting Standardized Evaluation for Cross-Platform Computer-Use Reward Models](https://arxiv.org/abs/2607.28609) 把视角转向裁判：用人工标注的跨平台轨迹评测视觉模型判定，再训练较低成本的奖励模型。关键负面结果是裁判存在宽松倾向，会接受未完成任务。如果奖励器相信 agent 的文字历史多于屏幕，强化学习就可能放大这种偏差。学习型奖励适合规模化筛选，文件是否存在、金额是否一致等仍应尽量确定性验证。

轨迹训练的进一步区别，在于数据如何产生、反馈针对哪个阶段，以及停止行为如何获得监督。 [HyMobileAgent: Data-Environment Co-Scaling for Efficient GUI Agents](https://arxiv.org/abs/2607.14548) 共同扩展移动端数据与环境，说明 GUI 效率不只来自参数规模，也来自任务分布与交互条件。 [Inducing Task Models from Computer-Use Traces](https://arxiv.org/abs/2608.20319) 将原始操作轨迹整理成任务层次和程序控制流，为复用流程提供比截图堆叠更结构化的记忆。

[Do GUI Agents Know When Not to Act? Enabling Conflict-Aware Termination for Multimodal GUI Agents](https://arxiv.org/abs/2609.03438) 通过冲突识别与终止机制处理不可执行指令，要求把恰当拒绝与普通操作失败分别计分。

SCALECUA 的任务合成与 OSReward 的裁判评估分别处理数据供给和信号质量，需要配合考虑。对于“文件不存在却要求发送”的矛盾任务，还需要正确停止，而不是不断重试到偶然触发奖励。

### 5. 工具增强：返回的图片真的提供了新证据吗

裁剪、放大和生成中间图像可以改变模型的观察，但并非所有额外图像都增加新信息。有些只是重新编码已有内容，有些则引入生成误差。应通过固定原始输入、比较工具结果与无工具基线，检查收益来自证据补充、注意力重分配还是更多计算，避免把更长的视觉推理链等同于更可靠的推理。

一个容易被忽略的因素是调用文字本身：目标描述、坐标和意图已经组织了问题，即使不读取返回像素，也可能帮助后续推理。要识别视觉证据的贡献，需要保留调用文字、只替换返回图像作为对照。

[2608.09682 · Thinking With Tools, Not With Pixels: Tool Calls as Text Scaffolds for Visual Reasoning](https://arxiv.org/abs/2608.09682) 保留调用文字结构，却用占位文本替代返回图片，比较完整图像工具链与只留结构的路径；它还拆分推理文字和空间代码的贡献。在所测分布中，返回图片的必要性受到挑战。结论不是图像永远无用，而是一些基准允许结构化文字携带主要信息；真正需要读取新证据的任务应成为更强对照，例如裁剪后才能识别的随机金额。

[2609.19664 · VideoResearcher: Self-Improving Tool Design for Long-Video Understanding](https://arxiv.org/abs/2609.19664) 从另一个方向改进工具：运行解决与演化两个循环，分析轨迹中的证据缺口，设计、验证并复用新的可执行工具，而不是只改提示词。它把能力提升放到外部工具设计，避免更新模型参数。局限是验证集选择和迭代预算可能带来过拟合；应记录每次新增工具的收益，并在没参与演化的视频上测试。

二者形成有用张力：一边问现有工具是否真的必要，另一边问缺什么工具。好的工具系统应先证明信息增益，再证明执行正确，最后比较总成本，而不是把工具调用次数当作推理深度。

视觉工具是否有用，需要同时检查它增加了哪些信息，以及模型能否利用这些信息。 [CausalDS: Benchmarking Causal Reasoning in Data-Science Agents](https://arxiv.org/abs/2607.08093) 用可控因果结构检查数据科学 agent 的代码、推断和适当弃答；它是证据使用的跨类对照，不是 GUI 定位测试。 [OmniReasoner: Thinking with Long Audio-Video via Native Tool Use](https://arxiv.org/abs/2607.19339) 通过原生放大工具按需获取长音视频的高保真证据，关注何时值得增加观察成本。

[Thinking Beyond Videos: Unifying Video Reasoning and Deep Research for Open-World Video Agents](https://arxiv.org/abs/2608.23329) 协调视频裁剪、多模态检索和网页研究，处理仅凭片段无法回答的开放世界问题，并带来外部来源核对需求。

### 6. 流式视频：实时回答与长期记忆互相牵制

流式系统只能利用当时已经发生的事件，不能像离线视频问答一样回看未来。它需要在响应速度、观察完整性和历史保存之间取舍；太早回答可能缺证据，持续等待又失去主动帮助的价值。比较时要固定可见时间范围，并把事件发现、时机选择与答案内容分别评价。

**[Internalized Visual Thinking](https://arxiv.org/abs/2608.15869)**在训练时联合学习文字预测与未来帧潜在表示预测，推理时直接回答，不再显式生成和重编码未来画面。它与视觉思维链的差别不只是少生成几张图，而是把部分预测能力放进训练目标。报告中的效率与准确率结果适用于所测主动视频推理设置；它并不证明所有需要视觉中间产物的任务都可以省去显式生成。

让助手看一小时会议并在需要时主动提醒，与把整段视频上传后问一次问题不同。流式系统不能偷看未来，还必须在有限内存中保留过去。只存文字摘要便宜，却可能永久丢失小字、表情或物体位置；存全部帧又昂贵。

[2608.05703 · StreamArena: Toward Continuous, Interactive, and Long-Horizon Agentic Streaming Video Understanding](https://arxiv.org/abs/2608.05703) 指出短片段、选择题评测可能让只看最后几帧的简单基线表现很好，因而构造小时级开放问答，分别测试实时感知、历史回溯、主动互动和工具使用。配套方法把低延迟前台与异步记忆后台分离。限制是前后台调度、持续预处理都应计入成本，不能只计最后回答那一步的延迟。

[2608.10949 · StreamFlow: Dynamic Memory Flows for Streaming Video Understanding](https://arxiv.org/abs/2608.10949) 在视觉编码前过滤时间冗余，并将长期内容压成可检索的视觉潜表示，回答时再按注意力需求注入历史证据。它不是简单“摘要更长”，而是改变记忆写入和读取时机。风险是过滤策略可能提前丢掉后来才重要的细节；评测需要专门安排低显著性、远距离事件，而不只问显眼动作。

流式问题与 GUI 的联系在于持续状态：都要判断哪些过去信息仍影响当前行动。不过看视频的回溯成功，不能直接当作软件任务的执行成功；应分别测试记住事实和利用事实改变状态。

流式理解中的时间处理与记忆组织相互关联，但各自改变的计算环节需要分开比较。 [VideoChat3: Fully Open Video MLLM for Efficient and Generalist Video Understanding](https://arxiv.org/abs/2607.14935) 以开放训练资源构建兼顾运动、长视频检索与直播响应的模型，便于区分骨干能力和外部记忆收益。 [Online Video Agent Harness for Long Video Understanding](https://arxiv.org/abs/2609.12818) 根据问题按需寻找证据，比较主动检索与提前密集处理整段视频的成本。

[Video-MOPD: Multi-Teacher On-Policy Distillation for Video Understanding](https://arxiv.org/abs/2609.09300) 从不同教师蒸馏理解、科学推理和时间定位能力，考察训练期多教师是否能简化部署。

### 7. 适配与压缩：丢了证据，还是不会用剩下的证据

模型变小、视觉 token 变少和数据分布变化会产生不同失败。压缩可能直接移除任务所需信息，适配不足则可能让信息仍在却不能正确使用。因此要分别测输入保真、表征能力与跨域泛化，并检查教师是否在新域可靠，而不是只把教师输出当作固定目标。

**[OnPoKD](https://arxiv.org/abs/2609.10321)**让轻量控制器结合教师、学生与零样本先验的可靠性和分歧，为样本构造动态蒸馏目标，并以验证反馈更新控制策略。控制器只在训练中使用，不改变推理架构。它研究的是视觉语言适配，不直接证明 GUI 执行收益；放在这里是为了说明弱数据和跨域条件下，如何避免把不可靠教师信号无差别传给学生。

例如，压缩屏幕输入后读错角落里的金额，需要先检查这些数字是否仍然可辨认。如果数字已经丢失，应调整观察和压缩；如果证据仍在，则可以研究训练如何帮助模型适应稀疏输入。

[2608.14144 · Self-Supervised Visual On-Policy Distillation](https://arxiv.org/abs/2608.14144) 不寻找更强教师，而是让同一个模型看原图与受损图，利用信息不对称产生自蒸馏信号。它的实验强调增强强度和任务一致性：适度退化能教学生利用证据，完全移除答案相关区域则产生无效差异。局限是训练增强必须与真实失真相关，不能用“无需人工标签”掩盖数据选择和增强设计成本。

[2609.34044 · SCOPD: Sparse-Context On-Policy Self-Distillation for Efficient Vision-Language Models](https://arxiv.org/abs/2609.34044) 在固定剪枝表示上反复采样，发现一些失败可以被恢复，提出表示利用差距；训练时先让当前稀疏学生生成推理前缀，再由拥有完整视觉上下文的教师对同一前缀提供监督，而不是直接模仿教师自己生成的整条轨迹。它说明压缩后的能力损失不全是不可逆信息损失。但多次采样诊断不是免费性能，部署比较应固定采样预算，并检查难例是否仍因证据彻底丢失而无解。

适配研究最终要回到可辨认的输入故障：低清晰度、反光、遮挡、窗口缩放或长历史压缩。把这些混合成一个平均分，可能让鲁棒性提升掩盖关键小字识别退化。

适配和压缩的结果应结合证据保留与任务迁移分析，而不能只用模型规模解释。 [Robustifying Vision-Language Models via Test-Time Prompt Adaptation](https://arxiv.org/abs/2607.09450) 用分布级对齐和动态缓存做测试时提示适配，针对对抗失真检查干净样本性能是否受损。 [OPD-V: Visual On-Policy Self-Distillation with Modality Balance](https://arxiv.org/abs/2608.05131) 通过强调或遮蔽相关区域的图像视图平衡蒸馏信号，比较不同模态监督对视觉推理的贡献。

[Where to Look Matters: On-Policy Self-Distillation for Long-Video Understanding](https://arxiv.org/abs/2608.25356) 用问题相关片段指导长视频自蒸馏，训练时提供聚焦证据，部署时仍输入完整视频。

### 8. 安全与统一接口：能跨任务复用，也能跨任务传播错误

统一接口降低集成成本，也扩大了同一条错误规则的影响范围。网页内容、截图文字和工具返回值都可能被误当成操作指令，记忆又会把影响带到后续任务。安全设计应同时标明数据来源、可执行权限和共享范围；界面统一不意味着权限也可以不加区分地统一。

能保存技能、记忆和程序的助手，比一次性问答器更有用，也产生新的信任边界。网页内容不应升级为用户授权；自动生成的工具不能因为“由自己写出”就变可信。统一理解与生成还会增加混淆：输出图像是新作品还是输入证据，必须明确。

[2608.06862 · SynChain: Inducing Computer-Use Agent Systems to Construct Their Own Attack Chains](https://arxiv.org/abs/2608.06862) 分析恶意影响怎样隐藏在持久化产物中，经由后续任务重新激活，而不需要每次都有新的外部恶意输入。它把安全评测从单次提示推进到跨任务轨迹。防御重点因而是来源、权限和状态传播，而不只是某一轮的文字过滤。所测攻击目标和任务链仍有限，不能由一次抵抗成功推断所有技能库都安全。

[2609.11244 · OmniHallu: Unified Hallucination Detection for Cross-Modal Comprehension and Generation in Multimodal Large Language Models](https://arxiv.org/abs/2609.11244) 把图像、视频、音频理解与生成中的幻觉拆成原子声明，由模态专家核对并聚合证据，再训练低成本验证器近似这一过程。它提供统一检查接口，却不能取消各模态的专业判据：音频事件次序与图像物体数量不是同一种误差。跨类纳入它，是为了设计验收层，而不是把内容真实性和操作授权合并。

安全测试应跨越任务边界：第一次任务写入了什么，第二次任务为什么读取，第三次是否改变权限。可生成界面的系统还要保存界面版本，否则重放轨迹时，原坐标可能已失去含义。

统一接口的收益与风险都可能跨任务传播，因而需要把能力复用与边界检查放在一起。 [ToolHazard: Scaling Adversarial Environments for Security Evaluation and Alignment of LLM-based Agents](https://arxiv.org/abs/2608.11878) 合成对抗环境状态测试间接指令注入，适合检查模型是否把环境内容误当高优先级命令。 [PixelUMM: Encoder-Free Unified Image and Video Understanding and Generation](https://arxiv.org/abs/2609.38597) 探索直接从像素统一图像视频理解与生成，关注共享表示，而不是将生成能力视作执行授权。

[The Interface of Theseus: The Rise of Just-In-Time Interfaces](https://arxiv.org/abs/2609.06770) 讨论按目标即时生成界面的设计方向，属于接口议题；它提出的问题是可定制性如何与可复现、可审计兼容。

## 方法比较：按需要补哪一环来选择

感知、定位、执行与验收形成不同的改进位置。真实流程中应先定位最早阻碍任务的环节，再选择空间监督、交互训练、工具或记忆机制，并检查局部改善能否保留到最终结果。

| 路线 | 主要解决什么 | 必须付出的成本 | 关键验收 |
|---|---|---|---|
| 原子感知与空间监督 | 看错、指错、几何关系脆弱 | 标注与教师监督 | 感知错误和定位误差分开 |
| 纯截图键鼠 | 缺少专用软件接口 | 长轨迹、视觉历史和交互采样 | 同样输入权限下完整完成率 |
| GUI 与 CLI 混合 | 跨应用与批量任务效率 | 更复杂的权限及副作用管理 | 实际文件和进程状态 |
| 可验证任务与在线学习 | 交互经验不足 | 环境复位、奖励器维护 | 独立任务及奖励误判率 |
| 主动工具与流式记忆 | 长视频证据不足 | 检索、存储和后台调度 | 新证据收益及总成本 |
| 压缩和自蒸馏 | 视觉计算过重 | 增强与教师训练 | 固定预算下难例保留率 |

这些路线往往需要组合，但组合前应有简单基线。若读文件即可验收，就没必要先训练视觉裁判；若工作流永远固定，脚本可能比通用 agent 更合适。选择更强系统的理由应是任务变化、信息不确定或跨工具需求，而不是名称里有更多“智能”。

## 负面结果怎样改变下一步实验

工具返回像素可能不是成绩来源、短视频基准可能被最后几帧解决、稀疏输入失败可能来自利用不稳、裁判可能系统性过宽。这四类负面结果共同要求做干预，而不只加模型：屏蔽返回图像、移除历史、固定剪枝表示、替换裁判证据，观察收益来自哪里。每次只改变一个关键因素，才能解释因果关系。

未解问题主要有三组。第一，是否存在同时要求细粒度新观察、长期记忆与真实执行的基准，而不是单项拼接？第二，奖励器和执行器共享视觉偏差时，怎样得到独立的验收信号？第三，任务、界面和权限持续变化时，怎样保留可重放轨迹，同时避免记忆中的旧假设继续支配动作？这些问题不能靠一个总成功率回答。

## 研究机会

从视觉理解走向可靠操作，需要把环境、主动观察与长期执行一起研究。下面三个方向分别扩展任务场景、改进证据获取，并检验局部能力能否组成完整的跨应用工作。

**1. 如何构造覆盖真实跨应用工作的多模态交互环境？**

静态截图和孤立点击难以表达软件工作中的状态依赖、等待、权限及跨应用交接。研究机会是构建可重置但保持真实约束的桌面或网页环境，并让任务覆盖自然的工具组合与失败分支。环境需要支持结果检查，而不只是动作回放，使训练与评测都能追踪信息获取、执行和交付之间的完整联系。

**2. 如何让 Agent 主动选择需要观察的视觉信息？**

全屏高分辨率输入、历史截图和工具返回之间存在成本与证据覆盖的取舍。可以研究根据当前不确定性选择裁剪、放大、重新观察或调用视觉工具，把观察当作可学习动作。关键是衡量这些选择是否保留后续任务所需信息，并区分观察缺失与推理错误，避免仅以 token 节约评价。

**3. 如何从局部感知与操作能力走向跨界面、长流程的可靠执行？**

界面变化会同时影响语义目标、空间定位和已有操作习惯。研究机会是连接任务记忆、状态确认和恢复策略，让系统在布局变化或动作失败后重新建立正确对应。评价需要改变界面、工具和任务组合，观察单项能力能否组成完整工作，而不是只扩充静态定位样本。
