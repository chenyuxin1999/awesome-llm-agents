# 13｜效率与循环架构：少算一些，真的会更快吗？

[首页](../README.md) · [专题索引](../README.md#topics) · [文献目录](../catalog/13_efficiency.md)

**阅读前置：** 本章用自然语言解释计算、缓存和运行成本之间的关系。需要补充 token、Transformer、训练与推理等概念时，可查阅 [LLM 前置知识](../docs/llm_primer.md)；比较方法时，重点看节省了哪种资源、付出了什么代价，以及实际任务是否因此更快完成。

## 1. 方向背景：为什么效率必须按完整任务衡量

智能体把模型推理、上下文管理、工具执行和多轮反馈组合在一起，计算成本会随任务长度与并行规模增加。效率研究不仅决定运行费用，也影响响应速度、可承受的探索次数以及能否在有限硬件上部署。要理解一种加速方法，首先需要区分参数规模、计算量、存储、通信和端到端延迟。

循环架构通过复用参数组织更多计算，自适应深度根据输入分配计算，缓存、量化和推测解码则改变执行方式。这些路线优化的资源不同：较少参数不必然减少运算，更快的模型内核也不一定缩短工具主导的任务。因此效率结论必须附带工作负载、硬件条件与质量约束。

本章围绕公平预算、稳定循环、动态深度、局部回流、推测解码、长上下文、低精度与服务系统展开。共同的问题是如何把局部节约兑现为完整任务收益，同时避免因减少计算或压缩状态损害正确性与可靠性。

## 2. 基础概念：建立一张不会混账的性能卡

首先分开五种预算。**参数量**描述独立权重的规模；MoE 还需分总参数与每步激活参数。**FLOPs**描述浮点运算量，不包括所有等待和搬运。**显存**包含权重、临时张量与历史 KV 缓存。**延迟**是单个请求耗时，**吞吐量**是单位时间处理的请求或 token 数。参数少不一定 FLOPs 少，FLOPs 少不一定延迟低，吞吐量更高也可能伴随更长排队。

生成过程又分预填充和解码。前者处理已有提示，后者逐步产生新内容；长输入短输出与短输入长输出的压力不同。智能体还会重复读取前缀、产生大量短调用，再等待工具返回。因此性能卡至少应记录输入输出长度、并发、到达方式、设备、精度、缓存策略、质量约束和失败重试。只测独立模型调用，可以报告模型性能，但不能冒称测过完整任务成本。

循环 Transformer 用共享层反复更新隐藏状态，好比同一套算子做多轮加工。**跨深度循环**是在同一 token 的表示上重复变换；**跨时间递归**把状态带到后续 token；**工具循环**则是模型与外部环境多轮交互。它们都叫循环，却有不同缓存、训练和验证要求。有效深度是执行路径的属性，不是模型思考质量的直接量尺。

还要区分两类加速。精确执行优化努力保持目标函数或目标分布不变，例如满足校正条件的推测采样；近似优化则接受一定误差，换取存储或运行收益，例如量化、跳层和某些缓存裁剪。近似方法并非不可靠，但应明确错误预算，报告质量—成本曲线，而不是只挑最省的一点。最终适合智能体的指标，可以是同一质量门槛下每个成功任务的时间和资源，而不只是输出速度。

### 2.1 参数复用为什么不自动减少运算？

深度循环让同一组参数多次加工一个位置的内部表示。每一轮都使用上一轮的状态和当前可用信息继续计算，但不需要为每一轮单独保存一套权重。因此，增加循环次数时，模型存储的独立参数可以基本不变，实际执行的运算却通常会增加。

如果模型宽度固定、各轮执行成本接近，多运行几轮就意味着重复完成更多次相似计算。循环之外的输入处理和输出模块还会产生额外开销；具体架构怎样组织注意力、注入状态或提前停止，又会改变每轮成本。所以，参数复用首先改变的是权重共享方式，不能据此直接推断计算量或延迟同步下降。

与不共享参数的模型比较时，相同参数量与相同计算量是两种不同条件。若希望同时匹配多项预算，可能需要调整宽度、专家配置或层布局。[SMELT](https://arxiv.org/abs/2609.01343)的意义正是在明确预算约束后再比较质量，避免把额外计算带来的收益完全归给架构本身。

### 2.2 KV 缓存的量级由哪些变量决定？

KV 缓存保存注意力计算中已经得到的键和值，使后续生成不必反复处理全部历史。它占用多少显存，取决于同时处理多少条序列、每条保留多长历史、多少层或状态组需要独立保存信息，以及每个状态包含多少数值、采用多高的存储精度。在其他条件不变时，并发增加、历史增长或独立状态组增多，通常都会扩大缓存需求。

实际分配还要考虑实现细节。不同序列的长度未必相同，分页与管理信息会占用额外空间；滑动窗口可以限制保留的历史，共享前缀和跨层复用则可能减少重复存储。因此，不能只用一个固定的每条序列开销估计所有工作负载，也不能把降低数值精度视为唯一的节省方式。

独立缓存状态组并不等于独立权重模块。循环轮次即使共享权重，也可能产生各自需要保存的键和值，所以参数复用是否节省缓存，要看具体实现。[PagedAttention](https://arxiv.org/abs/2309.06180)还提醒我们区分逻辑上需要保存的信息与实际分配效率：减少碎片和复用已有状态，可以在不缩小每个状态的情况下提高显存利用率。

### 2.3 如何把质量与成本放进同一个对照？

一种方法在增加预算后提升更快，并不意味着它在实际可用预算下已经更好。如果起点较低，较大的增幅仍可能没有追上另一种方法。因此，报告需要同时回答三个问题：使用相同预算时谁完成得更好，达到相同质量时谁消耗更少，以及在实际系统中谁更快交付结果。

这三个问题分别对应方法效果、资源效率和可部署性。比较时还应保持任务集合与质量标准一致，并把等待、工具调用和失败重试算入端到端成本。只展示一段增长趋势，或者只挑最有利的预算点，都不足以说明方案更适合真实工作负载。

## 3. 经典发展：从并行计算到资源协同

推理效率的发展并不是单纯把模型做小，而是识别时间与资源花在哪里：执行多少运算，参数和状态怎样存取，生成步骤如何调度，多请求怎样共享资源。不同瓶颈需要不同方法，所以经典路线同时包括架构、算子、缓存与解码流程。沿这些层次理解，才能区分一种方法减少了理论计算，还是减少了实际等待与数据搬运。

2017 年的 [Attention Is All You Need](https://arxiv.org/abs/1706.03762)强调基于注意力的并行序列建模；2018 年的 [Universal Transformers](https://arxiv.org/abs/1807.03819)把递归更新重新带入表示计算。这两篇不是彼此否定，而是在不同维度分配顺序计算。今天循环模型的关键仍是：什么可以共享、在哪里共享、多少轮才有用，以及训练见过的循环次数能否覆盖推理需求。

稀疏计算的经典入口是 [Switch Transformers](https://arxiv.org/abs/2101.03961)：总容量可以很大，但一次 token 只使用部分专家。它把“模型大小”拆成存储容量和活跃计算两项，同时带来路由与负载平衡问题。循环 MoE 又增加一层选择：专家是否跨层复用，复用后的角色是否仍可区分。这说明减少权重不一定等于减少沟通或调度开销。

2022 年的 [FlashAttention](https://arxiv.org/abs/2205.14135)把注意力执行中的内存访问放到中心；2023 年的 [PagedAttention](https://arxiv.org/abs/2309.06180)把 KV 管理与服务吞吐联系起来。两者分别说明，算子内部的数据搬运和多请求之间的缓存组织都是算法的一部分。论文公式没变，系统性能仍可能改变；反过来，公式层面算得更少，也可能因执行不规则而变慢。

[Speculative Decoding](https://arxiv.org/abs/2211.17192)以便宜草稿和目标验证替代每个 token 单独等待目标模型；[Mamba](https://arxiv.org/abs/2312.00752)则从状态表示出发探索序列处理的另一种资源分配。前者主要改变生成流程，后者改变信息如何保存在模型状态中。把这些历史路线并排看，才能理解近期工作为何同时研究共享权重、草稿状态、缓存压缩和服务调度，而不是只追一个“更少参数”的数字。

## 4. 前沿研究方向

前沿效率研究需要从实际瓶颈选择切入点。下面分别讨论模型计算结构、状态与缓存、生成流程和运行调度，连接单次调用与完整任务的资源分配。某项方法可以少用参数却增加通信，也可以减少生成步骤却增加预处理，因此各分支关注的不是同一个成本。比较近期论文时，需要先定位节省发生在哪一层，再观察任务质量、延迟、吞吐与峰值内存是否出现新的取舍。

### 4.1 公平比较：循环收益来自结构，还是额外计算？

让同一组参数执行多轮计算，能够在不同比增加权重的情况下改变推理深度。但用户等待的是完整结果，而不是参数文件变小，因此还需要计算增加的轮次付出了多少时间和运算。这个分支首先厘清比较对象：同样模型大小下的能力收益，与同样计算预算下的结构收益不是同一个问题。

**[Hidden Decoding at Scale](https://arxiv.org/abs/2607.08186)**沿序列维度为每个 token 引入多条内部计算流，并用流内与跨流注意力组织额外计算，避免仅沿网络深度循环。该方法保持主干层数不变，但需要继续预训练，并增加内部序列与缓存开销。适合与深度循环比较大规模训练兼容性，不能把“主干不扩大”误读成完全免训练或推理成本不增加。

**SMELT（`2609.01343`）**在每 token 运算量、非嵌入参数和 KV 缓存接近匹配的条件下研究循环 MoE，并采用中间部分层循环两次的设计。[论文](https://arxiv.org/abs/2609.01343)报告，在所拟合的计算最优前沿上节省 6.8%—18.0% 的训练 FLOPs，优势还迁移到下游基准，代码任务上的收益最大。“计算最优前沿”指不同计算预算下，通过选择模型规模和训练量所能达到的最佳损失边界。这项实验针对一个关键混杂：相同参数的循环模型可能实际多算很多；在同时匹配多项预算之后，作者仍观察到了收益。但这些结果有其模型规模、数据与拟合范围，训练计算节省也不能直接变成推理服务的相同比例加速。

**Loop the Loopies!（[`2607.16051`](https://arxiv.org/abs/2607.16051)）**同样通过计算匹配比较循环 MoE 与普通 Transformer。两篇可联合阅读，但不能只因为都说 matched compute 就默认预算口径相同：预训练数据、有效层数、激活专家数、训练时长和调参范围都可能不同。下一步需要报告完整质量—计算曲线，而不是用某个循环模型的最佳点对照普通模型的未充分调参点。

**MoRE（[`2609.18176`](https://arxiv.org/abs/2609.18176)）**把共享从整个循环块细化为邻近层的专家池复用，再用深度嵌入帮助专家识别自己正在服务哪一层。它说明参数复用有多种粒度：共享整层、共享专家、共享缓存，并不具有同一种信息约束。研究问题是哪些模块真的重复，哪些位置必须保留独立容量，而不是把所有权重共享都统一叫“更深思考”。

### 4.2 稳定循环：重复访问会改变训练动力学

共享参数被多次使用，会让同一更新同时作用于多个计算阶段。某个阶段有效的变化可能破坏另一个阶段，梯度规模和状态分布也可能随循环次数改变。因此研究稳定性时要区分初始化、归一化、训练深度和测试深度，并观察多轮状态是否收敛到有用结果，而不只是训练损失是否下降。

**DeepLoop（`2607.13491`）**指出共享参数会汇聚多次访问的梯度，并在下一次前向中再次被多次使用，因此普通深层网络的残差缩放规则不能直接照搬。[论文](https://arxiv.org/abs/2607.13491)用访问对齐来分析这种效应，并修改缩放配方。结果来自所测的小中规模语言模型，不是对任意架构稳定性的全局保证。重要对照是无复用时应基本不改变表现，启用复用后才体现针对性收益。

**Gated Recurrent Transformers（`2608.15062`）**在固定输入、输出模块之间放共享核心，并用门控调节每轮更新。[论文](https://arxiv.org/abs/2608.15062)给出一项具体的权衡：参数和峰值解码内存下降，但其某个大规模设置的编译后生成延迟仍增加。它不是失败，而是明确说明省了什么、付出了什么。**LoopMTP（[`2608.03624`](https://arxiv.org/abs/2608.03624)）**则用未来 token 目标帮助不同循环轮次承担任务，体现训练目标也可以塑造复用过程。

**Thinking with Looped Flows（[`2609.11801`](https://arxiv.org/abs/2609.11801)）**用局部去噪目标应对只反传少数循环步导致的训练困难；**Looped Transformers as Optimizers（[`2609.37379`](https://arxiv.org/abs/2609.37379)）**把状态更新解释为局部目标与优化步骤，推导循环变换。前者改变训练信号，后者约束变换结构。它们提供设计工具，却都不意味着更多轮数总有效；仍需在训练外深度和不同任务上测稳定性。

### 4.3 深度诊断与自适应：更陡的曲线也可能更差

动态计算希望简单样本早点停，困难样本多思考，但停止器也会犯错：早停可能漏掉必要推理，晚停可能强化错误循环。需要比较相同平均预算下的样本分配，而不只看最高深度时的表现。深度带来的收益、停止判断成本和分布变化后的校准都应分开测量。

**What Makes Recurrence Effective（`2609.36636`）**在知识与推理任务中比较训练内外的循环预算。[论文](https://arxiv.org/abs/2609.36636)报告推理可以受益而知识表现下降，难题也不总是从更多轮计算获益；输入输出层布局、历史状态注入和时间条件都会影响结果。因此不能把循环次数当成普遍有效的思考预算，更不能假定困难样本自动值得多算。

**Beyond Depth Truncation（`2609.19934`）**进一步质疑常用测法：截断深度同时减少模块调用、改变实际执行的不同计算，还可能把读出头放到训练外的残差分布。[论文](https://arxiv.org/abs/2609.19934)提出用控制协议拆开这些因素。它说明，即使质量随深度下降，也不能立刻证明被删的每一轮都进行了新的、有用的推理；测量干预本身也会制造损伤。

**TaH2（`2609.35748`）**研究按 token 分配循环次数。[论文](https://arxiv.org/abs/2609.35748)指出一些循环模型准确率随计算增长得更快，却仍在相同计算点落后，因为起点不同；然后用前瞻深度监督训练迭代决策器。开放问题是决策器本身的开销、误判代价与跨任务迁移。同一组质量—计算曲线应同时展示增长幅度、相同预算下的绝对水平与可达到的最好结果，不能只用斜率概括测试时扩展能力。

### 4.4 冻结模型与局部回流：不是所有循环都要重训

局部修改让现有模型重复利用某些计算，通常成本较低，却受到原模型表示和接口的限制。冻结权重不等于没有额外学习：可能仍需训练适配器、停止器或选择规则。比较方法应明确哪些组件被训练、哪些输入被重复处理，以及新增计算是否真的提供新的信息或仅重复已有错误。

**Recirculation（`2608.17981`）**研究现成模型上的推理时结构增强，把较深层信号反馈给较早位置。[论文](https://arxiv.org/abs/2608.17981)的重要限制是生成阶段额外延迟很小，但预填充需要串行处理。对于长提示、短回答的智能体，这个代价可能决定净收益；只展示生成速度会掩盖主要成本。**Write Back the Δ（[`2609.32457`](https://arxiv.org/abs/2609.32457)）**则使用层间新增信息而非整个状态作为反馈，学习选择和组合回流路径。

**T^2MLR（[`2607.15178`](https://arxiv.org/abs/2607.15178)）**把前一个 token 的中间层表示送入当前 token 的较早层，让中间计算跨时间延续。它与对同一个 token 反复完整前向不同，也与把自然语言笔记放进上下文不同。**Looped Language Models Improve Compositional Tool Calling（[`2608.18171`](https://arxiv.org/abs/2608.18171)）**把架构收益放到组合工具任务检验，研究区分孤立调用与依赖型任务。它支持任务结构值得分析，而不是把循环架构的所有收益都归为工具调用格式更准确。

这组研究共同提出：哪些状态值得再次加工，哪些状态可以跨步保留？一个可行的实验是固定底座和输出预算，分别改变反馈位置、反馈内容与循环次数。若同时增加可训练模块和测试时计算，就应承认结论属于整个新系统，不能只归功于“冻结模型也能循环”。

### 4.5 推测解码：草稿质量、缓存与工作负载共同决定收益

推测解码把一部分计算交给便宜草稿，再由目标模型检查，但草稿被拒绝时也会浪费工作。接受率会随领域、位置和上下文变化，固定草稿长度未必适合所有任务。因此应联合考虑草稿成本、验证成本、接受长度与并发条件，而不是只比较单次生成了多少候选 token。

**[AdaFlash](https://arxiv.org/abs/2607.19223)**分析扩散草稿器在不同领域和草稿位置上的接受率波动，再结合在策略蒸馏与自适应机制改善草稿。这里双向依赖既带来并行生成能力，也可能使位置间质量不均衡。其研究价值在于把草稿训练和运行时分配联系起来，而不是默认并行草稿越长越快。

**LoopSpec（`2609.17184`）**从早期循环状态产生草稿，用后期状态验证，并让未来草稿与当前验证流水重叠。[论文](https://arxiv.org/abs/2609.17184)宣称在其校正机制下实现无损解码；采样模式中的无损应理解为目标分布保持，而非任意随机运行逐 token 相同。**LoopCD（[`2610.02185`](https://arxiv.org/abs/2610.02185)）**利用早晚循环的对比信号指导选择，它是解码策略改变，不能因为也利用早期状态就被归入完全相同的无损加速保证。

**DeLS-Spec（[`2607.07409`](https://arxiv.org/abs/2607.07409)）**拆分长短上下文来改进并行草稿；**AngelSpec（[`2607.25852`](https://arxiv.org/abs/2607.25852)）**按对话与代码数学等工作负载协调草稿结构和训练数据。**H-Spec（[`2609.24197`](https://arxiv.org/abs/2609.24197)）**通过复用目标 KV 并补充末位置隐藏状态，避免维护独立草稿缓存。三者分别处理草稿依赖、数据分工和状态开销，不存在只看接受长度就能公平排出的总榜。

**Online Draft Co-Training（[`2609.07108`](https://arxiv.org/abs/2609.07108)）**研究长期强化学习训练中草稿与目标共同更新的系统障碍；**FOVEA（[`2608.22883`](https://arxiv.org/abs/2608.22883)）**则研究多模态草稿何时需要多少视觉证据。后者指出，增加视觉输入需要与草稿任务的信息需求匹配。下一步实验应同时报告草稿计算、接受率、验证成本和每请求缓存，并区分静态目标、正在训练的目标以及视觉状态不断变化的任务。

### 4.6 长上下文：压缩历史，不能把关键证据一起删掉

长上下文效率包括输入处理、缓存存储和反复读取，不是一个长度上限就能描述。滑动窗口、状态压缩和外部检索改变信息可访问方式，可能对需要精确回看的任务产生不同影响。比较时要检查质量退化发生在哪类依赖，并确认预填充与解码阶段的成本是否都被计算。

**Random Attention（`2609.03430`）**是值得先读的负结果。它保留提示，再在注意力头内随机裁剪推理轨迹，发现测试设置中复杂选择信号的收益很有限。[论文](https://arxiv.org/abs/2609.03430)把这种结果联系到提示的重要性以及文本、注意力头间的冗余。结论有条件：不是“任何 KV 都可随便删”，更不是原始提示也不重要。公平对照必须固定提示保护方式，否则实际上比较的是谁偶然保住了题目。

**A Probabilistic Interpretation of KV Cache Eviction（[`2608.28293`](https://arxiv.org/abs/2608.28293)）**把裁剪解释为期望估计，并讨论解码时对被删项的校正。**HiSparse（[`2608.07009`](https://arxiv.org/abs/2608.07009)）**面对另一种瓶颈：即使稀疏注意力只访问少量位置，全部历史仍可能占满显存，因此采用分层缓存管理。前者研究近似与偏差，后者研究状态放在哪里；不能把“选择少”直接等同于“存储少”。

状态模型提供更深层的替代。**DART（[`2608.02032`](https://arxiv.org/abs/2608.02032)）**从递归状态的键值解释改造读取方式，**Maglev（[`2608.02870`](https://arxiv.org/abs/2608.02870)）**用固定容量记忆及训练时的一致性约束，**Sparse Delta Memory（[`2607.07386`](https://arxiv.org/abs/2607.07386)）**用稀疏寻址扩大递归状态容量。另有 **Cross-Model KV Cache Transfer（[`2608.03893`](https://arxiv.org/abs/2608.03893)）**利用同家族模型间的线性关系复用预填充；**DeepSeek-V4.1-Flash（[`2609.19969`](https://arxiv.org/abs/2609.19969)）**组合跨层复用、低精度存储与重放。它们省去的状态、需要的校准以及可恢复的信息范围都不同，必须分别测长期检索与任务质量。

### 4.7 低精度：存储位数、运算精度和最终误差不是一件事

低精度可能节省权重与缓存空间，但量化、反量化和特定算子的支持决定收益能否实现。平均数值误差小，也可能在路由、长链生成或敏感决策中放大。需要报告实际内核、累加精度、校准数据和任务质量，不能只用理论位宽推算部署吞吐。

**VC-Attention（`2609.15810`）**针对视频扩散注意力，把值向量平滑与融合概率转换结合起来，分别处理量化离群值和 softmax 开销。[论文](https://arxiv.org/abs/2609.15810)同时报告算子与整段生成速度，适合学习识别两种测量层级。它不是所有文本模型的现成性能结论；硬件、序列形态和误差指标改变后，需要重新测量。

**Breaking the 1.58-bit Barrier（[`2609.16338`](https://arxiv.org/abs/2609.16338)）**从三值权重的符号分布出发研究编码，提醒我们平均存储位数与直接运算格式不同。**KronQ（[`2607.07964`](https://arxiv.org/abs/2607.07964)）**把梯度协方差信息引入后训练量化；**Quantization Degradation（[`2608.08188`](https://arxiv.org/abs/2608.08188)）**研究噪声如何产生与沿网络累积。编码与量化方法改变存储方式或误差分配，退化分析解释失效条件，不能只凭“更低 bit”推断更低延迟。

**FlashLoop（[`2609.29812`](https://arxiv.org/abs/2609.29812)）**把跨循环冗余、稀疏更新和 KV 残差量化组合起来，说明架构和低精度可以联合优化。但多个近似叠加时，分别较小的误差不一定仍然较小。值得保留的一条研究路线是依次加入每个组件，观察错误首先出现在哪类任务、哪段上下文，而不是只用平均分宣布质量几乎不变。

### 4.8 动态服务与输入表示：把收益兑现到完整请求

完整服务还包含排队、通信、媒体预处理、缓存调度和负载均衡。一个算子快了，瓶颈可能转移到其他环节；更高缓存命中也可能造成设备负载不均。端到端比较应给出请求长度与并发分布，区分冷启动和热缓存，而不是只展示最有利的一条吞吐曲线。

**[MiMo-V2.5 全流程推理优化](https://arxiv.org/abs/2607.13095)** 将滑动窗口缓存、前缀树、分布式缓存、路由和多模态预处理一起优化，展示架构上的理论节省需要工程配合。**[Non-GPU AI Accelerators 的部署实地研究](https://arxiv.org/abs/2607.08215)** 则记录特定 Ascend 软件硬件栈上 MoE 与多模态服务的算子、数值正确性和维护困难。后一项是具体配置下的现场研究，不是对所有非 GPU 平台的永久判决；两篇共同说明迁移和维护成本也是效率的一部分。

**vSkipper（`2609.37062`）**先展示跳层脱离现代服务引擎后反而变慢，再把动态路径接回连续批处理、分页缓存与计算图。[论文](https://arxiv.org/abs/2609.37062)控制提示、到达过程、输出长度和启动设置，强调何时值得执行路由。其“服务没有额外可分辨质量损失”是相对跳层检查点而言，不等于该检查点与原模型质量完全相同。这是模型误差和服务误差必须分开的一例。

**You Only Need 2/3 of the Chosen Experts（`2609.25809`）**在多种细粒度 MoE 上研究专家裁剪。[论文](https://arxiv.org/abs/2609.25809)报告指定保留比例下的平均质量与实测速率；这个比例是实验结果，不是所有模型的安全常数。应特别看任务尾部损失、路由行为和不同服务后端，因为平均不变可能掩盖少数依赖稀有专家的任务。

**Objective vs. Search（[`2609.19145`](https://arxiv.org/abs/2609.19145)）**把分词器的目标和搜索过程拆开比较。它说明，效率甚至从输入表示开始：更少 token 不一定让模型更容易学习，词表与语言覆盖又会改变公平预算。完整研究应联合报告字符或任务规模、token 数、质量与运行开销，而不是在改变分词器后仍把“相同 token 数”当成完全相同的数据量。

## 5. 跨路线对照：资源节约与适用条件

效率方法需要按节省的资源比较：减少权重、缓存或串行等待，并不一定带来相同的端到端收益。下面将各路线的节省对象、额外代价和匹配条件并列，帮助判断优势能否迁移到目标工作负载。

| 路线 | 主要节省对象 | 可能付出的代价 | 必须匹配的条件 |
|---|---|---|---|
| 循环与专家复用 | 独立权重、部分训练预算 | 更多顺序计算、训练不稳定 | 激活计算、缓存、数据与调参 |
| 自适应深度 | 不必要的重复轮次 | 决策器成本、错误提前退出 | 绝对质量和计算曲线，不只斜率 |
| 推测解码 | 目标模型的串行等待 | 草稿训练、缓存和拒绝开销 | 目标分布、草稿成本、负载 |
| 缓存裁剪与状态压缩 | 长上下文存储 | 关键证据丢失、检索质量下降 | 提示保护、序列长度、任务类型 |
| 量化与编码 | 存储、带宽、部分运算成本 | 误差累积、解码和转换开销 | 硬件、内核与端到端质量 |
| 动态服务 | 有效计算与排队时间 | 路由、同步、批处理破坏 | 到达过程、并发和延迟分位数 |

必须写进结论的负结果包括：门控循环可能省内存却增延迟；Recirculation 的预填充代价不能忽略；更陡的扩展曲线可能仍在相同预算下落后；复杂 KV 选择器可能输给保护提示后的随机基线；视频内核加速不等于智能体任务同比例加速。这些不是边角注释，而是决定方法是否适用的主要证据。

## 6. 研究机会

效率的下一步不仅是继续压缩某个组件，还包括按任务分配计算、减少完整工作流的重复开销，以及跨硬件兑现结构优势。三个方向都需要在固定质量要求下比较资源投入。

**1. 如何按任务难度动态分配计算，并保持可控的质量边界？**

不同输入和执行阶段需要不同计算量，固定深度或固定推理预算可能同时浪费简单任务资源并限制困难任务。研究机会是让循环次数、早停、搜索和模型选择依据可校准信号协同调整。评价应特别检查难例与长任务的退化，不能只用平均计算节约掩盖少数关键失败。

**2. 如何围绕完整 Agent 工作负载联合优化记忆、推理和工具执行？**

模型内核加速可能被工具等待、上下文重读和数据传输抵消。可以研究任务感知的缓存、状态压缩与调度，把信息保留和资源分配放在同一目标下优化。关键是使用真实到达过程、任务长度和并发条件，确认局部节约能够转化为端到端延迟、吞吐或成本收益。

**3. 如何让结构上的计算优势在不同硬件与服务条件下稳定兑现？**

低精度、稀疏化和参数复用的收益依赖实现与硬件支持，理论计算量不能直接预测部署效果。研究机会是联合设计结构、算子和服务策略，建立可迁移的成本模型与适配机制。应同时报告维护复杂度、数值正确性和完整任务表现，而不是只比较理想配置下的峰值速度。
