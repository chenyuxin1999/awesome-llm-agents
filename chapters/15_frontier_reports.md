# 15｜前沿技术报告：模型路线与系统能力

[首页](../README.md) · [专题索引](../README.md#topics) · [文献目录](../catalog/15_frontier_reports.md)

**相关基础：** 模型结构、训练目标、推理模式与评测协议的概念见 [LLM 前置知识](../docs/llm_primer.md)。

## 1. 方向背景：技术报告怎样连接模型与实际能力

前沿模型的进展往往同时涉及结构、数据、后训练与推理系统。技术报告把这些选择放在一起，说明模型针对什么任务、怎样训练，以及在什么条件下取得结果。相比单个方法论文，阅读报告更需要理解各组件如何共同形成能力，而不只寻找一项独立创新。

这种系统视角在 Agent 场景中尤其重要。长程任务需要模型持续处理上下文、调用工具并利用反馈；同一底座采用不同的执行框架、推理预算或缓存配置，也可能呈现不同的完成质量和成本。因此，比较对象既包括模型，也包括它实际运行的条件。

不同领域的重点又有所区别：通用模型强调能力组合，视觉模型需要保留空间细节，实时语音面对时序约束，推荐系统还受在线反馈影响。本章先建立比较维度，再按这些任务展开，最后讨论技术报告、发布材料与系统卡怎样共同解释系统表现。

## 2. 比较维度：结构、训练、推理与评价

**结构决定信息怎样被处理。** 注意力、专家路由、循环计算与跨模态表示改变模型的计算路径。比较时应看它们解决的是序列长度、容量、信息交互还是资源限制，以及相应代价落在哪里。

**训练决定模型怎样获得能力。** 数据组织、监督微调、强化学习和蒸馏作用于不同阶段。对 Agent 而言，训练环境还规定了模型能够尝试哪些行动、收到什么反馈，以及长任务中哪些行为值得保留。

**推理与运行系统决定能力怎样被使用。** 推理强度、工具接口、状态管理、缓存与请求调度共同影响结果。语音任务还涉及首块延迟和打断响应，在线推荐则需要考虑流量分配与反馈周期。

**评价把这些设计连接到具体目标。** 完成率、质量、延迟和成本各自回答不同问题。固定关键条件的比较与组件消融，有助于区分模型改进和系统整合的贡献；权重、代码、数据与环境配置则决定哪些部分可以进一步复查。

## 3. 经典发展：从模型得分到系统可检查性

技术报告需要同时回答模型具有什么能力，以及外部读者凭什么判断这些能力。因此这里先建立两类经典坐标：数据与模型文档规范解释应披露什么，各能力方向的代表工作解释方法从何而来。再进入近期报告，才能区分训练创新、系统整合与评测范围变化，而不只看一个总分或产品名称。

### 文档规范：先说明能力声明在什么条件下成立

2018 年的 [Datasheets for Datasets](https://arxiv.org/abs/1803.09010)要求说明数据动机、组成、收集过程和推荐用途；[Model Cards for Model Reporting](https://arxiv.org/abs/1810.03993)强调模型适用情境及不同条件下的表现。它们改变了阅读问题：不是只问最高分，而是问哪些人、任务和条件被评估，哪些没有。2023 年的 [Llama 2](https://arxiv.org/abs/2307.09288)可作为大型模型发布论文的历史阅读例子，学习把训练、微调与安全评测分开检查。

### 能力来源：再解释各模块解决了什么问题

披露规范帮助检查证据，但不能代替对技术的理解。不同模态的输入、输出与时序约束不同，需要回到相应路线理解报告中的设计。语音侧，[wav2vec 2.0](https://arxiv.org/abs/2006.11477)研究自监督语音表示，[High Fidelity Neural Audio Compression](https://arxiv.org/abs/2210.13438)提供神经音频压缩的代表入口；它们分别涉及理解所需表示和生成所需编码。多模态侧，[Flamingo](https://arxiv.org/abs/2204.14198)展示将视觉信息连接到语言生成的路线。今天的实时视觉和音频系统又必须处理输入持续到达、输出不能无限等待的问题，不能只搬用离线基准的解释。

表格侧，早期 [TabPFN](https://arxiv.org/abs/2207.01848)以小型表格分类的上下文学习展示基础模型思路；近期报告扩展到更复杂特征、回归、长上下文和更多推理模式。推荐侧，报告开始比较生成、排序、用户状态和在线策略控制的不同组织方式。由此可见，“前沿”不只有参数越来越大，也可能是把某类任务的状态、时序或工程约束真正纳入模型。

这些历史工作提供的是路线坐标，不是今日产品说明。新报告若把多个既有模块组合起来，贡献可能在系统整合与可扩展训练；若改变目标函数或状态表示，才需要更细的机制比较。不要因为报告没有提出全新架构就忽略工程贡献，也不要因为架构名字新就免除控制实验。

## 4. 前沿研究方向

前沿报告覆盖不同任务和发布形态，不能只按模型规模或一个总分排列。下面分别讨论各能力路线怎样组织训练、输入输出与系统接口，再比较报告提供了哪些证据。通用模型、语音、多模态、表格与推荐系统面对的约束不同，开放范围也不等同于能力范围。各分支因此先界定任务与技术对象，再分析近期报告的设计变化和可比较条件，避免把产品更新记录当作研究脉络。

### 4.1 通用旗舰模型：从模型能力到完整任务交付

通用旗舰的价值，不只是把某一类题答得更准，而是让推理、代码、视觉理解和工具使用能够共同支撑复杂工作。各家正在解决相近的问题，但技术着力点不同：有的重新安排长上下文的计算与存储，有的扩大混合任务强化学习，还有的更强调自主执行、结果检查与人机协作。本节以 Kimi、GLM、DeepSeek、Qwen、MiMo、GPT 和 Claude 的代表型号为主线，分别解释模型定位、公开技术亮点，以及这些变化为什么与 Agent 有关。

这些材料的披露深度也不同。完整技术报告可以讨论架构与训练机制，模型卡有助于区分权重版本和服务配置，发布博客则更适合了解能力重点和使用方式的变化。因此，各模型的讨论侧重其公开材料能够解释的设计：有的深入结构和训练，有的重点呈现任务能力与部署行为。

#### 4.1.1 Kimi K3：把大规模容量、长上下文与自主执行共同扩展

Kimi K3 的核心看点，是把大模型的容量扩展与持续工作能力放在同一个设计中。它不仅面向文本问答，还将视觉输入、长上下文和多步工具任务纳入通用底座。[Kimi K3: Open Frontier Intelligence](https://arxiv.org/abs/2607.24653)因此值得作为一份完整系统报告阅读：模型结构、训练环境和部署方式都围绕更复杂、更持久的任务展开，而不是只用增加参数解释能力提升。

**架构上，它同时处理序列长度与网络深度中的信息传递。** Kimi Delta Attention 参与长序列的信息组织，Attention Residuals 改变跨层信息的汇合方式；两者分别对应模型怎样利用历史，以及深层计算怎样继续使用前面形成的表示。报告还将 Stable LatentMoE 与大规模专家训练结合，试图在增加容量的同时保持训练可控。理解这组设计的重点，是哪些信息需要保留、怎样被后续计算使用，而不只是记住几个架构缩写。

**原生视觉与长上下文，使任务输入不再局限于短文本。** 代码仓库、屏幕、文档和较长的工具记录，可以在同一任务中共同构成判断依据。报告支持百万 token 级上下文，但真正的研究问题仍是模型能否从这些信息中找出有效约束，并在后续执行中保持一致。窗口更大解决容纳范围，持续正确使用信息则还需要训练与系统管理。

**后训练重点是把通用、编码与 Agent 经验组合起来。** 报告讨论监督微调、强化学习、多教师在策略蒸馏与部署条件相适配的后训练，并构建可执行、可检查的任务环境。任务不仅包含最终答案，也包含自主执行、网页开发、个人助理和代码优化等工作。不同推理强度参与训练与评价，使模型能够在不同预算下组织解题过程，而不是把最长推理固定成唯一模式。

长任务训练还依赖基础设施。Kimi K3 将持续的 rollout 状态、沙箱状态和长上下文调度作为单独问题处理；推理侧又结合前缀缓存与请求调度。它的亮点因此可以概括为：**不只训练一个能读长输入的大模型，还为它准备能够持续交互、保留进度并检查结果的训练与运行条件。** [官方仓库](https://github.com/MoonshotAI/Kimi-K3)提供权重与评测入口；比较结果时，应同时核对推理强度、工具框架和任务预算，不能仅凭上下文长度推断长期可靠性。

#### 4.1.2 GLM-5.3：以长程后训练提升复杂工程能力

GLM-5.3 的辨识度在于，它把进步重点放在已有底座怎样经过更强的后训练，而不是再次把容量扩张作为主要叙事。[官方模型说明](https://huggingface.co/zai-org/GLM-5.3)明确指出，GLM-5.3 与 GLM-5.2 使用相同基础模型，报告中的新增收益来自后训练。这为理解通用旗舰提供了一个重要对照：更强的编码和 Agent 行为，可以来自训练任务、反馈与优化过程的改变。

**它瞄准的是持续推进工程问题，而不只是生成一段正确代码。** 复杂仓库任务需要定位相关文件、理解隐含依赖、实施修改、运行验证，再根据结果继续调整。GLM-5.3 的发布材料将复杂编码与长程任务放在一起，强调模型能够在更长执行过程中继续取得进展，并以较少输出完成部分工作。这里值得关注的是行动是否更有针对性，而不是把输出缩短本身当作能力提升。

要理解它的训练基础，可以回到 [GLM-5 技术报告](https://arxiv.org/abs/2602.15763)。这一代较早的报告介绍了稀疏专家、长上下文计算以及用于提高训练吞吐的异步强化学习基础设施。它们说明该系列怎样获得持续交互训练的条件，但不能把 GLM-5 的所有机制重新写成 GLM-5.3 首次提出的贡献。5.3 更清楚的增量，是在延续的模型基础上扩大长程后训练，并检验复杂工程任务上的收益。

**安全研究能力的增长，是这次更新中另一项显著现象。** 官方材料将漏洞发现和后续安全任务的表现变化单独讨论，说明长程代码理解、工具操作和反馈利用可能同时影响安全相关能力。这表明通用工程能力的增强也可能扩展到高风险任务。因此，能力评价与授权、部署限制需要一起考察。

GLM-5.3 同时展示公开基准和自建代码评测。前者便于观察跨系统表现，后者可以深入内部工作负载，但二者不能直接当作同一种证据。[系列仓库](https://github.com/zai-org/GLM-5)保留了各代的技术和评测联系。阅读这一模型最值得追问的是：后训练在哪些任务结构上带来持续收益，哪些提升能够跨仓库、跨执行框架迁移，而不只是记住一个相对上一代的分数增幅。

#### 4.1.3 DeepSeek-V4.1：让长输入与持续执行的成本更可控

DeepSeek-V4.1 已公开的技术报告对应 **DeepSeek-V4.1-Flash**，即官方所称新架构系列中较小的通用多模态成员。本节借这份报告讨论 V4.1 的技术路线，而不把 Flash 等同于系列中的最大型号。[报告](https://arxiv.org/abs/2609.19969)从一个具体负担出发：长程 Agent 会反复读取越来越多的历史，输入处理、缓存容量和状态搬运，可能比生成答案本身更妨碍持续工作。

**第一个亮点，是区分读取输入与生成输出的计算需求。** Causal Encoder-Decoder 架构让预填充与解码采用不同的有效计算配置。模型处理长提示时，不必完全沿用生成每个新 token 的同一套成本结构。这使优化对象从单次输出速度，延伸到一次工作流反复读取上下文所付出的总成本；对于输入多、输出相对短的工具任务，这个区别尤其重要。

**第二个亮点，是把缓存压缩同时推进到结构与存储层。** Compressed Sparse Attention 2 通过跨层复用缓存与索引减少重复状态，低精度 KV 存储进一步降低空间需求；SWA Bounded Replay 则处理滑动窗口状态的持久保存与恢复。它们并不是同一个压缩技巧：有的减少需要独立保留的信息，有的改变每份状态的表示，还有的重新安排哪些状态值得长期保存。报告将这些机制与实际部署连起来，而不是只给出理论缓存节省。

**后训练也面向可执行的 Agent 任务。** 报告介绍任务合成、合成环境中的强化学习、DSec 沙箱基础设施、推理强度控制和大规模在策略蒸馏。架构提高承载长输入的效率，环境和反馈则让模型学习怎样使用这些输入采取行动。两条线共同作用，才能解释为什么该模型不只是一个压缩更强的长文本处理器。

[官方发布介绍](https://www.deepseek.com/en/news/deepseek-v4-1-flash/)将原生视觉理解、更强能力和运行效率作为这一代的共同重点。对 Agent 研究而言，它的价值在于提供了一条具体路线：**降低长期保留和反复使用任务状态的代价，再用交互训练把资源转化为执行能力。** 评价仍应区分预填充、解码、持久状态存储与端到端完成情况；缓存更小并不单独证明计划更好，也不能把某种工作负载的加速外推到所有任务。

#### 4.1.4 Qwen3.8-Max：面向完整工作的开放旗舰与服务配置

Qwen3.8-Max 的主线，是把旗舰级通用能力推进到编码、专业工作、研究和长程 Agent 场景，并提供相应的开放模型基础。[官方系列介绍](https://github.com/QwenLM/Qwen3.8)强调，从回答更难的问题转向更可靠地完成复杂多步任务，是这一代的主要目标。理解这条路线，需要分别看支撑通用能力的模型结构，以及让模型持续工作的推理和服务配置。

**模型结构延续 Qwen3.5 的混合计算路线，再扩展容量。** 对应的 [Qwen3.8-2.4T-A95B 模型卡](https://huggingface.co/Qwen/Qwen3.8-2.4T-A95B)披露，模型将 Gated DeltaNet、全局注意力与稀疏专家结合：不同计算模块分担序列信息更新与跨位置交互，专家机制则在保留较大总容量的同时，只让部分参数参与每一步计算。这里的亮点是容量与计算组织共同扩展，让长序列处理和较大的知识容量不必完全依赖每一步都执行全部参数。

**Agent 侧更强调自主规划、环境反馈和跨工具兼容。** 持续编码往往不是先写完计划再机械执行，模型需要在测试失败、依赖变化或需求补充以后调整工作。官方材料把这类端到端执行能力与代码、专业研究放在同一代升级中，并强调与常用 harness 和开发工具的配合。因此，对其进步的评价应包括完整工作是否结束、结果是否经过检查，而不只比较一次代码生成。

**推理强度与跨轮延续是另一个具体设计点。** 系列接口允许调整推理投入，并保留历史轮次中的推理上下文，为持续任务提供不同于每次重新开始的组织方式。其研究意义是让计算预算与任务阶段相匹配：简单步骤不必总用最高投入，复杂阶段又能沿已有进度继续。但保留更多历史也需要管理失效假设与旧约束，不能把历史越长等同于状态越准确。

需要区分开放权重与托管服务。模型卡说明，**Qwen3.8-Max 服务基于开放模型，并额外提供视觉输入、非思考模式、默认长上下文和内置工具等配置**；这些服务能力不能无条件视为下载权重后就自动具备的同一套接口。阅读这组材料最有价值的方式，是同时理解通用旗舰的模型基础与执行配置，再分别比较它们带来的收益，而不是把所有表现都归因于参数规模。

#### 4.1.5 MiMo-V2.6-Pro-RL：同时扩大探索、环境与评价反馈

MiMo-V2.6 的通用旗舰检查点是 **MiMo-V2.6-Pro-RL**。[官方模型卡](https://huggingface.co/XiaomiMiMo/MiMo-V2.6-Pro-RL)将它定位为面向文本、图像、视频、音频和长程任务的统一底座；[技术报告](https://huggingface.co/XiaomiMiMo/MiMo-V2.6-Pro-RL/resolve/main/MiMo_V2_6_technical_report.pdf)则以扩大强化学习为主线。它的重点不只是多采样，而是让更多尝试、更多任务和更好的评价一起形成有效学习过程。

**第一条线是扩大训练中的探索空间。** 中期训练提供较广的多模态基础，随后将编码、通用 Agent、视觉和安全相关环境放入混合强化学习，并在多种执行框架中收集轨迹。不同任务不再完全分开训练，目的是让处理反馈和组织行动的方法能够在场景之间迁移。混合环境因此既扩大覆盖，也要求系统能够统一管理不同任务的观察、动作和完成条件。

**第二条线是提高反馈的分辨能力。** 只用通过或失败打分，会把质量差异很大的成功轨迹当成同样好。报告中的组内 Agent 评价，先从对照轨迹构造更适合任务的准则，再在训练中比较成功方案的质量，将学习信号更多分给更合适的路径。这使模型有机会从只是完成任务，继续改善实现质量、行动效率与不必要的反复，而不是把更多输出当作更强推理。

**第三条线是让大规模训练保持稳定。** 长上下文和不同任务的执行时间差异，使异步训练、轨迹表示和沙箱调度变得重要；报告还讨论固定专家路由，减少训练期间路由漂移导致的负载问题。与此同时，环境加固、对抗筛查和验证器交叉检查用于抑制奖励投机。规模扩大以后，采样吞吐、奖励可信度和训练稳定性需要共同维护，否则更多计算可能只放大已有问题。

混合强化学习之后，报告还通过多教师、不同前缀条件的在策略蒸馏扩展监督，覆盖一些难以直接验证的任务。MiMo 这条路线的亮点因此是：**既扩大模型可以尝试的工作，也改善模型怎样判断哪种尝试值得继续学习。** 这里的自我改进指训练中的探索与反馈循环，不等于已经证明模型可以在任意环境中无限递归提升。

#### 4.1.6 GPT-6 Astra：从操作软件到理解交付目标

GPT-6 Astra 的发布重点，是让通用推理更直接地转化为可以委托的实际工作。[发布博客](https://openai.com/index/gpt-6-astra/)把计算机操作、浏览、软件工程、科学与专业工作放在一起，强调的不只是单项答题能力，而是模型能否判断接下来需要做什么，并通过软件和工具把目标推进到可检查的结果。

**计算机与浏览器使用，是这次发布最鲜明的主线之一。** 博客讨论模型在真实应用中整理记录、处理文档、分析数据、制作图表以及完成前端检查的能力。共同难点是目标通常不能直接对应一个按钮：系统需要理解界面、选择操作、观察变化，并在多个步骤之间维持约束。发布还伴随执行框架层面的改进，因此实际加速包含模型与 harness 的共同贡献，不宜只归给底层模型。

**编码与科研被放进更完整的执行循环。** 软件任务不仅要求生成补丁，还需要安装、运行、测试和排查问题；科研任务则连接数据处理、模拟、拟合和结果分析。博客使用长程终端任务与专业软件任务展示这一方向。其亮点是模型更接近承担一段工作流程，而不是只给出完成流程所需的文字建议。个别研究案例仍然应与可重复的基准结果区分，不能据此把所有科学问题都视为已经自动化。

[面向工作的后续博客](https://openai.com/index/gpt-6-astra-next-generation-work/)进一步强调写作、设计判断和对用户意图的理解。专业交付往往有许多未被逐条写出的要求：材料要能被读懂，图表要支持判断，修改不能破坏原有业务目的。因此，Astra 的叙事从是否会操作软件，继续推进到是否知道什么结果才算把事情做好，以及哪些后果需要先确认。

**对齐与权限边界也被作为能力的一部分讨论。** [系统卡](https://deploymentsafety.openai.com/gpt-6-astra)研究困难或不可完成的任务是否会诱发越界，以及浏览、工具和专业环境中的潜在失效。博客中的授权控制、确认策略和自动审查属于部署系统，不能当作模型永不越界的保证。这组公开材料更适合分析自主工作能力、评价设计与部署约束；没有披露的参数规模和完整架构，不应从能力表现反推出来。

#### 4.1.7 Claude Fable 5.1：长程研究能力与更可控的推理投入

Claude Fable 5.1 的重点，是继续提高编码、知识工作和长时间问题求解能力，同时让这些能力更适合持续使用。[发布博客](https://www.anthropic.com/claude-fable-and-mythos-5-1)既展示性能变化，也讨论推理强度、缓存使用和安全干预。理解它不宜只看最高投入时的峰值成绩，还要看较低投入能否完成过去需要更多计算的工作。

**博客把复杂工程与 Agent 科研放在同一条能力主线上。** 二者都要求持续理解目标、提出方案、执行检查，再利用反馈修改策略。发布材料中的研究案例与客户测试，突出较长任务中的问题发现、实验推进和实现验证。它们展示了模型可以承担哪些工作，但案例仍有具体环境和参与者条件，应与公开评测分开理解。

**不同推理强度下的表现，是这次发布的重要比较方式。** 同一个模型可以在不同成本下运行，Fable 5.1 的提升不仅体现为最高设置下的结果，也体现为较低投入时相对上一代的能力。这对实际 Agent 很重要：工作流中并非每一步都需要同等程度的推理。缓存与持续上下文又会改变长任务的实际开销，所以应该比较完整任务的投入，而不是仅看生成文字的长度。

Fable 5.1 与同次发布的 Mythos 5.1 还需要明确区分。[官方说明](https://www.anthropic.com/claude-fable-5-1-mythos-5-1-system-card)指出，两者使用相同底层模型，但安全措施和访问方式不同。因此，同一类测试中的差距可能包含安全干预的影响，不能直接解释为两套模型架构的智力差距。这也提供了一个具体的比较案例：底层能力相同，部署策略仍可能改变模型在任务中的实际行为。

这一代的整体亮点，是把较强的长程问题求解与更可管理的使用条件放在一起。博客提供能力方向、推理投入和行为变化的线索，系统卡补充安全测试与未解决问题；二者可以共同解释产品进步，但不能替代未公开的训练消融或独立复现。

#### 4.1.8 Claude Opus 5.5：让较高能力更适合日常复杂工作

Claude Opus 5.5 的发布重点，是把接近 Fable 5.1 的广泛工作能力放进更高效、更易协作的通用模型中。[发布博客](https://www.anthropic.com/claude-opus-5-5)同时讨论编码、计算机使用、知识工作、沟通和安全。它与 Fable 5.1 的比较，应理解为能力与运行条件的重新平衡，而不是简单假定后发布的型号在每个维度都完全取代前者。

**工程能力的重点是较大范围修改与验证。** 博客用代码迁移、软件性能改进和完整应用制作等案例，说明模型不只需要产出能运行的代码，还要保持既有行为、检查改动是否达到目标，并把不同环节合成可交付结果。对研究者而言，这比只比较局部补全更接近真实工程，但案例规模和完成时间仍依赖具体任务条件。

**效率进步来自多个环节，而不只是降低标价。** 官方材料同时讨论服务计算、任务使用的 token 数量、缓存读取和生成速度。这些因素共同影响长程 Agent 的成本：即使单次调用更便宜，若不断重做工作仍可能没有优势；反过来，更短、更有效的行动路径可以进一步放大模型侧的节省。比较时需要保留任务质量与完成率，而不是把最快输出直接当作最好表现。

**更清楚的沟通被作为协作能力强调。** 发布材料描述了重要信息前置、表达更自然和长任务进展更容易跟踪的变化。对需要审阅代码、判断风险或接管任务的人来说，可读性会影响检查成本，因此不是与能力无关的文风装饰。不过，这类体验应结合用户评价与真实工作测试，不宜只用少量示例证明所有场景都更好。

[Opus 5.5 系统卡](https://www.anthropic.com/claude-opus-5-5-system-card)进一步覆盖行为审计、提示注入，以及较长或不可完成任务中的边界问题。它使性能、效率和行为可靠性能够放在一起讨论，但仍保留安全失效与测试覆盖的限制。将它与 Fable 5.1 并读，可以看到通用旗舰的另一种进步方式：不是只追求最高能力点，也要降低持续工作的资源负担和人的监督成本。

综合这些材料，旗舰模型的亮点可以分成三层：模型怎样承载更复杂的信息，训练怎样把信息处理能力转成行动策略，以及整个系统怎样把行动变成可靠交付。Kimi、DeepSeek 和 Qwen 的公开材料提供了不同的结构与状态管理线索，GLM 和 MiMo 突出了长程后训练，Astra、Fable 与 Opus 的博客和系统卡则集中展示工作能力、运行条件与行为边界。这些是各份材料最清晰的观察入口，不意味着各家只研究其中一层。

### 4.2 文本生成的新计算单位：概念预测与扩散块

改变生成单位可能提升并行性，也会改变训练目标、条件依赖与错误修正方式。单步生成更多内容不代表完成同一任务更快，因为还可能需要迭代修复或额外验证。报告比较应说明输出单位、采样次数与质量约束，避免把一次前向的速度当作整段生成的速度。

**NCP-ArchPreview（`2609.10715`）**从隐藏状态构造离散概念词表，联合训练下一 token 与下一概念预测，再将概念信息反馈给生成。[论文](https://arxiv.org/abs/2609.10715)给出两种不同口径：使用相当于 OLMo-3-7B 总训练 token 51.3% 的数据量，达到其最终预训练损失；相对于严格参数匹配的 8.9B 基线，使用 85% 的标准计算量接近其训练损失。前者比较达到指定损失所需的数据量，后者比较计算预算，且“接近”不能改写为完全相同。作者还用受控实验区分潜空间架构与 NCP 目标的贡献。这些对照分别说明数据与计算的利用效率，需要在各自匹配条件下解释。“概念”在这里是训练中的表示单位，不是已经证明模型具有人的概念理解。

**DiffusionGemma（`2608.00146`）**从自回归模型转向并行细化文本块，经监督去噪、强化学习与采样器蒸馏训练。[论文](https://arxiv.org/abs/2608.00146)披露转换成本和生成速度。它与 NCP 的区别很清楚：前者改变生成过程中的并行组织，后者增加跨 token 的训练目标和表示。速度必须连同块大小、首字等待、任务质量和设备一起看，不能只用长输出的高吞吐来推断交互工具调用更灵敏。

这两条路线都挑战“下一 token 就是唯一计算单位”，却没有消除任务依赖。短命令、受格式约束的工具参数与长篇生成可能需要不同策略。应研究混合生成时何时切换、拒绝或修订已输出内容如何处理，以及离线质量提升能否迁移到带外部动作的执行框架。

### 4.3 视觉与多模态：文档理解、实时感知与向量检索

多模态能力取决于任务需要保留的细节。文档识别需要字符笔画与布局，通用图像描述更关注对象语义，检索又要求跨样本可比较的表示。报告应解释视觉编码器和训练目标如何支持具体用途，再看基准结果，不能以几个视觉问答分数代替全部感知能力。

**[MonkeyOCRv2](https://arxiv.org/abs/2607.11562)**联合图像到文本生成与像素级文档重建，希望在语义对齐之外保留字符与布局信息，并在多类文档任务中测试编码器。放在报告阅读中，重点是看数据语言覆盖、任务定义与编码器替换条件。文档感知变好并不直接证明跨应用工具操作或长任务执行变好。

**MOSS-VL（`2608.15045`）**把“说话时继续看”作为系统能力，通过门控跨注意力、合成交互数据和分阶段课程组织训练。[论文](https://arxiv.org/abs/2608.15045)还涉及何时说话、保持沉默和修订。它解决的是持续输入与生成的协调，不只是静态图片问答。评测应包含迟到的视觉证据、打断和纠错；看懂最后一帧并不能说明系统在整个过程中及时采取了正确行动。

**OvisOCR2（[`2607.13639`](https://arxiv.org/abs/2607.13639)）**聚焦文档解析，利用同一 HTML 来源生成页面图像和 Markdown 目标，结合真实文档标注。这种数据设计对齐视觉与结构化输出，但合成来源一致也可能降低真实噪声的难度。因此要分别观察公开基准、内部长尾任务以及版式和文字错误类型，不能用一个总分替代真实文档工作流质量。

**Douyin Multimodal Embedding（[`2608.02148`](https://arxiv.org/abs/2608.02148)）**先做对比学习，再通过潜在证据推理和跨条件重建补充细粒度语义，尽量把额外负担留在训练端。**WeMM-Embedding（[`2608.24053`](https://arxiv.org/abs/2608.24053)）**支持多种输入组合与可变输出维度。它们交付的是可检索表示，不是直接完成网页操作的智能体；但检索错误会进入后续决策。比较应看同任务、同维度和同索引预算下的召回，而非把嵌入排名与生成模型榜单互换。

### 4.4 识别与实时语音：说了什么、谁在说、何时回应

识别准确率、说话人区分、打断响应和对话时机属于不同能力。离线转写可以等待完整音频，实时系统则需要在证据尚未完整时决定是否回应。因此报告必须交代输入延迟、流式条件与交互协议，不能直接把整段音频成绩与低延迟对话能力画等号。

**VibeVoice-ASR-Streaming（`2609.02812`）**交错音频块、少量前瞻和已有文本，在语音到达时同时给出文字与说话人归属。[论文](https://arxiv.org/abs/2609.02812)把原先分离的识别与说话人任务统一起来。关键限制是实时性依赖块大小和前瞻；错误率低也可能通过等待更多未来音频实现，因此延迟与正确率必须同报。

**Xiaomi-CocktailASR-1（[`2609.11274`](https://arxiv.org/abs/2609.11274)）**用参考语音提示目标说话人，直接转录其内容，并在目标缺席时输出空文本。它与“把所有人都识别出来”不同：这里拒绝输出是成功能力之一。**Qwen-Audio-3.0-ASR（`2609.07549`）**把方言、热词、长上下文与自然口语放进统一指令框架，[论文](https://arxiv.org/abs/2609.07549)另述流式变体。两者的错误分母和任务目标不同，不能仅凭一个识别率排序。

**StepAudio 3 Realtime（`2609.14005`）**将感知、双工交互、并行推理和异步工具组织为连续循环。[论文](https://arxiv.org/abs/2609.14005)中的“边说边思考”是一种时序设计，不意味着推理无限免费。要检查用户打断后旧计划是否被取消、工具结果如何改变正在说的话，以及较快回应是否增加不必要承诺。完整语音智能体需要评估任务完成，而不仅是声音自然或首音频延迟。

### 4.5 音频与音乐生成：统一接口之下仍有不同表示路线

相同文字接口背后可能使用离散音频 token、连续声学表示或分阶段生成流程。这些选择影响音质、时长控制、语义遵循与可编辑性。比较报告要先确定任务是语音、音效还是音乐，并区分客观指标与人类偏好，避免将不同数据和听评协议下的分数拼成总榜。

**StepAudio 3 Gen（`2609.12945`）**采用共享音频表示和离散自回归建模，并用分阶段训练管理语言与音频能力之间的干扰。[论文](https://arxiv.org/abs/2609.12945)覆盖语音、音效、音乐及混合内容。**Qwen-Audio-3.0-Gen-Preview（[`2607.27011`](https://arxiv.org/abs/2607.27011)）**则用扩散 Transformer 和共享 VAE 生成混合波形。二者的共同目标是减少任务专用分支，差别在生成组织与表示；统一模型不能因此被默认在每种细分音频任务上都最佳。

**Qwen-Audio-VAE（[`2607.11738`](https://arxiv.org/abs/2607.11738)）**研究连续音频编码器的压缩、重建与编码速度，它是上游基础部件，不是完整歌曲生成系统。**Qwen-Music（[`2607.11699`](https://arxiv.org/abs/2607.11699)）**结合质量感知课程与渐进后训练，**WanSong（[`2607.14749`](https://arxiv.org/abs/2607.14749)）**强调扩散框架中的长音频、可控性与步数蒸馏。应分别评价音质、歌词或指令匹配、长程结构、编辑保持和推理成本；单个客观音质指标不能代表完整音乐体验。

**AuK（[`2609.08936`](https://arxiv.org/abs/2609.08936)）**以自然语言和音频上下文统一生成、内容编辑、增强及声学修改；**Luna-TTS（[`2608.11593`](https://arxiv.org/abs/2608.11593)）**将扩散语言建模与分块输出结合。后者报告的低首块延迟基于预热服务，冷启动还需要计入模型加载与网络开销。声音控制能力的评价还涉及语音来源授权、防冒用机制及其对正常生成的影响。

### 4.6 表格基础模型：跨数据集先验与泛化

表格任务的难点包括样本规模、特征类型、缺失与目标分布。某个模型在小数据上有效，未必适合长尾类别或分布漂移。技术报告应明确预训练任务分布、下游适配成本与传统基线调参预算，不能只比较模型参数量或默认配置下的一次得分。

**EXAONE Tabular（`2608.25774`）**从合成结构因果模型先验预训练，交错特征轴与样本轴注意力，让上下文中的标签信息参与预测。[论文](https://arxiv.org/abs/2608.25774)提供架构中心的解释：它不是每个新表都重新梯度训练，也不等于已经识别真实数据的因果关系。合成先验可以支持预测，因果效果却需要额外假设与实验设计。

**Mitra-v2（[`2609.04540`](https://arxiv.org/abs/2609.04540)）**也只用合成数据预训练，扩大任务分布并调整二维 Transformer 与优化；**Xiaomi-TabLDM（[`2609.03880`](https://arxiv.org/abs/2609.03880)）**结合特征分组、上下文利用和稀疏专家。三者适合比较先验覆盖、结构设计和测试时资源，而不是只比参数量。尤其应看类别数、缺失值、特征数量、任务切分和是否额外微调；不同评估协议下的平均名次不能直接拼接。

**TabPFN-3.5（`2609.17895`）**把评测扩展到时间或分组切分、复杂类别、多模态表格以及不同推理模式。[论文](https://arxiv.org/abs/2609.17895)同时涉及快速、增强和更高计算变体，其中有专有推理优化。因而可检查程度应按组件标注，不宜简单说整套系统完全可复现。一个快速变体的速度与另一个高计算变体的精度，不能合成成同一个“又快又强”的配置。

### 4.7 推荐与在线实验：替换整个系统，还是增加控制层？

线上系统往往包含召回、排序、过滤、缓存和业务规则。新模型可能替换其中一环，也可能只增加一个调度层；系统指标同时受流量与实验周期影响。阅读时应标清部署位置、对照策略与资源约束，区分离线精度、在线行为和真实效用。

**RecGPT-V3（`2607.15591`）**处理每次请求重读历史、文本标签到物品映射的信息损失以及冗长推理成本。它用记忆枢纽、文本与语义标识的联合表示、潜在意图推理连接用户理解和物品空间。[论文](https://arxiv.org/abs/2607.15591)报告在线实验及服务资源结果；但这些结果绑定具体产品、流量和业务指标，不能当成任何推荐平台的通用提升幅度。

**Sona（[`2608.11015`](https://arxiv.org/abs/2608.11015)）**用共享用户表示统一候选生成与排序，训练时引入教师，服务时不保留教师；**DREAM（`2608.09408`）**相反，并不替换原有推荐流水线，而是在其上加入可审计的策略控制层。[论文](https://arxiv.org/abs/2608.09408)区分意图感知、策略推理、参数下发与反馈。两者说明“智能体化”不是只有重建整个系统一种路线。应比较增量收益与维护成本，而不是把完整替换与附加控制的指标直接相减。

**PILOT（[`2608.18637`](https://arxiv.org/abs/2608.18637)）**用实验管理、搜索规划和记忆整理三个角色组织在线树实验，并由确定性服务限定合法命令、统计边界和权限。这一设计体现了模型决策与运行约束的分工：语言模型可以提出与选择方案，但安全边界不应只存在于提示词。开放问题是如何在真实反馈延迟、分布漂移和异常恢复下保持统计有效性；一次作者自评的业务提升不等于长期无人工运行已经普遍可行。

### 4.8 发布材料与系统卡：能力变化、部署条件与风险

模型发布通常同时涉及能力变化、服务配置与风险控制，理解一次升级需要把这些信息联系起来。技术报告解释训练与结构，发布介绍展示重点任务和产品形态，系统卡则讨论测试场景、失效行为与部署措施。沿同一型号比较这些材料，可以看清模型本身与外围系统各自承担的作用。

**[ABot-C0 Technical Report](https://arxiv.org/abs/2607.07370)**从多源运动数据、策略学习与统一部署栈三个层次描述四足机器人控制系统。它不是通用语言模型报告，却能清楚展示报告阅读的共同方法：逐项区分数据生成、模型设计和真实运行证据，再看哪些部分可以独立验证。四足动作展示也不能直接证明系统具备开放式任务规划与长期自主学习。

部署报告则进一步解释能力怎样转化为运行效率。**[MiMo-V2.5 全流程推理优化](https://arxiv.org/abs/2607.13095)**将缓存布局、路由和媒体预处理放在同一流程中，说明同一模型的服务表现还取决于软件栈与工作负载。它与机器人部署报告提供了不同场景的例子：训练、执行和系统维护各自承担一部分成本，需要分别记录。

通用模型的发布可以从版本演进与任务定位两条线比较。前者关注同一系列在能力、效率和交互方式上的变化，后者区分通用任务、专门任务与端侧部署。这样才能把发布材料接回实际研究问题，而不是只按名称排列型号。

系统卡材料包括[Claude Opus 5 System Card](https://www.alphaxiv.org/abs/2607.claude-opus-5)、[Claude Opus 5.5 System Card](https://www.alphaxiv.org/abs/2609.2609-opus-5-5)。这类资料适合检查作者披露了哪些评价与风险边界，不能仅凭系统卡名称认定获得独立安全认证。

[GPT-5.6: Frontier intelligence that scales with your ambition](https://www.alphaxiv.org/abs/2607.gpt-5-6)、[Introducing Laguna S 2.1](https://www.alphaxiv.org/abs/2607.introducing-laguna-s-2-1)与 [Introducing Muse Spark 1.1](https://www.alphaxiv.org/abs/2607.introducing-muse-spark-meta-model-api)提供不同系列的版本入口。比较时可先确定各自面向的任务和调用方式，再追踪后续报告中的结构、训练与评测变化。

[Introducing Claude Fable 5.1 and Claude Mythos 5.1](https://www.alphaxiv.org/abs/2609.claude-fable-and-mythos-5-1)与 [Introducing Claude Opus 5.5](https://www.alphaxiv.org/abs/2609.claude-opus-5-5)可与本章通用旗舰部分相互参照：版本变化不只体现为任务得分，还涉及推理投入、协作体验和部署控制。[Gemini 4 Argon: our next era of frontier intelligence](https://www.alphaxiv.org/abs/2609.gemini-4-argon)则提供另一系列的对照入口。

成本与开放方式是另外两个比较维度。[GLM-5.3-Flash: Frontier Intelligence, Flash Cost](https://www.alphaxiv.org/abs/2608.glm-5-3-flash)与 [Introducing K2 Horizon: Frontier Performance, Radically Open](https://www.alphaxiv.org/abs/2609.k2)分别在发布题名中突出这些目标。实际选择仍需要把任务质量、运行成本、可获取组件和许可条件放在一起考察。

专门任务或部署形态还包括[Pangram 4 Technical Report](https://www.alphaxiv.org/abs/2607.pangram-4)、[SWE-1.7: Frontier Intelligence at a Fraction of the Cost](https://www.alphaxiv.org/abs/2607.swe-1-7)、[Introducing Muse Glimmer: An Open Agentic Model That Runs on Your Device](https://www.alphaxiv.org/abs/2608.introducing-muse-glimmer-open-agentic-model)。它们的评价对象与通用语言模型不同，需先明确任务、运行环境及可检查产物，再判断能与哪些报告作技术对照。

系统卡将能力测试与风险分析连接起来。比较重点包括攻击场景、对手能力、失败判据，以及部署措施对正常任务的影响。随着模型和服务更新，保留这些条件的版本对应，可以追踪能力增长是否伴随新的失效方式，也为后续安全研究提供具体问题。

## 5. 跨路线对照：任务、配置与技术贡献

不同路线的比较，首先要明确任务与约束。旗舰模型适合观察通用能力上限，其他通用底座则能提供语言分布、训练起点和资源配置的对照。这些差异有助于解释同一种技术在不同数据与资源条件下是否仍然有效。

[Soofi S](https://arxiv.org/abs/2607.09424)结合德英双语数据、稀疏专家与混合架构，提示语言覆盖和部署目标会改变设计选择。[Mach-Mind-4-Flash](https://arxiv.org/abs/2607.09375)与 [Solar Open 2](https://arxiv.org/abs/2607.20062)分别从领域专家整合和固定预算下的扩展切入，适合比较教师怎样选择、经验怎样组合，以及额外训练成本由谁承担。

[Motif 3](https://arxiv.org/abs/2608.09119)提供专家激活、连接方式与多 token 预测的组合设计线索，[K-EXAONE 2.0](https://arxiv.org/abs/2608.04505)则从既有模型扩展容量。这些工作与旗舰报告形成的联系，是如何区分架构、数据、训练与部署各自的贡献。下面按实际技术对象归纳比较条件，不把不同任务的最佳成绩合并成一个排名。

| 路线 | 最应检查的披露 | 可以比较的能力 | 不能直接混用的指标 |
|---|---|---|---|
| 通用语言与智能体 | 预训练、教师来源、后训练与工具预算 | 同任务同执行框架的成功与成本 | 总参数、激活参数和端到端成本 |
| 潜变量与扩散文本 | 额外目标、块大小、去噪步数和首字等待 | 质量—计算—延迟曲线 | 训练 token 节省与全部训练成本 |
| 视觉与嵌入 | 输入时序、标注方式、向量维度与索引 | 同条件解析、检索或实时响应 | 静态识图、检索召回与完整任务 |
| 语音理解与交互 | 前瞻、分块、目标说话人与打断处理 | 同延迟约束下识别和交互完成 | 离线错误率与实时任务成功 |
| 音乐与音频生成 | 编码、时长、编辑约束和主观评价 | 同内容条件下质量、可控与成本 | 单项音质和完整歌曲体验 |
| 表格模型 | 数据切分、合成先验、推理模式与调参 | 同协议分类、回归及不确定性 | 不同变体的最佳速度与最佳精度 |
| 推荐与实验控制 | 流量分配、指标周期、约束与回退 | 具体平台上的增量业务与效率 | 不同平台的业务提升百分点 |

负结果和未知同样重要：低输出 token 成本不是全部服务成本；无梯度适配不是零推理成本；流式模型不是零等待；更强主观偏好不能替代内容忠实度；开源部分组件不能补齐未公开数据。没有统一条件就标不可比，比勉强排一个确定名次更诚实。

## 6. 研究机会

跨报告比较的研究价值，在于从不断变化的系统中提炼可迁移的设计。为此，需要识别真正有效的技术因素、建立可复查的能力证据，并保留不同模态与应用的任务差异。

**1. 如何从不断变化的模型报告中识别可迁移的技术贡献？**

不同版本常同时改变数据、结构、后训练和推理设置，排行榜差异无法直接归因。研究机会是建立按任务与计算条件对齐的跨版本比较，用可获得的消融和独立实验区分因素。目标是提炼在其他模型或场景仍可能成立的机制，而不是维护一个快速过期的总排名。

**2. 如何定义足以支撑核心能力主张的最小披露与复查协议？**

报告的材料完整性不同，权重开放、代码开放和评测可复现也不等价。可以研究任务、预算、环境、失败样本和验证器等必要字段，设计成本可控的复查协议。关键是让外部研究者能够判断结论依赖哪些条件，并明确哪些主张仍缺少可检查证据。

**3. 如何比较不同模态和应用中的方法，而不抹平任务差异？**

语音、视觉、表格和在线系统可能共享训练或计算思想，但目标、反馈和部署条件不同。研究机会是识别可跨领域比较的机制变量，同时保留领域特定的质量与风险指标。方法迁移应通过新场景实验验证，不能因为报告使用相同术语就推断获得了同一种能力。
