# 相邻研究方向与待复核文献

[返回首页](../README.md) · [邻近方向目录](../catalog/90_adjacent.md) · [待复核目录](../catalog/99_review.md)

## 主线与相邻领域

Agent 研究与数学、物理、计算机视觉和传统软件系统存在广泛联系。理解这些联系，需要区分研究对象与所用工具：一项工作可以为 Agent 提供表示、算法或环境，但其主要贡献仍属于相邻领域。本页说明这些方向如何与专题衔接。

相邻研究方向与待复核文献分别设置入口。前者说明研究对象处于主线之外，后者说明现有证据不足以可靠确定归属。主题边界不表示质量评价，待复核也不是独立研究领域。

## 1. 纯数学与物理：研究对象不能与研究工具混淆

一篇证明数学命题的文章，和一篇研究 AI 如何搜索、生成并检验数学证明的文章，主问题不同。前者推进数学知识，后者还讨论计算系统的能力与验证机制。只有在材料确实说明 AI 参与发现、搜索或验证时，才有理由把它纳入[科研与数学 Agent](../chapters/12_science.md)。

文献的主归属依据研究对象与贡献，而不是标识格式。非 arXiv 页面同样可以包含学术研究，数学题名中的结果主张也不能视为已经获得验证。分类依据与记录字段见[分类方法](classification_audit.md)。

同理，一篇面向人类读者的数学学习指南，也不会因为出现在 AI 社区的榜单里就变成数学智能体研究。初学者没有必要先读完这些论文，才能进入 Agent 主线。

## 2. 计算机视觉：重建、生成、理解与行动要分开

图像重建通常问“怎样从观测恢复场景”；生成问“怎样合成符合条件的内容”；视觉理解问“图里有什么、发生什么”；GUI 或机器人 Agent 进一步问“为完成目标应该采取什么动作”。这些问题可能共享网络和数据，但不能用同一类成功指标评价。

例如，*Exploration Matters for Escaping the Blur Trap in 3D Gaussian Splatting*（`2607.17965`）讨论场景重建中的优化问题，其核心是怎样获得更好的场景表示。它可以与感知模块的研究联系起来，而与自主提出问题、执行实验的科研 Agent 有不同的研究目标。

对于图像与视频生成，本指南保留[第 16 章](../chapters/16_generation.md)，因为生成模型确实可以成为工具或环境组件；但只有加入目标、反馈与行动过程，才能讨论它在 Agent 系统里的角色。世界模型另见[第 10 章](../chapters/10_world_models.md)，不能仅因输出视频就直接归入。

## 3. 翻译、时间序列和传统系统：应用名称不决定机制

一个翻译基准主要评估译文质量，一个时间序列模型主要预测未来观测，一个数据库系统主要管理查询与存储。它们可能被 Agent 调用，也可能完全不需要 Agent。归类应看论文主要改变了什么、如何评价，而不是看到“reasoning”“routing”或“tool”等词就强行合并。

例如，如果时间序列研究真正让模型选择不同工具、根据反馈迭代分析，可以作为工具使用的交叉材料；如果只是训练一个更准确的预测器，就应承认它属于邻近路线。归属尚不明确的工作进入待复核目录，待主要贡献与实验设置明确后再分类。

## 4. 如何把“待复核”变成可操作的清单

待复核条目明确标记需要补充证据的位置，并保留分类不确定性。建议按下面的顺序处理：

1. **核对身份。** 题名、链接和标识是否相符？非 arXiv 页面应查原作者页面，而不是猜一个 arXiv ID。
2. **找主要贡献。** 作者交付的是模型、数据、评测、系统、理论分析还是某领域发现？
3. **问主要问题。** 方法中使用蒸馏，不代表主问题就是蒸馏；在科学任务上测团队合作，也不一定应主归科研。
4. **选择归属并保留理由。** 给一个主类，必要时加关联标签；证据不足就继续待复核。
5. **回写维护文件再重建。** 不手工修改生成表格，保留来源分类与证据记录。

本附录明确主线与相邻领域的边界，并为证据补充、分类纠正和交叉阅读提供入口。
