# 跨专题研究进展

[返回首页](../README.md) · [全局总览](overview.md) · [研究机会](learning_path.md)

一些研究同时改变信息组织、训练反馈与执行方式，难以只从单个专题理解。本页围绕四条联系展开：如何从资料中构造证据，如何让交互经验支持学习，如何验证科研产出，以及如何将预测与试验连接到机器人执行。相关工作与各章的方法脉络相互补充。

## 1. 从“找得到资料”到“组织出证据”

检索到相关资料以后，系统仍可能需要加工材料才能支持决策。[RECAST](https://arxiv.org/abs/2610.10507)研究这一环节：有些证据并不原样存在于某段文档，而需要对多份材料筛选、聚合或计算。作者让路由模型选择检索与计算操作，并在需要时由另一个模型把操作转成代码。因此，它可以作为研究“如何构造下一步可用上下文”的新入口，而不只是又一个更换检索器的方案。阅读时应检查路由、代码执行与最终回答的成本分别如何统计。

[RunningTab](https://arxiv.org/abs/2610.10444)关注另一个常见失败：Agent 能搜索工作目录，却忘记用户要求交付什么，或者误把列出的文件当成已经读过。它在环境侧保留任务记录，把要求、实际读取的摘录与来源、列出但尚未打开的候选联系起来。它与模型内部“记住更多”的路线不同，重点是让环境保留可检查的工作状态。下一步值得观察，这种状态记录能否减少遗漏，又是否引入新的维护负担。

这两篇一起说明，上下文问题至少有三层：信息在哪里，怎样把它加工成证据，以及系统如何知道哪些工作仍未完成。可先读[基础章的观察与证据选择](../chapters/01_basics.md)，再进入[记忆章](../chapters/02_memory.md)。

## 2. 训练数据要与实际执行框架对得上

[CoTrace](https://arxiv.org/abs/2610.10426)不把框架搜索中收集的全部轨迹当作同质数据，而是关注轨迹产生时的框架与后来采用的运行方式是否一致。其摘要描述分别推进框架搜索与策略训练，并处理数据来源匹配、轨迹分配和训练课程更新。这给[强化学习与蒸馏](../chapters/05_rl_and_distillation.md)补充了一个具体问题：同一段“成功经历”，换了工具或上下文规则之后，还适不适合拿来监督模型？

[Before They Can Solve](https://arxiv.org/abs/2610.10478)把问题移到训练之前：能否从基础模型的表现预测经过后训练的编码 Agent 能力？它适合连接[模型科学](../chapters/14_model_science.md)与[评测](../chapters/06_evaluation.md)。但预测研究首先需要检查训练配方、模型范围与留出设置；一个关联指标不能直接被当作跨模型、跨训练预算的普遍能力定律。

## 3. 研究智能体不仅需要答案，还需要可检验的产出

[SciExam for ENSO](https://arxiv.org/abs/2610.10513)要求 Agent 根据真实观测建立简化气候模型，而不是回答一组已经知道答案的科学题。其流程区分代理自己构建的诊断与隐藏评价，并检查重建、未观测变量和留出年份预测等方面。这与[科研章](../chapters/12_science.md)的核心问题一致：科学模型是否有效，不能只靠一段评语判定。论文摘要中的相对成绩也应放回具体任务与评价条件，而不是被解释为 AI 已全面胜过气候研究者。

[Kernel Autoresearch](https://arxiv.org/abs/2610.10394)研究模型设计中的核函数。这里的 *kernel* 不是 GPU 计算内核，而是机器学习模型中的核函数；如果只按英文关键词归类，很容易把它误放到推理加速。作者希望结合程序化候选生成与有效性约束，并保留行为不同的候选。它提供了“开放生成怎样与严格约束共存”的案例：随机输入上的数值检查，可能不足以保证在不同尺度或维度仍然有效。

[A Society of Researchers](https://arxiv.org/abs/2610.10468)则把多个自主研究者之间的组织方式作为问题。读这种工作时，除了看单个代理的推理能力，还应看共享知识、验证、资源分配与独立检查是怎样安排的。它适合接在[协作章](../chapters/08_collaboration.md)之后阅读，而不是仅按“多几个角色”的方式理解研究团队。

## 4. 从机器人模型到可靠的机器人使用

[RoboJEPA](https://arxiv.org/abs/2610.10515)把潜空间世界模型的规模、数据和计算关系作为研究对象，并考察模型预测误差与机器人规划表现的关系。它连接[世界模型](../chapters/10_world_models.md)、[具身智能](../chapters/11_embodied.md)和[模型科学](../chapters/14_model_science.md)。需要继续检查的是：所拟合的关系在什么范围内成立，换任务或设备后还能否用预测误差代理真实控制表现。

[EmbodiedRSI](https://arxiv.org/abs/2610.10498)把有限的真实交互当作需要主动分配的实验资源：系统保留不同代码或技能假设，选择能够区分它们的物理实验，再利用结果更新。这比“失败之后再试一次”提出了更具体的问题——下一次机器人试验，究竟能帮助排除什么原因？它与软件 Agent 的自动修改相关，但物理试验的成本和风险不能省略。

[Agentic RSR](https://arxiv.org/abs/2610.10479)连接真实场景、模拟场景和回到真实环境的执行，提醒读者场景重建不只要看起来像，还要保留任务相关的交互关系。[RobotWorld](https://arxiv.org/abs/2610.10409)则提供多种机器人任务的模拟测试环境，检查通用多模态 Agent 能否通过机器人接口完成目标。其中一个值得关注的问题是：代理可以组织相当复杂的感知与控制流程，但局部能力未必稳定组合成成功行为。这个问题正呼应全局总览中的“单步会做，不等于长任务可靠”。

## 5. 研究机会：连接局部改进与完整系统

**如何让环境侧的状态与证据组织真正改善长期执行？** 可以结合任务记录、轨迹分析与恢复机制，研究哪些信息必须由环境持久保存，哪些适合交给模型学习。重点是比较新任务中的遗漏、恢复与资源成本，而不是仅检查记录格式是否更完整。

**如何把自动生成的候选连接到独立且可扩展的验证？** 科研、工具设计和机器人交互都可能产生大量候选，验证则具有不同成本和适用边界。研究机会是联合设计候选生成、预算分配和外部确认，避免搜索持续利用近似反馈的盲点。

**如何判断跨模块改进能否迁移到完整系统？** 某项局部方法可能改善表示、训练信号或协作，却未必提高最终任务表现。需要保持可比较的模型、环境与预算，将单模块收益、模块间误差传播和端到端结果分别检验，才能判断哪些变化值得进入更长期的系统设计。
