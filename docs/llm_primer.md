# 大模型前置知识：读 Agent 综述之前，需要理解什么？

[返回首页](../README.md) · [Agent 全局总览](overview.md) · [术语表](glossary.md)

本页介绍阅读 LLM 与 Agent 研究所需的基本概念，从文本表示、模型计算和训练过程，逐步连接到上下文管理、工具使用与系统评价。各节用自然语言解释机制，并提供相应的经典论文入口。

建议先理解四条关系：**文本如何变成模型输入；训练如何改变参数；推理如何产生输出；系统如何把输出变成行动。** 各节先说明过程怎样发生，再解释它为什么影响 Agent 的设计与评价。

## 1. 语言模型究竟预测什么？

文本输入模型前，通常先经过分词器，转换成一串 **token**。Token 是模型处理的离散单元，可能对应一个词、词的一部分、标点或更细的片段；它不固定等于一个汉字或一个英文单词。不同分词器对同一段文本的切分也可能不同。子词切分的历史入口可读 [Neural Machine Translation of Rare Words with Subword Units](https://arxiv.org/abs/1508.07909)，但不要把某一篇论文的具体实现当作所有 LLM 分词器的统一实现。

对自回归文本模型，生成是逐步发生的：模型先根据已有文本判断下一个 token 的各种可能性，再由生成规则选出一个，将其加入上下文，继续判断后面的 token。前面生成的内容会影响后续选择，所以整段回答不是一次性从数据库里取出的结果。[Language Models are Few-Shot Learners](https://arxiv.org/abs/2005.14165)是理解大规模自回归语言模型与上下文学习的重要原始资料。

“预测下一个 token”描述的是训练与生成接口，不意味着模型只能做浅层续写。为了在大量不同文本上做好预测，模型可能学到语法、知识、程序模式和推理中有用的表示。但反过来，生成出一段合理文字，也不意味着其中每个事实已经被外部验证。**生成机制与结果真实性，是两个需要分别检查的问题。**

对 Agent 而言，这解释了一个常见误区：模型写出“测试通过”，只是生成了这些 token；只有执行系统真的运行测试并取得结果，才有外部证据。

## 2. Token 怎样变成模型可以计算的对象？

离散 token 通常先映射为向量，这一步称为 **embedding，嵌入表示**。向量可以理解为一组用于计算的数，不是人手规定的一串属性标签。模型在多层计算中不断更新这些表示，得到依赖当前上下文的隐藏状态；同一个词在不同句子中的表示可以不同。

Transformer 中的注意力机制，让一个位置根据相关性组合其他位置的信息。可以把它理解为三个相连的步骤：当前表示提出需要寻找什么信息，其他位置提供用于匹配的特征，模型再根据匹配程度分配权重，汇集相应内容。查询、键和值分别对应查找需求、匹配依据与被汇集的信息，它们都是模型从输入表示中计算得到的，不是人工逐项填写的标签。

不同注意力头可以形成不同的信息组合方式，再由模型继续加工。权重表达的是内部计算中的相对分配，不能直接当作事实可靠性或人类意义上的重要程度。原始机制与多头设计见 [Attention Is All You Need](https://arxiv.org/abs/1706.03762)。

注意力不是完整模型。Transformer 还包含前馈计算、残差连接、归一化和位置信息等部分。常见的自回归文本生成模型使用因果限制，让当前位置不能查看尚未生成的后文；原始 Transformer 论文中的完整编码器—解码器结构，也不应直接等同于所有后来的 LLM。后续架构还有循环计算、状态空间、混合专家等路线，在[效率与架构章](../chapters/13_efficiency.md)分别讨论。

为什么 Agent 读者需要知道这些？因为“记忆”“状态”“上下文”可能出现在不同层：一份外部笔记是系统存储，当前 token 序列是模型输入，隐藏状态是模型内部计算结果，参数则是在训练中形成的长期数值结构。它们不能只因为都保留信息，就被视为同一种机制。

## 3. 训练与推理，究竟有什么不同？

**训练**通常包括预测、计算误差、追踪参数对误差的影响，以及更新参数。模型先对训练样本做出预测，损失函数衡量预测与目标之间的差距，优化器再据此调整参数。以自回归预训练为例，训练文本提供每个位置实际出现的 token；模型如果给这个目标分配的概率过低，就会受到更大的惩罚。训练尝试让它在相似上下文中更倾向于预测正确内容。

损失降低，表示模型在这个训练目标上变得更符合数据；它不直接等价于“所有知识更正确”或“所有 Agent 任务成功率更高”。从训练目标到实际任务能力，还隔着数据、模型、后训练、工具和评价条件。

**推理**则是在给定参数和输入下运行模型，获得输出。常规部署中，增加对话历史、检索文档或工具结果，通常改变的是本次计算的输入，而不是自动更新模型权重。研究中也存在测试时训练、在线适应等不同设置；遇到它们时，应明确看参数或其他可学习状态有没有更新，不能套用普通聊天调用的假设。

**微调**是在已有模型基础上继续训练；它仍然涉及学习信号和参数更新，不是把提示词写得更详细。[LoRA](https://arxiv.org/abs/2106.09685)是一种减少需要训练的参数量的方法，但少训练一些参数不等于不训练，也不意味着所有计算成本都按同样比例减少。

由此可直接区分三种常见改进：给模型更多证据是输入层改进；改变工具与控制循环是系统层改进；用数据更新参数是训练层改进。一篇论文可能同时做三种事，阅读时应分别记录。

## 4. 预训练、SFT、偏好优化与强化学习如何连接？

**预训练**让模型从大规模数据中学习通用表示与预测规律。数据量、模型规模、训练计算之间存在重要的资源取舍；[Scaling Laws for Neural Language Models](https://arxiv.org/abs/2001.08361)与 [Training Compute-Optimal Large Language Models](https://arxiv.org/abs/2203.15556)提供两条历史入口。这里的经验关系依赖实验范围，不能把某一条拟合关系当作适用于所有架构和任务的自然定律。

预训练模型有语言建模能力，也未必会按用户期待的方式回应。因此，后续常见 **SFT，监督微调**：给模型输入与目标回答，训练它模仿期望行为。数据可以是问答，也可以包含工具调用、程序或完整行动轨迹。SFT 的核心问题是示范是否正确、覆盖了什么，以及模型在自己执行时会遇到哪些示范里没有的状态。

**偏好学习或偏好优化**进一步利用“哪个回答更符合要求”之类的信息。一个常见历史路线先训练奖励模型，再用强化学习调整生成策略；[Training Language Models to Follow Instructions with Human Feedback](https://arxiv.org/abs/2203.02155)给出了这一方向的重要实例。[Direct Preference Optimization](https://arxiv.org/abs/2305.18290)提供不同的优化形式。它们都不应被概括成“人类喜欢的答案就一定真实”：偏好反映的是给定数据与评价要求。

**强化学习，RL**把行为、环境和结果反馈连接起来。对 Agent，动作可能是工具调用，状态信息来自当前观察，奖励可能来自任务检查器。策略决定如何行动，训练尝试提高预期奖励。问题在于，任务可能在很多步以后才给出成功信号，中途又可能遇到工具故障或错误反馈；因此，长期行为应该由哪些决策负责，并不容易判断。

**蒸馏**则利用教师模型或更强系统产生学习信号，让学生学习其中的输出、判断或行为。教师不一定只是更大的同类模型，也可能具有额外信息或更复杂的执行框架。若教师与学生看见的信息、能用的工具不一致，直接模仿可能失效。这也是为什么[第 05 章](../chapters/05_rl_and_distillation.md)会分别讨论强化学习、同策略蒸馏和框架蒸馏，而不是把它们当作同一个训练技巧。

这些阶段是一套理解常见方法的分类，不是所有模型都必须按固定顺序经过的流水线。看到“post-training，后训练”时，要继续查具体目标和数据；这个词本身没有告诉你模型学了什么。

## 5. 上下文学习为什么不等于“模型永久记住了”？

在提示里给几个示例，模型可能就能按同样方式完成新任务。这常被称为 **in-context learning，上下文学习**。在通常设置中，示例作为当前输入影响输出，而不需要为这些示例再做梯度更新。将它与训练区分，是理解记忆与技能论文的重要前置。[Few-shot 语言模型研究](https://arxiv.org/abs/2005.14165)

**上下文窗口**是一次模型计算能够处理的输入序列范围。窗口更长，意味着可以放入更多信息；但能容纳不等于能可靠利用。[Lost in the Middle](https://arxiv.org/abs/2307.03172)研究长上下文中信息位置与使用效果的关系，是理解“有效记忆不等于最大窗口”的基础阅读。

**RAG，检索增强生成**通常先从外部资料找出相关内容，再提供给生成模型。[原始 RAG 论文](https://arxiv.org/abs/2005.11401)将参数化生成模型与非参数检索结合。RAG 不自动意味着模型权重知道了新事实，也不自动解决多步任务的进度管理、过时信息删除和冲突处理。

Agent 的**长期记忆**可以由外部文件、数据库、摘要或其他状态组成。系统要决定什么时候写入、什么时候取回、如何标注来源、什么时候更新或删除。如果一条旧规则已经失效，却每次都被检索回来，存得更牢可能反而使任务做得更差。这些是[记忆与上下文章](../chapters/02_memory.md)讨论的机制问题，不是单纯扩大输入长度。

## 6. 生成概率、答案正确率与自信程度不要混淆

模型在每一步输出 token 的概率分布；解码方法决定怎样从中选择后续内容。可以选择概率较高的候选，也可以进行采样。温度、截断采样等设置会改变生成分布，进而影响多样性和稳定性。它们不是直接调节“真实性”的开关：更确定的文字也可能重复错误，更随机的输出也不自动带来更好的探索。

模型说“我很确定”，是一种输出行为，不必然是经过校准的概率估计。生成过程中某个 token 概率高，也不等价于整个答案事实正确。评价置信度需要明确事件：是在预测这道题是否答对，下一次工具调用是否有效，还是当前证据是否足够？不同事件需要不同验证方法。

对 Agent，是否继续尝试、是否调用更强工具、是否请人介入，都可能依赖不确定性判断。但这些决策还要结合代价：一次只读搜索与一次不可逆外发操作，不应该使用完全相同的风险门槛。评价和升级策略见[第 06 章](../chapters/06_evaluation.md)，权限与后果见[第 07 章](../chapters/07_safety.md)。

## 7. 为什么推理很贵，为什么 KV cache 不是长期记忆？

自回归生成中，后续 token 需要利用前面的信息。**KV cache**缓存注意力计算中的键和值，以减少重复计算；它是推理实现中的中间结果缓存，不等于用户偏好数据库或能跨项目整理经验的记忆系统。

从工作负载看，服务通常需要处理已有输入，再逐步生成新 token；两部分分别常称为预填充与解码。长输入、短输出，和短输入、长输出，会形成不同的计算与存储压力。多个请求一起运行时，还要考虑批处理、调度、缓存与设备利用率。相关技术背景见[Transformer](https://arxiv.org/abs/1706.03762)与[效率章](../chapters/13_efficiency.md)。

Agent 又多了一层系统成本：等待搜索、执行代码、运行测试、读取文件、请求其他模型，以及失败后重试。论文说“少用了 token”，未必意味着总时间更短；说“模型小”，也未必意味着整个任务更便宜。比较时应明确测的是模型计算、工具等待还是端到端任务开销。

**推理时计算扩展**指在部署时投入更多采样、搜索、验证或其他计算。它与增加模型参数、增加预训练数据不是同一件事。更大的计算预算可能帮助某类任务，但也需要有用的候选生成和选择信号；没有可靠反馈，反复尝试可能只是在重复同一种错误。

## 8. 模型怎样进入一个真实的 Agent 系统？

现在可以把整个过程接起来：模型接收目标、工具说明和当前观察；输出一个候选动作；执行系统检查动作与参数；工具实际运行并返回结果；系统记录状态，再决定是否继续调用模型。

```text
语言模型：根据可见信息产生下一步输出
    ↓
执行系统：解析输出、检查权限、执行工具、记录结果
    ↓
环境：文件、网页、代码仓库、模拟器或设备发生变化
    ↓
评价与反馈：检查任务状态，决定继续、停止或交还给人
```

模型不应该因为生成了一个工具名称，就自动获得使用任意系统资源的权限。参数校验、工具可用范围、执行隔离和重要操作确认，应由外围系统明确管理。也不能把网页或文件中出现的指令，自动视为用户对系统的新授权。

这层外围系统就是后文常说的 **harness，执行框架**。框架可以包含记忆、计划、路由、重试和结果检查；模型参数可以保持不变。于是，评测某个 Agent 时，光写模型名称不够，还需要交代它连接了哪些工具、如何管理状态、允许试多少次。

## 9. 看一个分数之前，先知道它怎样产生

研究中通常需要区分训练数据、用于调参或选方案的验证数据，以及最后用于检验泛化的测试数据。如果在同一组题上反复修改提示词、框架和奖励，再把最终成绩称作未见任务表现，就容易高估方法的适用范围。

评价指标也对应不同问题：调用格式是否正确，单个函数是否执行成功，完整任务是否完成，过程是否遵守约束，结果是否经外部验证。一个系统可以在前两项很好，在后面几项仍不可靠。不要用静态问答准确率自动代替长任务完成能力。

读到“提高若干点”时，还要查：比较的是相同模型吗？任务和版本一致吗？工具权限、重试次数和输入预算一致吗？报告的是单次运行还是多次运行？是否只展示成功样例？这些不是只有评测专家才需要关心的细节，而是理解论文结果的基础。

比较研究结果时，将任务设置、训练数据、计算预算与评价方法对应起来，才能判断改进来自何处、适合哪些条件。引用与比较的组织方式见[文献收录与分类](methodology.md)。

## 10. 怎么判断自己已经具备后续阅读的基础？

不以能否背出全部缩写为标准。试着回答下面六个问题：

1. 给模型增加一页检索资料，和用这页资料微调模型，改变了什么不同对象？
2. 为什么模型写出一段正确格式的工具调用，还不能说明任务完成？
3. 为什么更长上下文、更多记忆和更大的 KV cache 不是同一项能力？
4. SFT 学习示范，RL 利用奖励，两者在训练信号上有什么区别？
5. 同一个基础模型放进两个不同执行框架，为什么不能只用模型名解释分数？
6. 为什么提高一个基准上的表现，仍需要检查代价、约束与未见任务？

能够用自己的话回答这些问题，就可以进入[Agent 总览](overview.md)和[基础、规划与工具章](../chapters/01_basics.md)。后续遇到数学细节，再按专题需要补；没有必要先学完一整门深度学习课程，才开始理解研究问题。

若希望补更深的模型背景，可按“Transformer → 自回归语言模型 → 指令后训练 → 参数高效微调”的顺序读本页原始文献；若主要关心应用，先走“模型与系统区别 → 上下文与记忆 → 评测 → 安全”。两条路线共享概念，不要求相同的实现深度。
