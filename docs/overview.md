[返回首页](../README.md) · [论文阅读第一站：综述导读](../chapters/00_surveys.md) · [下一步：基础与工具](../chapters/01_basics.md)

## 1. 从回答问题到完成任务

生成答案与完成任务需要不同的系统能力。以软件修改为例，给出代码只是其中一步；完整流程还包括理解仓库、定位问题、实施修改、运行测试与判断结果。要把这类工作交给模型，系统必须让它获取实际状态、采取行动，并利用反馈继续推进。

Agent 系统尝试把其中一部分循环交给机器：读取项目，选择工具，执行修改，观察测试结果，再决定下一步。关键变化不是回答更长，而是**模型的输出能够改变外部状态，之后又根据反馈继续行动**。ReAct 将推理与行动交替组织，Toolformer 研究模型如何学习使用工具；它们提供了理解这条路线的两个基础入口。[ReAct](https://arxiv.org/abs/2210.03629) · [Toolformer](https://arxiv.org/abs/2302.04761)

因此，可以将 LLM Agent 理解为一类闭环系统：**LLM Agent 是以语言模型参与决策、通过工具或环境采取行动、根据反馈推进目标的系统。** 这一视角将决策、执行和反馈放在一起，也便于区分不同程度的自主性。并非所有系统都需要自主规划；步骤已知、后果严重的任务，固定工作流通常更容易检查。Anthropic 的工程文章也明确区分预先安排路径的 workflow 与由模型动态决定过程的 agent。[Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)

## 2. 先分清四个层次

**模型**负责根据输入预测、推理或选择动作。**运行系统**负责工具定义、执行循环、存储、超时和权限；论文常称它为 *harness*，这里称“执行框架”。**环境**是被操作的对象，例如代码仓库、浏览器或机器人场景。**评测**规定任务、成功标准和计算预算。

这个区分非常重要。换了记忆摘要方法，可能改善的是执行框架；增加训练轨迹，可能改变模型参数；使用更宽松的测试集，可能只改变测量结果。如果论文只给一个总分，却没有交代这些层次，你还不能知道增益来自哪里。[AgentBench](https://arxiv.org/abs/2308.03688) 和 [SWE-bench](https://arxiv.org/abs/2310.06770) 分别提供跨环境任务与真实软件问题的评测入口，它们的分数也不能简单互换。

读任何新论文时，先写下四句话：它改了哪一层？输入输出是什么？在哪个环境里测试？成功如何判定？如果这四句写不出来，先别急着记住方法缩写。

## 3. 为什么研究不再只是“把提示词写好”？

短任务里，模型常能把所有信息一次放进上下文；长任务则会累积工具输出、过时计划和中间错误。工作持续得越久，系统就越需要决定什么值得保留、什么时候重试、如何恢复，以及何时停止。上下文工程因此不仅是措辞优化，还包含选择、压缩和组织模型下一步需要的信息。[Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)

长流程给错误提供了更多出现和传播的机会。即使每一步通常能够完成，某次遗漏也可能改变后续条件，最终使整项任务失败；反过来，及时检查和恢复又可能阻止局部错误扩大。因此，单步准确率不能替代完整任务可靠性，评价还需要观察错误怎样传播、能否被发现，以及系统是否能够继续完成目标。

由此可以把记忆、技能、工具与评测放到同一个问题下理解：**系统怎样把连续决策组织成可靠的任务过程，并在出错后恢复？** 记忆保存任务状态，技能复用行动经验，工具连接外部操作，评测检验这些能力能否共同发挥作用。各方向的文献入口见[分类目录](../catalog/README.md)。

## 4. 用三条主线理解发展脉络

### 主线一：从生成文字到使用工具，再到持续行动

ReAct 把“想下一步”和“执行下一步”串起来；Toolformer 探索工具调用如何成为学习目标。随后，Reflexion 把执行后的语言反馈用于后续尝试，Voyager 在 Minecraft 中积累可调用技能。它们分别说明：行动可以被组织、失败可以留下经验、成功程序可以复用；但并不意味着系统获得了无条件自我改进能力。[ReAct](https://arxiv.org/abs/2210.03629) · [Toolformer](https://arxiv.org/abs/2302.04761) · [Reflexion](https://arxiv.org/abs/2303.11366) · [Voyager](https://arxiv.org/abs/2305.16291)

这条线引出[基础与工具](../chapters/01_basics.md)、[记忆](../chapters/02_memory.md)和[技能与自改进](../chapters/03_skills_and_self_improvement.md)。新手应先理解这三者：工具提供动作，记忆提供信息，技能提供可复用的过程，它们不是同义词。

### 主线二：从任务演示到明确的评测，再到针对反馈的训练

一个成功视频很难告诉我们系统失败多少次、是否泄露了答案、用了多少次重试。AgentBench、WebArena、SWE-bench 把任务放进更具体的交互环境；τ-bench 则把用户交互、工具和规则约束一起纳入评估。环境越真实，越需要区分“最终输出看似正确”和“操作过程满足要求”。[AgentBench](https://arxiv.org/abs/2308.03688) · [WebArena](https://arxiv.org/abs/2307.13854) · [SWE-bench](https://arxiv.org/abs/2310.06770) · [τ-bench](https://arxiv.org/abs/2406.12045)

有了可重复执行的任务，才能收集轨迹、定位错误，并进一步训练策略。这里引出[训练数据与环境](../chapters/04_training_data.md)、[强化学习与蒸馏](../chapters/05_rl_and_distillation.md)、[评测与验证](../chapters/06_evaluation.md)。评测沿两条轴线扩展：更长的任务依赖与更广的应用场景，用分能力表现解释系统的适用范围。评价器质量与奖励可信度则是支撑这些比较的方法问题。

### 主线三：从一个智能体到更复杂的行动空间

一个模型可能同时承担计划、执行和审查；也可以把工作分给多个角色。但拆分会增加沟通、状态同步和整合成本。AutoGen 是理解对话式多智能体组织的一手入口；不能仅凭角色数量推断效果更好。[AutoGen](https://arxiv.org/abs/2308.08155)

行动空间也从文本 API 扩展到屏幕和物理世界。此时，看懂图片、点击正确位置、控制机器人动作、预测环境变化是不同问题。[GUI](../chapters/09_multimodal_gui.md)、[世界模型](../chapters/10_world_models.md)、[具身智能](../chapters/11_embodied.md)分别讨论这些问题；[多模态生成](../chapters/16_generation.md)则研究内容合成及其作为工具或环境组件的作用。

## 5. 怎样理解 2026-10-08 这一版中的“当前状态”

以下是编者对本地趋势样本与补充基础文献的综合解读。每一项都对应可深入阅读的专题，不是行业普查或能力保证。

| 值得关注的变化 | 真正要问的问题 | 别轻易推出的结论 |
|---|---|---|
| 上下文管理被拆成检索、摘要、写入和删除 | 哪种信息在什么时刻真的有帮助？ | 窗口更长就没有记忆问题 |
| 成功轨迹被整理成技能或改写执行框架 | 改进是否迁移到没见过的任务？ | 自动改提示词就是递归智能爆炸 |
| 训练越来越依赖交互数据和可执行环境 | 奖励是否可信，环境是否覆盖真实失败？ | 有一个奖励分数就能训练好 |
| 长任务评价更关注过程与恢复 | 测试是否检查中间状态、代价和越权？ | 最终答案正确就代表过程安全 |
| 多智能体、GUI 和机器人扩大任务范围 | 收益是否足以抵消通信、感知和控制成本？ | Agent 越多、模态越多就一定越强 |

模型和系统的比较需要同时考虑任务、预算和运行条件。同一方法可能在某类工作中提高质量，却在另一类工作中增加开销；技术路线的价值因此要结合具体目标判断。[前沿技术报告](../chapters/15_frontier_reports.md)进一步比较结构、训练、推理配置与工作能力。

## 6. 研究与落地共用的五个检查问题

1. **有必要用 Agent 吗？** 固定脚本、检索系统或单次模型调用能解决时，它们是应该保留的基线。
2. **成功由谁判断？** 最好能检查真实状态；必须使用模型评价时，应抽样人工复核，并报告分歧。
3. **比较是否公平？** 模型、工具权限、输入长度、重试次数和总预算都可能影响结果。
4. **失败会留下什么后果？** 修改文件、外发信息或控制设备之前，先确定权限、可回滚性和人工确认点。
5. **结论能否迁移？** 在同一批任务反复改系统，很可能只是适应了测试集。保留未接触过的任务尤其重要。

涉及高影响操作时，还需结合具体场景设置权限、验证和人工接管机制。[安全专题](../chapters/07_safety.md)

## 7. 读完总览，怎样选择下一步？

[跨专题研究进展](after_snapshot.md)进一步连接证据管理、训练一致性、科研验证与具身执行，讨论局部方法怎样进入完整系统，以及哪些收益需要在跨模块实验中检验。

如果你只想先看懂领域：读 01、02、06、07，再任选一个应用。若你想做训练研究：先弄清评测，再读 04、05，不要跳过奖励和数据泄漏。若你研究底层模型：13 和 14 是支撑路线，但循环 Transformer、优化器和可解释性不是 Agent 的必修前置。

最后，请把“前沿”理解为**已经能说清问题，却仍没有被充分解决的地方**。论文名字新、点赞多、图好看，都不能代替一个清楚的研究问题、一组可靠的比较和明确的适用边界。
