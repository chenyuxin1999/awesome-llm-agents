# 质量标准与检查

[首页](../README.md) · [证据标准](methodology.md) · [覆盖报告](coverage.md)

## 内容标准

- 每章先交代研究方向的重要性、问题边界与主要挑战，再引入概念和方法。
- 每个研究分支说明问题来源、基础思路及关键取舍，不以论文列表替代解释。
- 经典与前沿分开，节与分支先总述后展开；检查相邻段落是否重复概括或省略推理连接。
- 正文以自然语言解释机制，不展示数学公式；保留适用条件、研究取舍和原始引用。
- 方法比较保留任务、模型、预算、接口和评价条件，区分作者报告与独立判断。
- 综述、研究路线图、方法论文与项目公告分别注明定位。
- 公共文档不包含对特定委托者的称呼、写作过程对话或重复的分类迁移日志。
- 研究结论对应明确来源与实验设置，解释方法收益及其适用范围。

## 自动检查

在项目根目录执行：

```bash
python3 scripts/build_catalog.py --source data/papers.jsonl --check
python3 scripts/audit_coverage.py --check
python3 scripts/validate_guide.py
```

| 检查 | 范围 |
| --- | --- |
| 目录一致性 | 记录数量、唯一主归属、原始元数据、分类配置与生成文件 |
| 正文覆盖 | 各章可见汉字、正文引用、跨章去重与报告一致性 |
| 链接与结构 | 相对链接、锚点、必要章节、经典与前沿的总述、公式标记、来源记录与公共文档规范 |
| 来源匹配 | 已取得的官方题名与主库标识及已记录版本对应关系 |

生成结果见[结构检查报告](../data/validation_report.json)和[覆盖数据](../data/coverage_report.json)。内容审阅重点检查问题铺垫、方法联系、论证完整性与引用准确性。

## 版本与来源

引用使用稳定原始入口；涉及题名或摘要变化时保留版本对应。已记录的差异见[版本说明](version_notes.md)。外部页面访问失败只表示该次检查未成功，不据此判断文献不存在。

## 发布前检查

1. 将项目复制到独立临时目录，从自带数据重建并运行检查。
2. 抽查首页到专题、专题到文献目录以及相关方向的导航。
3. 核对新增引用的类型、身份与版本，并检查导读是否超出已阅读证据。
4. 确认阅读页面没有私人路径、认证信息、写作对话或内部迁移备注。

来源更新与本地结构检查分开执行，分别检查外部内容变化和仓库内部一致性。
