19｜多模态 agent

模型能不能看到自己行动的结果
首页 · 专题索引 · 文献目录 · Markdown 版
任务与指令观察与画面模型与 agent动作工具、环境与验证存档与结果风险与断点

方向背景：从看懂一张发票，到把报销真正办完

设想月底你要报销一趟出差。邮箱里躺着三张电子发票，一张是 PDF，一张是手机拍的纸质小票，还有一张藏在订票网站的订单页面里；学校的报销系统是一个十几年前的网页，没有任何程序接口，只能一格一格地点、一格一格地填。你要做的事情其实很清楚：读出每张票上的金额和日期，打开系统，找到对应的输入框，把数字填进去，上传附件，最后确认页面上显示“提交成功”。

前一半事情，读懂票据上的金额和日期，是多模态理解那一章的故事：让模型把图片、截图和文档里的信息变成可以推理的东西。后一半事情才是本章要讲的。要把报销办完，模型得移动鼠标、敲击键盘，去操作那个从来没打算给程序调用的网页；更要紧的是，它每做一步，都得回头看一眼屏幕，确认刚才那一下真的生效了。人做事几乎都是这样的闭环：点一下按钮，看看页面有没有变；画一笔，看一眼再画下一笔。

这一章借用多模态范式图谱第九节的一个问题来串起整条线：模型能不能看到自己行动的结果。 做完一步就交差、不回头看结果的系统，叫开环；做完一步先看一眼结果、再决定下一步的系统，叫闭环。视觉 agent 这几年的发展，大体就是环路一段一段闭合的过程。2023 年，语言模型指挥一组视觉工具，却看不见工具画出来的东西；2025 年，模型能在思考途中反复拿起同一张图，裁剪、放大、再看；同一时期，屏幕成了第一个规模够大、又能让模型真正动手的视觉世界，每点一下，电脑都会回一张新截图；到 2026 年，模型能写 Blender 脚本、调用视频模型，再去看渲染出来的成品，不满意就改；最后，长程交互里那些早已滑出上下文的旧画面，也可以原样存档、随时调回来看。

难处在于，环路闭合只是让模型有机会看到结果，看没看对、信不信得过，是另一回事。模型认出了“税额”这两个字，未必知道该点的是它右边那个输入框；点对了位置，页面可能正在加载，点下去什么也没发生；填完了表，屏幕上那个“成功”提示也许只是旧页面的残影。屏幕只是软件状态的一个快照，它可能不完整，也可能已经过时，甚至可能被人动过手脚。所以本章在讲每一段环路怎样闭合的同时，也会一直追问三件事：模型看到的结果是不是真实的证据，它据此做出的下一步动作是否落在了正确的位置，而“任务完成”这个判断，最后又是由谁、依据什么做出的。

先读这几篇

这一章的主线由几篇出自一线团队和独立写作者的长文搭起来。它们回答的是同一个问题的不同侧面：让模型自己看屏幕、自己动手，能走多远，代价在哪里。前两篇是 Anthropic 和 OpenAI 发布电脑操作模型时写的技术说明，第三篇讲“看图思考”，第四篇是独立开发者的上手记录，第五、六篇分别反思基准分数、公开训练配方，最后两篇是 2026 年的综述。建议按顺序读，读完再回来看各阶段和前沿分支。

顺序文章为什么读
1Anthropic，Developing a computer use model（2024-10-22）本章主线的转折点。Anthropic 解释了为什么放弃为每个应用单独做工具的路线，转而让模型学会人类本来就在用的那个通用接口：看截图、动鼠标、敲键盘，去操作“几乎任何软件”。文章里有几处细节特别值得记住：模型要靠数像素来决定光标往哪里移，作者说把数像素训练准是让鼠标命令起作用的关键；训练只用了计算器、文本编辑器这样的简单软件，而且出于安全考虑不联网，泛化却比团队预想的快，模型遇到障碍时还会自己纠正。作者也很坦率：当时在 OSWorld 上是 14.9%，同类第二名是 7.7%，人类在七成上下；操作慢、容易出错，还不会拖拽和缩放，截图式的观察会漏掉一闪而过的通知。文中把提示注入列为头号担忧，这个判断至今仍是整个方向的安全底色。同一天的发布文 Introducing computer use, a new Claude 3.5 Sonnet, and Claude 3.5 Haiku 可以对照着读，它说明这项能力以公开测试版的形式经 API 开放，并补充了允许更多步数时 22.0% 的成绩。
2OpenAI，Computer-Using Agent（2025-01-23）和第一篇是同一条路线的另一种讲法。OpenAI 把 Operator 背后的模型写成一个“感知、推理、行动”的循环：截图让模型看见屏幕，模型结合当前和过去的观察一步步推理，再用虚拟鼠标键盘执行，直到任务完成或需要用户介入。它报告 OSWorld 38.1%、WebArena 58.1%、WebVoyager 87%，对应的人类成绩分别是 72.4% 和 78.2%。这篇最值得细读的是安全设计：有外部后果的最后一步要请用户确认，银行这类高风险任务直接拒绝，在邮箱等敏感网站上要求用户盯着，另有一个发现可疑内容就暂停执行的监控器。作者也承认它还很早期，可靠性随网站和任务措辞而变，不熟悉的界面和文本编辑仍然吃力。
3OpenAI，Thinking with images（2025-04-16）环路在一张静态图上闭合的标志。o3 和 o4-mini 被描述为第一批能在思维链里“用图思考”的 o 系列模型：它们会在推理途中裁剪、放大、旋转图片，把处理后的结果放回上下文接着想，OpenAI 说这为测试时计算开出了一条视觉与文字混合的新维度。文中只给了一个具体数字，V* 视觉搜索基准上 95.7%，并称这个基准基本被解决了。更有价值的是它列出的三条局限：推理链过长，工具调用和图像操作有冗余；感知错误即使工具用对了也会导致答错；同一道题多次尝试会走出不同的视觉推理路径，其中一些是错的。读完会明白，“能反复看”只是第一步，看得准、看得省还远没有解决。
4Simon Willison，Initial explorations of Anthropic's new Computer Use capability（2024-10-22）一位独立开发者在发布当天的上手记录，读来比官方文档更有现场感。他在 Docker 容器里跑起官方演示，让 Claude 打开自己的博客搜索鹈鹕、编译运行 C 程序、用 apt 装 ffmpeg，都一次成功；让它解数独，结果一塌糊涂。他点出了一个容易被忽略的事实：Anthropic 并不提供那台电脑，机器由开发者自己准备，模型只接收截图、返回动作；他认为这次最重要的新能力是模型终于能可靠地给出屏幕坐标。他最大的担心仍是提示注入，并引用了一个网页诱导模型下载并运行文件的演示。半年后他写的 Watching o3 guess a photo's location is surreal, dystopian and wildly entertaining 是理解“看图思考”的最好旁证：o3 为了认出一块车牌，前后裁剪了大约 25 次，他一面觉得这有点表演成分，一面判断把工具调用放进推理阶段是一种别家很快会跟进的强大模式，同时提醒任何一张随手分享的照片都可能暴露拍摄地点。
5XLANG Lab，Introducing OSWorld-Verified（2025-07-28）OSWorld 作者团队回头审视自己的基准，是理解“GUI agent 的分数到底意味着什么”的最佳读物。原版发布前做了四轮、超过 400 个人时的检查，发布后仍然收到了 300 多条反馈：网站改版、验证码、加载时序、指令有歧义、合理的替代解法被判错。一个十人左右的小组花了大约两个月主要修检查器。修完之后的格局很有参考价值：最好的 agent 框架 CoACT-1 达到 60.76%，约为人类水平的 84.4%；通用基础模型在 35% 到 44% 之间；专门的 GUI 模型在 25% 到 40% 之间。作者还判断，UI-TARS、OpenCUA 这类专门模型的成功主要来自大量人类操作电脑的轨迹数据。
6Hugging Face，Smol2Operator: Post-Training GUI Agents for Computer Use（2025-09-23）想动手的同学最该读的一篇。作者把 Aguvis 数据里五花八门的手机和桌面动作统一成一套函数式动作，把坐标归一化到 0 到 1 之间，然后分两阶段训练一个 2.2B 的 SmolVLM2：第一阶段学定位，第二阶段学带推理的操作。它在 ScreenSpot-v2 上从几乎为零起步，第一阶段后到 41.27%，第二阶段后到 61.71%；同一配方用在 460M 的 nanoVLM 上也有约 58%。整篇文章是一份完整、可复现的配方，读完你会相信 GUI 定位在很大程度上是一个数据问题。
7Neel Mokaria、Kevin Qinghong Lin、Mike Zheng Shou、Philip Torr、Dinesh Manocha 等，A Survey on Foundations and Frontiers of Multimodal Agentic Frameworks: Techniques and Applications（2026-06）读完前面几篇，再用这篇综述把视野拉到 2026 年。作者认为以往的 LLM agent 综述没有系统地回答多模态怎样改变 agent 这个问题，于是把 agent 拆成感知、推理、规划、记忆、行动五个模块，逐个讨论多模态带来的变化，并比较了三种架构：委托式让纯文本模型去调用外部的视觉或音频工具，把输入翻译成描述和转写再交给语言模型；晚融合用一个投影层把预训练编码器的特征接进语言模型的嵌入空间；早融合让一个统一的模型直接处理原始的多模态 token。作者的判断很明确：把各种模态转成语言会丢掉大量信息，融合了多模态信息的框架普遍表现更好；晚融合轻便、推理快，早融合更适合细粒度的理解和推理。应用部分覆盖机器人、GUI 与网页导航、多媒体内容生成与编辑、长视频理解与检索四个领域，恰好对应本章的屏幕、闭环创作、长程视觉记忆和走出屏幕几段；文中还强调，经过微调的领域专用架构在成本和延迟上比消耗大量 token 的闭源 API 更有优势。委托式正是本章“开环”一段的做法，读它可以看清这条主线在更大的版图里处在什么位置。
8Yanzhe Chen、Kevin Qinghong Lin、Mike Zheng Shou 等，Multimodal Embodied Agents: A Unified Capability-centric Perspective from Computer-Use to Robot-Use（2026-10）本章“两个出口”一段最新的一篇综述，把电脑操作和机器人放在同一把尺子下比较。作者把多模态具身 agent 定义为把多模态任务推理和物理动作结合起来、并根据反馈修正决策的目标驱动系统，提出一个按功能划分的能力框架 PAPAV：感知当前状态，预判动作的后果，规划可行的路线，通过界面或身体去行动，最后验证结果。框架按功能定义、不绑定具体架构，computer-use agent 和机器人因此可以放在同一张表上对比。作者还归纳了五类物理约束，从部分可观测一直到结果无法验证，它们让事先能定下来的选择更少，犯错之后能挽回的余地也更小。最值得记住的是他们对 64 个基准的统计：显式评测几乎都集中在行动上，只有 5 个评测预判、3 个评测验证，这两种能力基本藏在任务成功率背后。这和本章边界一段的教训是同一件事：环路闭合之后，验收那一环最容易被忽略，也最决定系统能走多远。

如果还想多读一点，Chip Huyen 的 Agents（2025-01-07）是理解本章所需 agent 概念的好起点：她把 agent 定义为感知环境并作用于环境的东西，它的行为由环境和可用的动作集合决定；工具分为扩充知识、扩展能力和会改变外部数据的“写”动作三类，文中还专门说工具能把纯文本模型变成多模态模型，这正是本章第一段“开环”所做的事；她对规划与执行分离、反思和三类失败模式的讨论，在 GUI agent 上几乎一一对应。Hugging Face 的 ScreenSuite（2025-06-06）把 13 个基准按感知、定位、单步动作、多步 agent 四类统一起来，并且坚持只用截图、不给无障碍树和 DOM，适合拿来理解“纯视觉设定”为什么会让分数和别处不同。Epoch AI 的 What does OSWorld tell us about AI's ability to use computers?（2025-10-30）从外部审计了 OSWorld 的任务构成，是第五篇最好的补充。最后，VISTA 的项目页讲的是本章主线的最后一段，长程视觉记忆。

一、先看全景，再分清几个容易混在一起的概念

本章所有的工作都可以放回同一条环上去看：观察屏幕，估计当前局面，发出动作，电脑执行，再验证结果。环上有三处最容易出问题：看到的东西能不能当证据，动作落没落在对的位置，“完成”由谁判定。另有三组常被混在一起的说法要分开：开环与闭环，看图思考与电脑操作，模型与包在它外面的程序和环境。

先看全景。开头那次报销，是读出三张发票上的金额和日期，在一个没有程序接口的老旧网页里一格格填好，最后确认页面显示提交成功。下图把它拆成了一圈。最左边的琥珀色框是观察：模型拿到的可能是一张截图，也可能连带网页的 DOM（网页的元素结构）或无障碍树（accessibility tree，操作系统为读屏软件提供的界面结构描述）。紫色框是状态估计，模型要在心里拼出一份当前的局面，除了屏幕上看得见的东西，还包括已经做过哪几步、还剩哪些目标、用户授权它做到哪里；后面讨论停止和权限时，靠的都是这一格。橙色框是动作，可以是一次坐标点击、一次对某个元素的操作，也可以是一条命令行。动作交给电脑执行之后，软件的状态真的变了，电脑随即返回一张新截图，底下那条虚线把它送回最左边，下一轮从这里开始。最右边的验证框单独画出来，是因为“做完了没有”这个判断最好去读真实的文件、数据库或应用状态，助手自己说一句“已完成”，是最不可靠的证据。

图上方的三个粉色框，对应方向背景里提出的三件事。第一个问题挂在观察上：屏幕只是软件状态的一个快照，它可能还没加载完，可能已经过时，也可能被人伪造，所以看到的东西能不能当证据，本身就是一个问题。第二个问题挂在动作上：认出了“税额”两个字，和点中它右边那个输入框，是两种不同的能力。第三个问题挂在验证上：页面上闪过的“成功”提示也许只是旧页面的残影，判定完成的那一方看的是什么、凭什么下结论，决定了整条环最后交出去的结果是否可信。本章后面的每一段主线、每一个分支，都是在这条环上补某一环。

第一组是开环和闭环。这里的环指的是“动作”和“看到动作的结果”之间那条回路。开环系统做完一步就把结果交出去，中间的产物它自己并不检查；闭环系统每做一步都会拿到一份新的观察，再据此决定下一步。区分的关键在于模型看到的是什么：如果它只看到工具返回的一句文字描述，比如“检测到三个人”，那么环路其实并没有闭合，因为它看不见那三个框画在了哪里。本章说的“看到结果”，指的是模型能直接读到行动之后的画面本身。

左边面板里琥珀色的虚线框表示，那张画了框的图其实存在，只是模型看不到，于是漏检了一个人、某个框画歪了，模型都无从得知；右边多出的那条从画面回到模型的箭头，就是本章说的“环路闭合”。

第二组是看图思考和电脑操作。两者都是让模型在推理途中发出动作、读回图像，区别在于动作作用在哪里。看图思考的动作作用在模型自己的输入上：裁剪、放大、画线，改变的是“怎么看”，世界本身没有变；电脑操作的动作作用在外部环境上：点击、键入、滚动，改变的是软件的状态，而且这种改变往往无法撤回。所以前者的风险主要是看错，后者还多了一层做错之后的副作用。多模态理解一章把裁剪放大这类主动观察视为“看”的延伸，本章则把它放在环路闭合的第二步，看作通向真正动手之前的一个台阶。

两边的差别在中间那个框作用在哪里：左边作用的是一份图片副本，最坏的情况是看错了，重新看一次就行；右边作用的是软件本身，表单提交了就是提交了，所以底部那个框换成了粉色。这也是第二节把看图思考放在屏幕之前的原因，它是环路闭合的一个更安全的台阶。

第三组是模型、harness 和环境。一个电脑操作 agent 的成绩，既取决于模型本身，也取决于包在模型外面的那一层程序：截图怎样压缩、历史保留几张、允许哪些动作、出错怎样重试。这一层叫 harness，在第 18 章 Harness 工程里是研究对象本身，在本章则是比较不同系统时必须先对齐的条件。环境也一样：同一个任务，允许用命令行和只允许点鼠标，难度可以差得很远。

图里最外面的绿色框是环境，它决定了只许点鼠标还是也开放命令行和文件系统、任务能不能一键复位、成败由什么程序来判。右下角的粉色框是本章反复要用的一条比较规则：两份成绩之间的差距，可能来自模型，也可能来自外面两层的设置，先把这两层对齐，比较才有意义。

最后看时间线。下图每一行是第二节主线的一个阶段，屏幕阶段因为工作最多，拆成“环境与基准”和“定位与产品”两行；点的位置按 arXiv 编号或发布日期取到月份。

把这张图和第二节开头的阶段表对照着看，会发现几条线并没有一条接一条地登场。屏幕上的环境和基准早在 2023 年就搭起来了，那时语言模型还在靠调度工具“看”图；看图思考到 2025 年才真正训练进模型，几乎和原生 GUI 模型同时成熟；闭环创作的早期例子 SceneCraft 和 BlenderAlchemy 出现在 2024 年，把强化学习用到这类创作循环上的 VideoGen-Agent 则要等到 2026 年。环路一段一段闭合，是一条逻辑上的顺序；在时间上，这几段往往是交错着推进的。

二、发展主线：环路一段一段闭合

这条主线的骨架来自图谱第九节“环路逐渐闭合”那张图，各阶段的细节则分别由上面几篇长文补上。几段之间的差别只在一处：模型能看到哪一层行动的结果。每往下走一段，模型能看到的结果就多一层，它要承担的责任也跟着多一层，前一阶段的评测于是多出一类覆盖不到的错误。

主线按“模型能看到哪一层结果”排成几段：先是看不见工具的产物，再是能在一张图上反复看，然后是每一步都有新截图的屏幕，接着是从截图直接出动作的原生模型，以及对分数、长度和安全的反思；最后是看成品再改的创作、能回查旧画面的长程记忆，和走出屏幕的两个出口。

开环：语言模型指挥视觉工具，却看不见工具的结果

2023 年的语言模型还看不见图，于是当起了调度员，把感知和生成交给现成的视觉模型，或者写一段调用视觉函数的程序。它们不训练任何东西就让语言模型处理了图片，代价是看不见工具真正产出了什么。

故事从 ChatGPT 还看不见图的时候讲起。2023 年 3 月，Visual ChatGPT 和 HuggingGPT 几乎同时想出了一个办法：既然训练一个多模态大模型又贵又慢，那就让语言模型当调度员。它把用户的请求拆成子任务，挑选现成的检测、分割、生图、修图模型去执行，再把各个工具返回的结果拼成最终答案。HuggingGPT 把这个分工说得最直白，语言模型负责规划、选模型、调用和汇总，具体的感知和生成交给 Hugging Face 上成千上万个专门模型。不训练任何东西，ChatGPT 就有了处理图片的能力，这是多模态工具调用的起点。

同一时期还有一条更讲究的路。CVPR 2023 最佳论文 VisProg 和稍晚的 ViperGPT 让语言模型根据问题写一段小程序，程序里调用“找物体”“裁剪”“计数”“比较大小”这些视觉函数，程序跑完，答案就出来了。这样做的好处是推理过程被写成了代码，每一步调用了什么、得到了什么都可以逐行检查，几个简单函数也能组合出复杂的推理。

图的上一行按 HuggingGPT 论文自己的划分画成四步：任务规划、模型选择、任务执行、回复生成；第三、第四步之间那行粉色小字标出，结果是以文字的形式回到语言模型那里的。两行的共同点是：写计划或写程序的那个语言模型，自始至终没有亲眼看过图。

Chip Huyen 在 *Agents* 里说，工具能把纯文本模型变成多模态模型，这一段正是她那句话最早的大规模实践。可这两种做法有一个共同的短板：语言模型看不到工具到底画出了什么、找到了什么。检测漏了一个物体，计数就错；分割框住了别的东西，后面的修图就修错了地方；而语言模型拿到的只是一段文字结果，只能照单全收。图谱把这叫作开环。要让环路闭合，模型自己必须能看图，而且要在推理的过程中反复地看。

看图思考：环路先在一张图上闭合

下一步是让模型自己看图，并且在思考途中回头再看。四个代表工作的差别，主要在“谁来决定再看一眼”：从语言模型引导的搜索，到一块给模型用的画板，再到直接训练进模型本身。

下一步是让模型自己看图，并且在思考的过程中回头再看。人遇到看不清的地方会凑近了看，模型也可以这样做。2023 年底的 V* 提出用语言模型引导视觉搜索，让多模态模型在高分辨率、杂乱的图像里主动去找小目标，并配了一个专门考这件事的 V*Bench。2024 年的 Visual Sketchpad 给模型一块可以画线、画框、做标记的画板，必要时还能调用专门的视觉模型，把“画草图”当作视觉版的思维链；作者报告它在数学题上平均提升 12.7%，在视觉任务上平均提升 8.6%，配上 GPT-4o 在 V*Bench 上达到 80.3%。

2025 年 4 月，OpenAI 在 *Thinking with images* 里宣布，o3 和 o4-mini 把这种能力训练进了模型本身：它们会在推理途中裁剪、放大、旋转图片，处理后的结果直接回到思维链里，V* 上达到 95.7%。开源一侧的 Pixel Reasoner 用指令微调加“好奇心驱动”的强化学习，教 7B 的视觉语言模型在像素空间里放大、选帧，作者报告 V* bench 达到 84%。Simon Willison 那篇看 o3 猜照片位置的文章，把这种能力在真实使用中的样子写得很生动：为了认出一块车牌，模型前后裁剪了二十多次，最后给出的第二个猜测正是拍摄的小镇。

从上往下读紫色那一列，能看到“再看一眼”这个决定一步步收进了模型内部：V* 由语言模型引导一个专门的搜索过程，Visual Sketchpad 让模型自己在画板上动手，o3 和 Pixel Reasoner 则把这件事训练进了模型的推理。灰色那一列的数字集中在 V* 这类找小目标的基准上，这些收益主要证明了“看得更细”，看得细能不能换来“做得对”，要到屏幕那一段才见分晓。

这一步的意义在于，视觉第一次成了推理过程中可以反复查看、主动处理的对象，找小目标、读小字这类问题因此大幅改善。可它的局限也很清楚。OpenAI 自己列出了推理链过长、感知错误、多次尝试路径不稳定三条；Willison 觉得二十多次裁剪有些表演的成分；本章三.1 还会看到一篇论文质疑，返回的像素究竟有没有带来新的证据。更根本的是，这里的动作只改变了“怎么看”，世界本身纹丝不动。要让动作改变环境，就得把模型放进一个会对动作作出反应的地方。

屏幕：第一个能大规模动手的视觉世界

网页和操作系统成了第一个规模够大、又能真正动手的视觉世界。几年里，舞台从网页扩大到整个操作系统和手机，判定成败越来越多地交给程序去查内部状态；与此同时，大家发现最难的一环是把“知道该做什么”落到“点在哪里”。

这样的地方很早就有人在搭了。2023 年的 Mind2Web 从 137 个真实网站、31 个领域里收集了 2000 多个开放式任务，第一次让大家看到通用网页 agent 要面对多么杂乱的真实网页。同年的 WebArena 更进一步，搭了一组可以自己部署、可以复位的网站，让 agent 在里面真的去下单、发帖、改设置，最后检查网站状态有没有按要求改变。评测的终点从“选出正确答案”变成了“实际建立、修改或查找一个外部对象”。

把看得懂截图的模型放进这样的环境，会怎样？2024 年初的 SeeAct 给出了一个清醒的回答，论文标题就是结论：GPT-4V 是一个通用的网页 agent，前提是它能定位准；它还发现 Set-of-Mark 那种先给区域编号、再让模型报号码的办法在网页上并不好使（实验细节见下文的 SeeAct 图）。同月的 WebVoyager 在 15 个热门真实网站上搭了任务，报告端到端的多模态 agent 成功率 59.1%，并用 GPT-4V 自动评判开放式结果，与人工判断的一致率为 85.3%。4 月的 OSWorld 把舞台从浏览器扩大到整个操作系统：在真实的 Ubuntu 虚拟机里，agent 要操作办公软件、图片编辑器、终端和浏览器，每个任务配一段可执行的检查脚本来判定成败。5 月的 AndroidWorld 又把这套做法搬到手机上，在 20 个真实应用里搭了 116 个带参数的程序化任务，每个任务都有初始化、成功检查和清理逻辑，最好的基线完成 30.6%。

这五个环境沿两个方向变化：上排的舞台从网页一步步扩大到整个操作系统和手机，下排的判定方式从和人工标注的操作序列比对，变成每个任务配一段可执行的检查脚本。越往右，“做没做成”越像一个能用程序回答的问题，这正是后面强化学习能够大规模展开的前提。

SeeAct 的实验设计很能说明问题。它先让 GPT-4V 用文字描述下一步要做什么，比如点击“搜索”按钮，这一步往往是对的；难的是第二段，把这句描述落到网页上一个具体的元素或坐标。作者比较了几种做法：Set-of-Mark 那种给区域编号、让模型报号码的办法在网页上并不好使；把 HTML 结构和视觉信息结合起来，是自动方案里最好的一种；如果由人来替它完成定位，GPT-4V 在真实网站上能完成 51.1% 的任务。最好的自动定位和人工定位之间仍有明显差距，所以论文的结论落在右边那个粉色框上：定位是最大的瓶颈。后面几年里专门做定位的工作，都是在填这道差距。

图谱对这一段有一个很到位的判断：屏幕是第一个规模大、又能真正动手的视觉世界。网页和软件本身就是程序，可以用脚本批量造出各种初始状态，做砸了一键恢复；任务做没做成，也能直接去查程序内部的状态，文件有没有保存、表单有没有提交，用不着人来打分。强化学习最需要的正是大量可以重置的环境和自动给出的奖励，GUI 恰好两样都有。

真正让这个方向出圈的，是 2024 年 10 月 Anthropic 发布的 computer use。在 *Developing a computer use model* 里，Anthropic 解释了他们的选择：与其为每个应用造一套工具，不如让模型学会人类本来就在用的那个通用接口。Simon Willison 当天的试用记录则点出了技术上的关键一环，模型终于能可靠地报出屏幕坐标了，这件事此前一直是瓶颈，学术界为此做过 SeeClick、UGround 这类专门把文字落到坐标上的工作，CogAgent 则用高低两路分辨率的编码器去看清界面上的小字。三个月后，OpenAI 的 Computer-Using Agent 把这个循环讲成了感知、推理、行动三步，在 OSWorld 上报告 38.1%，并在登录、验证码、付款这类步骤上停下来请用户确认。

原生 GUI 模型与在线强化学习

端到端的路线开始占上风：一个模型从截图直接出键鼠动作，靠大规模轨迹数据和多轮在线强化学习变强。问题的重心随之从“能不能看懂屏幕”移到“交互经验从哪里来、反馈信号可不可信”。

2025 年前后，端到端的路线开始占上风。2024 年底的 Aguvis 只用截图作为输入，把不同平台的动作统一到同一套动作空间里，并在动作前加入显式的推理；训练分两步，先学定位界面元素，再学规划和推理。2025 年 1 月字节跳动的 UI-TARS 把这条路线命名为“原生 agent”：一个模型从截图直接输出键鼠动作，不依赖外部的商业模型，也不依赖手工设计的工作流。它的配方有四样：大规模界面截图带来的感知能力，跨平台统一的动作建模，任务分解、反思和里程碑识别这类慢思考，以及在数百台虚拟机上收集、筛选、修正新的交互轨迹，让模型从自己的错误里学习。论文报告它在 OSWorld 上 50 步预算时得到 24.6，同条件下 Claude 是 22.0。

到了 2025 年 9 月的 UI-TARS-2，强化学习已经从配料变成了主菜。技术报告把难点归成四个：数据稀缺、多轮强化学习不稳定、只靠 GUI 做不了的事情、以及环境本身不可靠；对应的办法是数据飞轮、稳定化的多轮强化学习框架、带文件系统和终端的混合环境，以及大规模的沙箱平台。作者报告 OSWorld 47.5、AndroidWorld 73.3，在 15 个游戏上的平均归一化得分约为人类水平的六成。同年 8 月的 OpenCUA 则把整套基础设施开源出来：一个采集人类操作演示的标注工具，一个横跨 3 个操作系统、200 多个应用和网站的数据集 AgentNet，以及把演示变成带反思推理的状态动作对的流水线；作者报告 OpenCUA-72B 在 OSWorld-Verified 上平均成功率 45.0%，是当时开源模型中最好的。

对照两边会发现，左边 UI-TARS 的第四样配料，也就是在虚拟机上收集和修正自己的轨迹，到了右边的 UI-TARS-2 已经长成了整张图的主体：数据飞轮、稳定的多轮强化学习、混合环境和沙箱平台，四个对策都在回答同一个问题，怎样让模型持续、稳定地从自己的交互里学习。两个灰框里的分数从 24.6 到 47.5，记录了这段时间的进展；两次评测的步数预算和环境设定未必相同，直接相减时要留个心。

边界：分数可信吗，任务做得完吗，安全吗

环路闭合得越多，“怎么知道真的做成了”越难回答。分数会被检查器误判和接口差异扭曲，长流程任务远没有做完，屏幕上的文字还可能被当成指令。

环路闭合得越多，模型能做的事越大，“怎么知道真的做成了”就越难回答。OSWorld 的作者团队自己就踩过这个坑。OSWorld-Verified 那篇文章记录了他们的复盘：网站改版和反爬机制让任务悄悄变了样，应用没加载完动作就执行了，“把所有空白格填上”这样的指令可以有好几种理解，合理的替代解法被检查脚本判错。修改时他们尽量只动检查器、少动任务描述，好让新旧分数还能接得上。

Epoch AI 的 Florian Brand 和 Greg Burnham 从外部又审了一遍，结论更让人警醒。他们估计，约 15% 的任务只用终端就能完成，另有约 30% 的任务可以用终端和 Python 脚本代替大部分界面操作，加起来将近一半的任务几乎用不着 GUI；大多数任务十个原子动作以内就能做完；约 10% 的任务存在使其失效的严重错误。所以分数从不到 10% 涨到将近 70%，固然很大程度上反映了能力的真实进步，其中也混着终端技能、基准版本更替和指令理解的差异。Hugging Face 的 ScreenSuite 从另一个方向提醒了同一件事：同一个模型，只给截图、不给无障碍树和 DOM，分数就会和别处的榜单不一样，比较之前先得问清楚观察条件。

图的左半边把 XLANG Lab 文章里修完检查器之后的几组数字画在同一把尺子上：专门的 GUI 模型落在 25% 到 40%，通用基础模型在 35% 到 44%，最好的 agent 框架 CoACT-1 到了 60.76%，约为人类水平的 84.4%。右半边是 Epoch AI 估计的任务构成。两边放在一起读：一个 OSWorld 分数里同时装着界面操作、终端技能、基准版本和指令理解好几样东西，比较两个系统之前，先问清它们看到的是什么、被允许用哪些接口。

往更长的任务看，差距仍然很大。2026 年的 OSWorld 2.0 收集了 108 个长流程任务，人类完成每个任务的中位时间约 1.6 小时，agent 平均要调用 318 次工具，而初版 OSWorld 大约只要 30 次。在 500 步预算下，表现最好的配置也只完整完成了 20.6% 的任务，部分得分 54.8%。作者总结的失败模式很具体：忘了约束条件，漏看任务中途才出现的信息，该问用户时自己瞎猜，做完不检查。

安全这条边界从一开始就摆在桌面上。Anthropic 在发布 computer use 时就把提示注入列为头号担忧：模型会读联网电脑的截图，网页上的恶意文字可能让它偏离用户的本意。Simon Willison 发布当天就引用了一个网页诱导模型下载并运行文件的演示。OpenAI 的做法是让多层防护叠在一起，包括拒绝高风险任务、在外部动作前请用户确认、在敏感网站上要求用户盯着，以及一个发现可疑内容就暂停的监控器。本章三.4 讨论裁判和停止，三.5 讨论跨任务的攻击与统一接口的风险，都是在这条边界上工作。

三条边界落在环路的不同位置。“分数可信吗”挂在验收上；“安全吗”挂在模型决定动作这一步，截图里的一段恶意文字一旦被当成指令，后面执行得再准确，也只会把事情做坏；“任务做得完吗”不属于某一环，属于整条环要转的圈数，OSWorld 2.0 平均要调用三百多次工具，任何一环的小错都会被一圈圈放大。右下角的绿色框是 OpenAI 的回应，几层防护分别卡在任务开始之前、外部动作之前和执行过程之中。

闭环创作：调用工具，再看成品

环路接到了生成工具上：写脚本、调用生成模型，再看渲染出来的成品，不满意就改。和开环一段相比，差别就在“看成品”这一眼，整个循环的上限也卡在这一眼上。

在屏幕之外，环路在创作上也闭合了。图谱把这一段放在 2025 到 2026 年：模型先规划分镜或建模步骤，然后写 Blender 脚本、调用视频生成模型、或者写绘图代码；工具产出成品后，模型去看渲染出来的画面，判断好不好，不好就改脚本、换提示词再来一遍。2023 年那种开环做法里，语言模型只拿到工具交回的一句文字，看不见工具真正画出了什么；和它相比，关键差别就在于这里能看到工具产出的成品，出了问题自己会改。

这条线的早期例子来自三维。2024 年的 SceneCraft 让语言模型 agent 把文字描述变成可以在 Blender 里执行的 Python 脚本，处理多达约一百个三维资产的场景，并用视觉语言模型分析渲染出来的图像，迭代修改场景。同年的 BlenderAlchemy 把一个基于视觉的编辑生成器和一个状态评估器配成一对，去搜索满足用户目标的 Blender 操作序列，必要时还先用生图模型“想象”一张参考图，让抽象的文字描述有一个视觉上的落点。到了视频，单个生成模型一次只能稳定生成几秒到十几秒，多模态生成那一章讲过这是模型本身的限制；agent 把一部片子拆成许多镜头，每个镜头交给生成模型去做，自己负责规划、检查和拼接，整体长度和复杂度就不再受单个模型的限制。第 16 章在它的“Agent 编排与可编辑交付”分支里专门讨论这类生成工作流，本章只从“看成品”这一环来看它。

图补上了两个系统各自的一处细节。SceneCraft 没有直接从文字写代码，先把描述整理成一张场景图，记下各个资产之间的空间关系，再把这些关系翻译成数值约束写进脚本；作者还把常用的脚本函数编进一个可复用的库，让系统不调模型参数也能越做越好。BlenderAlchemy 那一行的琥珀色虚线框，是生图模型“想象”出来的参考图。两行的共同点写在底部：渲染出来的画面回到了模型眼前，这正是闭环创作和开环做法的分界。

图谱对这一段的评价很中肯：整个循环的上限卡在“看成品判断好坏”这一步，模型看不出画面哪里有问题，就不会去改。这和 OSWorld-Verified 的教训是同一个道理：OSWorld 团队发现检查脚本会把合理的替代解法判错，也会被加载时序骗过，环路闭合之后，验收者的眼力决定了系统能走多远。交互一长，还会冒出另一个问题：看过的画面越来越多，早先那些画面要么被丢掉，要么被压缩成一句文字，等后面需要回头核对细节时，已经找不回来了。

长程视觉记忆：旧画面原样存档，随时调回来看

交互一长，早先的画面要么被丢掉，要么被压成一句文字。VISTA 不改模型，只在外面加一层 harness，把每一帧原样存档，让模型按回合号随时调回来细看。

2026 年 10 月，MIT 何恺明组的 VISTA 把这个问题单独拎了出来。它不改模型，只在外面包了一层 harness：模型直接以截图的形式观察环境，交互中的每一帧画面都原样存档，不转成文字；推理时，模型可以按回合号调出任何一帧旧画面，裁剪放大、并排比较、读出精确的像素值，还可以写笔记。论文摘要报告，在 ARC-AGI-3 上，它把 Claude Opus 5.0 的相对人类动作效率从 40.68 提到满分 100，25 个公开游戏全部完成，所用动作比第一次玩的人类少 57.4%。

这一段值得和前面几段对照着看。看图思考让模型在一张图上反复看，VISTA 让模型在一整段交互历史上反复看；GUI agent 的环路每一步都闭合，VISTA 则让很多步之前的结果也重新可见。它的局限也写在项目页上：存储和检索都依赖外部系统，模型自身的记忆能力并没有变强；三维环境里画面变化更复杂，项目页只给了两个游戏第一关的示意；公开游戏发布在模型之后，可能出现在训练数据里，真正的泛化要看私有测试集。VISTA 在第 18 章里是“感知接口也是 harness 部件”的例证，在本章则是环路闭合的最后一段。

两个出口：在学出来的世界里行动，用身体行动

环路闭合之后还有两条路：在学出来的世界里先预判后果再行动，或者用身体在真实世界里行动。2026 年的具身综述用同一把尺子量这两条路，发现预判和验证两环很少被单独评测。

走到这里，环路已经在工具、图像、屏幕、创作和长程记忆上一段段闭合了。再往前，图谱指出了两条路，各自已有专门的一章。

第一条是在学出来的世界里行动。屏幕之所以适合训练，是因为它可以重置、可以自动判分；可如果环境本身是一个学出来的模型，agent 就能在里面先“想一想”动作的后果，再决定要不要真的去做。世界模型一章讲的就是这件事。本章三.5 会看到一个很有意思的交汇：有人把世界模型用作 GUI agent 的验证器，先预测点击之后下一屏应该是什么样，再和真实的下一屏比对。

第二条是用身体在真实世界里行动。机器人和 GUI agent 一样，环路天生闭合，每做一步，相机都会回一张新画面；区别在于动作是连续的、不可撤回的，环境也没法一键重置。图谱的速查卡里有两张属于这条路：把动作切成 256 档当词来说的 RT-2，和在模型后面接一个用流匹配输出连续动作的动作专家的 π0。前者放在下面的速查表里作为过渡，后者（图谱卡片 X8）请到具身智能一章去读，那里用“叠一件 T 恤”的例子从头讲过。

2026 年的两篇综述可以帮你把这两个出口和前面几段放回同一张图里。Mokaria 等人的多模态 agent 框架综述把机器人、GUI 与网页导航、多媒体生成与编辑、长视频理解放在一起，按感知、推理、规划、记忆、行动五个模块比较；它指出把各种模态转成语言会丢掉大量信息，可以和本章开头的开环一段对照着读，那一段里语言模型只拿到视觉工具交回的文字描述，看不见工具的真实产物。2026 年 10 月 Chen 等人的多模态具身 agent 综述更进一步，用感知、预判、规划、行动、验证五种能力同时衡量 computer-use agent 和机器人，发现 64 个基准里只有 5 个评测预判、3 个评测验证。从屏幕走到身体，事先能定下来的选择更少，犯错后的挽回余地也更小，预判和验证这两环只会更要紧，这也正是世界模型和具身智能两章接着要讲的事。

1. 视觉工具与看图思考：返回的图片真的提供了新证据吗

当模型一眼看不清时，人会凑近看、放大看、换个角度看。于是很自然地，研究者给视觉语言模型配上了裁剪、放大、画辅助线、生成中间图像这类工具，让它在推理过程中再看一眼。这些工具确实改变了模型的观察，可并非每一张额外的图片都带来了新信息：有的只是把已有内容重新编码一遍，有的还会引入生成误差。要弄清楚收益从哪里来，就得固定原始输入，拿工具返回的结果和不用工具的基线比较，分辨收益来自补充了证据、重新分配了注意力，还是仅仅多花了计算。更长的视觉推理链和更可靠的推理之间，还隔着这样一道检验。

主线位置看图思考

“看图思考”阶段，并延伸到视频和外部检索。接 V*、Visual Sketchpad、o3 的 thinking with images 和 Pixel Reasoner，以及 OpenAI 自己列出的“推理链过长、感知错误、路径不稳定”三条局限。

给模型配上裁剪、放大、检索这类工具之后，先要证明返回的东西真的带来了新证据，再去讨论该怎样用、什么时候用。视频把这个问题放大了，证据常常藏在画面之外。

有一个很容易被忽略的因素：调用工具时写下的那段文字本身。模型在调用裁剪工具时要写出目标描述、坐标和意图，这一步已经在帮它组织问题了，哪怕它根本不去读返回的像素，后续推理也可能因此变好。要识别视觉证据真正的贡献，就得保留调用文字，只替换返回的图像，做一组对照。

2608.09682 · Thinking With Tools, Not With Pixels: Tool Calls as Text Scaffolds for Visual Reasoning 做的正是这组对照。它保留工具调用的文字结构，用占位文本替代返回的图片，比较完整图像工具链和只留结构的路径，还进一步拆分了推理文字和空间代码各自的贡献。在所测的数据分布上，返回图片的必要性受到了挑战。这个结论要读得准确：它说明一些基准允许结构化文字携带主要信息，图像在别的任务上依然可能不可或缺。真正需要读取新证据的任务应该成为更强的对照，比如只有裁剪放大之后才能认出来的随机金额。Simon Willison 觉得 o3 二十多次裁剪有些表演成分，这篇论文可以看作对那种直觉的一次系统检验。

三行之间只差工具返回的东西：第一行是完整工具链，第二行把返回的新图换成占位文本、调用文字原样保留，第三行完全不用工具。所以第一行和第二行的差，才是返回像素本身带来的新证据；第二行和第三行的差，来自调用文字帮模型把问题组织了一遍。第三行和右下那个框是为了说明读法画的示意，具体的实验条件以论文为准。

2609.19664 · VideoResearcher: Self-Improving Tool Design for Long-Video Understanding 从另一个方向改进工具。它运行“解题”和“演化”两个循环，分析轨迹里的证据缺口，然后设计、验证并复用新的可执行工具，改动落在工具上，提示词保持不动。这样能力的提升被放到了外部的工具设计里，不必更新模型参数。它的局限是验证集的选择和迭代预算可能带来过拟合；比较稳妥的做法是记录每次新增工具带来的收益，再到没有参与演化的视频上测试。

两篇工作之间形成了一种很有用的张力：一边在问现有的工具到底有没有必要，另一边在问还缺什么工具。一个好的工具系统应当先证明它带来了信息增益，再证明执行是正确的，最后才去比较总成本。工具调用的次数，说明不了推理有多深。

视觉工具有没有用，要同时看它增加了哪些信息，以及模型能不能用上这些信息。CausalDS: Benchmarking Causal Reasoning in Data-Science Agents 用可控的因果结构检查数据科学 agent 的代码、推断和恰当的弃答；它是证据使用方面的跨类对照，并不测试视觉定位。OmniReasoner: Thinking with Long Audio-Video via Native Tool Use 把看图思考推广到长音视频：模型先做一个低成本的全局预览，再通过监督微调和强化学习学会决定要不要、在哪里调用放大工具，把高保真的计算集中到相关的时间段上。它关心的是什么时候值得多花这份观察成本。

视频把这个问题放大了，因为证据不光藏在画面里，还常常藏在画面之外。Thinking Beyond Videos: Unifying Video Reasoning and Deep Research for Open-World Video Agents 把视频裁剪、多模态检索和网页浏览协调在一起，去处理那些只看片段答不出来的开放世界问题。证据一旦来自外部网页，核对来源也就成了任务的一部分。Video-DeepResearch: Towards the Next-Generation Multimodal Deepresearch Agent 在初步评测里抓到了两个很能说明问题的毛病：模型会绕开视觉工具，直接去做文字搜索；还会依赖参数里记住的知识，假装自己用工具查过。它的办法是把感知和外部探索拆开，分阶段解锁工具，强迫模型先做完跨帧的视觉定位，再去网上检索；作者报告 35B-A3B 版本在自建的 200 题多跳视频问答上平均 64.0%。AdaVDR: Adaptive Tool Use and Reflection for Video Deep Research 关心的是反过来的问题：不恰当的工具调用本身会产生错误结果，所以 agent 要按任务和自身能力挑工具，只在中间结果不可靠时才回退修正；作者报告它比基座模型在 VDR-EE 上高 15.20 个点，在已有的 VideoDR 基准上高 29.00 个点。三篇放在一起读，能看出“看”与“查”之间的分寸正在变成一个可以学习的决策。

三篇的共同问题是“看”与“查”之间的分寸，差别在各自管的是哪一种分寸：OmniReasoner 管成本，把昂贵的高保真处理只花在相关的时间段上；Video-DeepResearch 管顺序，第一阶段只开视觉工具，跨帧定位做完才允许上网检索；AdaVDR 管可靠性，执行之后检查中间结果，不可靠时才回退、换工具。

2026 年 10 月的两篇新工作把视觉工具推向了更通用的执行环境。OpenVLHarness: Real World Visual Agentic Tool-Use with Multimodal Memory（2610.26860）先做了一个对照研究：在 22 个基准上，单纯给基座多模态模型更多推理预算，视觉推理只涨一点点。它于是搭了一个两层的 harness，能力层把各种异构工具包装起来，并把它们的输出渲染成模型读得懂的观察；持久的多模态记忆把图像、结构化数据和网页引用存成可以取回的产物，再由一个编码接口在这些产物上运行生成的程序，把多个工具的结果组合起来。作者报告，在八个开源和闭源骨干上，它比匹配的无工具基线平均高 9.7 到 12.6 个点，搭配中等推理强度的 GPT-6 Luna 时，比最高推理强度下的基座模型、Codex 和 Visual Sketchpad 高 7.7 到 8.5 个点，模型 token 成本最多只有它们的 37%。S-Agent 2.0: Spatial Reasoning with a General Coding Agent（2610.28354）走得更直接：给一个现成的通用编码 agent 加一套命令行三维感知工具，让它获取场景证据、存进持久的场景记忆、再用平实的空间语言解释读数，作者称之为帮视觉语言模型“闭合证据回路”。作者报告，同一个 agent 加上这套工具后，Qwen3.8-27B 在 MMSI-Bench 和 ReVSI 上分别提高 13.9 和 20.5 个点，并且能在 Codex、Claude Code 等不同的编码 harness 上工作；一个有意思的观察是，骨干越强，专门工具的收益缩得越快，而这套通用工具的收益保持得更好。这两篇都把“看图思考”从一张图推广到了一个能存、能查、能编程的工作台上，和三.7 的长程视觉记忆可以对照着读。

2. 点击落点：语义正确之后，还要点在正确位置

主线讲过，SeeAct 发现模型常常知道该做什么，却说不准该点哪里；Simon Willison 也认为 computer use 最关键的进步是模型终于能报出可靠的坐标。可定位这件事比给物体画框要复杂：界面会缩放、会滚动、会被弹窗遮住，状态也在不停地变。上一帧里某个坐标对应“提交”按钮，等动作真正执行时，同一个坐标下可能已经换成了别的东西。所以比较定位方法时，静态截图上的定位精度和交互过程中的落点正确率是两个不同的量，还得看系统怎样处理刷新和重试。离线定位拿了高分，未必能换来可靠的操作。

主线位置屏幕

“屏幕”阶段的定位瓶颈。接 Set-of-Mark、SeeClick、UGround、CogAgent 把文字落到坐标上的工作，以及 Anthropic 关于“数像素”的说明和 Smol2Operator 的定位数据配方。

定位要过两道坎：先认对目标，再把它兑现成一次落在正确像素上的点击。失败时要把“选错了目标”和“坐标偏了一点”分开，两者的修法完全不同。

拿一句很普通的指令来体会：“点击总额下方的输入框”。它里面混着三件事：认出“总额”这个对象，理解“下方”这个相对位置，再换算成一个具体的动作坐标。前两件事主要是感知和空间理解，多模态理解一章有专门的空间定位分支，那里收录的 SpatioLM、Multi-View Relational Distillation、Qwen-3D、ReToken（v2 已改名为 *ReToken: Improving Long-Context VLMs with Visual Retrieval Token*）和 Mixture-of-Thought-Tokens，分别从训练时补几何、蒸馏多视角关系、三维场景识别、视觉检索 token 和落在空间位置上的思考 token 这几条路去补强。本章关心的是第三件事，也就是把这些空间知识最终兑现成一次落在正确像素上的点击。

从行动的角度看，这些空间方法都还要过一关：几何上的改善能不能保留到实际的落点上。SpatioLM 这类方法在空间问答上的提升，要通过实际的定位偏差和操作后果来检验，才能说转化成了 GUI 上的收益；多视角关系蒸馏解决的是几何对应，解决不了界面语义上的歧义，比如屏幕上有两个都叫“保存”的按钮。分析失败时，要把“选错了语义目标”和“坐标偏了一点”分开，这两种失败需要完全不同的修法：前者要更好的界面理解和任务记忆，后者要更好的定位数据，或者干脆换一种不依赖坐标的动作接口。

3. 动作接口：纯屏幕与混合工具各付什么代价

主线“屏幕”阶段留下的第一个分歧，在这里正面展开。纯屏幕接口最接近人的操作方式，适用范围最广，Anthropic 当初选这条路，看中的就是它能用“几乎任何软件”；可许多信息只能从像素里间接推断，每一步都要重新看懂一遍界面。原生工具和命令行能直接给出结构化的结果，却依赖平台提供的接口和权限约定。混合方案要回答的问题因此很具体：哪些操作值得绕开 GUI，哪些必须保留可视交互，两条路径之间的状态又怎样保持同步。Epoch 对 OSWorld 的审计让这个问题变得更尖锐：既然将近一半任务几乎用不着界面，比较不同系统之前，先得讲清楚它们被允许用哪些接口。

主线位置屏幕原生 GUI 模型

“屏幕”到“原生 GUI 模型”。接 Claude computer use 与 OpenAI CUA 的纯像素路线，WebArena、OSWorld 中混用结构化信息的框架路线，以及 UI-TARS-2 引入文件系统和终端的混合环境。

纯像素接口兼容面最广，每一步却都要重新看懂界面；结构化工具和命令行直接给出结果，却依赖平台的接口和权限。比较不同系统之前，先统一它们被允许使用的输入和工具。

先看两个把边界画得很清楚的系统。PalmClaw 在手机本地管理会话、记忆、技能和执行循环，并把设备能力作为参数和返回结果都很明确、带权限检查的工具开放出来。它提供了一种和“连续点击”很不一样的系统边界，适合用来比较两者的接口长度和权限的可解释性。HumanCLAW 来自身体行动的评测，它把高层的动作决策和低层的运动执行解耦开来，作者发现识别物体比导航和交互容易得多，主要原因是模型追踪不好自己的身体。它算不上 GUI 基准，却能帮我们理解同一个诊断原则：先把执行端的干扰控制住，再去测模型有没有选对动作。

人能操作的软件未必提供标准 API，所以纯截图加鼠标键盘有很广的兼容面。它的代价是每一步都要重新理解界面，批量处理一百个文件时会非常慢。引入命令行可以绕过不少界面上的摩擦，同时也带来了权限、文件副作用和评测条件上的差异。

2607.28227 · Qwen-UI-Agent Technical Report: Toward Next-Generation Real-World Centric Foundation GUI Agents 走的是混合路线。它把移动端、电脑、网页和搜索环境放进统一的工作流，动作空间里 GUI 和 CLI 交替出现，并支持一轮输出多个动作。它还把环境与任务的构建、失败诊断都纳入了训练迭代。这套方法的吸引力在于把跨设备办事当作一个系统问题来做；限制在于结果依赖环境基础设施和执行层，整套工程带来的收益不好全部归到骨干模型的参数上，批量动作也要重新检查中途有没有冒出弹窗。

2608.02352 · Qwen-CUA: Native Computer Use for (almost) Everything 则站在纯像素一边，只用截图观察和键鼠事件，不用 DOM、无障碍元数据和任务专用的 API；它保留最近的几张截图，把更早的视觉历史折叠起来。这样更接近通用的人类界面，却需要大量可以验证的交互经验，这正是主线“原生 GUI 模型”一段所说的数据瓶颈：专门模型的进步主要靠大量人类操作电脑的轨迹，而公开可用的轨迹数据集仍然很小。拿它和混合系统比较时，要先统一双方允许的输入和工具，否则“谁更强”可能只是在比“谁能直接访问文件”。它的历史折叠也要检查一下：被压缩掉的细节，会不会在后面某一步重新变成关键，这正是三.7 里 VISTA 想解决的问题。

2026 年 10 月阿里的 OpenGCUA: Toward a Fully Open Stack for Generalist Computer Use（2610.22200）把混合路线做成了一整套开放的栈。作者报告，在 OSWorld-v2 上，完整配置让所测的八个模型全部提分，平均部分得分提高 19.6 个点，每个任务的步数比只用 GUI 的批量执行平均少 53.0%；在四个真实 macOS 任务上，不同模型消耗的推理 token 差距可以达到十几倍。这组数字说明，接口和执行层的设计对成本的影响，可能不亚于换一个模型；第 18 章收录的那些只换外层程序、不换模型就省下大量成本的对照，是同一类证据。

光谱最左边是只看截图、只发键鼠事件的 Qwen-CUA，最右边是把设备能力包装成带权限检查的函数的 PalmClaw，中间两个紫色框是 Qwen-UI-Agent 和 OpenGCUA 的混合路线。最底下的粉色框是比较时要守的规矩：先统一双方允许的输入和工具。

对实际使用者来说，选接口之前不妨先写一张权限表：可以读哪些目录，可以写哪些应用，哪些动作必须让人确认。效率也不只是少点几次鼠标，遇到错误能不能恢复、有没有留下可以审计的记录，同样算在效率里。

接口的选择还要和适配数据、任务环境以及可执行的验收放在一起考虑。UI-Mate: Advancing Open-Weight Foundation GUI Agents with In-Context Demonstrations 通过环境化的训练和上下文中的示范，帮助 GUI 模型适应新的流程，可以用来比较“给示范”和“更新参数”两种适配方式的成本。CUA-Universe: A Scalable and Dynamic Environment for Hybrid GUI+CLI Agents 用动态的 GUI 与命令行混合任务来训练，研究跨工具的组合能力能否迁移到其他环境。RecreationWorld: Scalable and Verifiable Environments for Hybrid Computer-Use Agents 运行参考应用来产生轨迹和行为测试，把“看起来像是完成了”变成了可以执行的结果检查。这和 OSWorld 给每个任务配检查脚本是一脉相承的思路，只是它想把这件事做得更可扩展。

4. 轨迹、环境、奖励与停止：更多数据之前先保证反馈可信

主线说，原生 GUI 模型靠轨迹数据和在线学习变强。可交互数据有一个麻烦的性质：它把策略和环境绑在了一起。一条成功的轨迹里可能夹着大量无效动作，一条失败的轨迹里也可能有正确的观察和很有价值的恢复步骤。静态截图上的标签告诉不了模型一次失败是怎么发生的，而成功轨迹又常常缺少恢复动作的示范。在线强化学习能补上交互，前提是任务可以复位、奖励值得信任、采样预算花在有学习价值的地方。奖励设计还得分清动作是否有效、阶段是否完成、最终目标是否达成，并且说清楚系统什么时候必须停下来。停止信号如果不可靠，模型可能在已经成功之后继续操作，亲手把结果破坏掉。

主线位置原生 GUI 模型边界

“原生 GUI 模型与在线强化学习”的核心，同时触及边界。接 UI-TARS 的反思式在线轨迹、UI-TARS-2 的数据飞轮与沙箱平台、OpenCUA 的人类演示数据，以及 OSWorld-Verified 对“可靠奖励极其耗费人力”的复盘。

在线学习靠三条供给线：任务从哪里来，环境有多深，裁判信不信得过。三者分别管着数据供给、经验质量和信号质量，再加上一道“该停就停”的闸门，反馈才算可信。

把所有状态都塞给模型，并不会自动增加有效的经验。2607.11185 · SCALECUA: Scaling Computer Use Agents with Verifiable Task Synthesis and Efficient Online RL 把可验证的任务合成和在线训练结合起来：通过容器里的交互和多个 agent 的反馈来构造任务，再按模型当前的能力边界分配采样，并把视觉上下文分段，缓解训练压力。它同时回应了数据稀缺和训练吞吐两个问题。它的限制在于，自动生成的验收器也可能漏掉条件；评测时要把独立的人工任务和合成任务分开测，确认模型优化的是能力，没有只学会出题流程的固定套路。

环境从哪里来，是第二个问题。Echoverse: Deep, Evolving Environments for Training Computer-Use Agents at Scale 来自微软研究院，它的出发点是在线真实网站难以复位、难以大规模采样，于是合成一批有深度、会演化的环境，让任务带着真实的状态依赖。作者报告，一个 9B 模型在十二个环境上训练后，在十四个评测划分上的平均成功率从 36.5% 升到 67.1%；更有意思的是两个消融：浅的环境反而会拉低真实网站上的表现，深的环境才能带来提升；修好一个有问题的环境，在它上面训练的模型就从 16.2% 升到 38.5%。环境质量本身就是一个一阶变量。2026 年 10 月同样来自微软的 Agent World Model in the Wild: Computer-Use Agent Environment Synthesis（2610.26828）把环境合成做成了一条完全由开源模型驱动的流水线，环境里同时有 GUI、MCP 服务和命令行，质量控制包括基于执行的门槛、多个裁判的一致性检查和反事实探针；它产出 341 个长程环境与任务对，有些任务需要 100 步以上，GPT-6-Astra 也只能解出六成，只在这些合成环境里训练的两个 Qwen 模型在八个分布外基准上都有提升。

2607.28609 · OSReward: Instituting Standardized Evaluation for Cross-Platform Computer-Use Reward Models 把视角转向裁判本身。它用人工标注的跨平台轨迹来评测视觉模型的判定，再训练成本更低的奖励模型。最关键的是一个负面结果：裁判普遍偏宽松，会把没完成的任务判成完成。要是奖励器更相信 agent 自己写的文字历史，较少去看屏幕，强化学习就可能把这种偏差一轮轮放大。学习型奖励适合做规模化的初筛；文件是否存在、金额是否一致这类可以确定性检查的事，还是尽量交给确定性的验证去做。Echoverse 的消融也指向同一个方向：把有据可查的验证器和逐步的稠密裁判合起来用，比单用其中一种更好。

轨迹训练之间更细的区别，在于数据怎样产生、反馈针对哪个阶段，以及停止行为从哪里获得监督。HyMobileAgent: Data-Environment Co-Scaling for Efficient GUI Agents 同时扩展移动端的数据和环境，说明 GUI agent 的效率除了来自参数规模，也来自任务分布和交互条件。Inducing Task Models from Computer-Use Traces 把原始的操作轨迹整理成任务层次和程序控制流，为复用流程提供了一种比截图堆叠更有结构的记忆。Do GUI Agents Know When Not to Act? Enabling Conflict-Aware Termination for Multimodal GUI Agents 通过冲突识别和终止机制来处理那些根本无法执行的指令，并要求把“恰当地拒绝”和“普通的操作失败”分开计分。

图的四行汇进右上方的在线强化学习：策略能学到的东西，取决于任务、环境和裁判这几条供给线的质量。右下的粉色框单独画出停止，面对根本无法执行的指令，最好的做法是停下来报告，系统得为这种行为单独计分。

这几篇放在一起看，任务合成、环境深度和裁判质量分别管着数据供给、经验质量和信号质量，三者要配合着考虑。再加上停止这一环：面对“文件不存在却要求发送”这样自相矛盾的任务，系统要能正确地停下来，把它报告给用户，别一遍遍重试，直到偶然触发了某个奖励。OSWorld 2.0 总结的“该问用户时自己瞎猜”“做完不检查”，说的正是这一类问题。

5. 安全与统一接口：能跨任务复用，也能跨任务传播错误

统一接口降低了集成成本，也扩大了一条错误规则的影响范围。早在 2024 年发布 computer use 时，Anthropic 就把提示注入列为最担心的问题：模型会读联网电脑的截图，网页上的一段恶意文字就可能让它偏离用户的本意。到了今天，情况更复杂了。网页内容、截图里的文字、工具的返回值都可能被误当成操作指令，而能保存技能、记忆和程序的助手，又会把这种影响带到后续的任务里。屏幕本身也可能被伪造：一张看起来完全正常的截图，可能是攻击者重放的旧画面。安全设计因此要同时标明数据的来源、可执行的权限和共享的范围；界面可以统一，权限却要分得清清楚楚。

主线位置边界

“边界”中的安全一环。接 Anthropic 与 OpenAI 在发布电脑操作 agent 时提出的提示注入问题和多层防护，Simon Willison 引用的网页诱导下载演示，以及第 10 章把世界模型当作预测器的思路。

统一接口让一条错误规则能跨任务传播。只看屏幕的监控器会被重放的合法画面骗过，安全要看的是动作前后的转移；能保存技能和记忆的助手，还要追踪内容的来源和权限怎样一路传下去。

能保存技能、记忆和程序的助手，比一次性的问答器有用得多，也随之产生了新的信任边界。网页上的内容不能升级成用户的授权；自动生成的工具，也不会因为“是自己写的”就变得可信。

2608.06862 · SynChain: Inducing Computer-Use Agent Systems to Construct Their Own Attack Chains 分析了恶意影响怎样藏进持久化的产物里，在后续任务中被重新激活，整个过程不需要每次都有新的外部恶意输入。它把安全评测从单次提示推进到了跨任务的轨迹上。防御的重点也随之变成来源、权限和状态的传播，单靠某一轮的文字过滤是拦不住的。它所测的攻击目标和任务链仍然有限，一次抵抗成功，推不出所有技能库都安全。

跨任务的安全测试要跨越任务边界去设计：第一次任务写入了什么，第二次任务为什么会读取它，第三次有没有因此改变权限。ToolHazard: Scaling Adversarial Environments for Security Evaluation and Alignment of LLM-based Agents 合成对抗性的环境状态来测试间接指令注入，适合检查模型会不会把环境里的内容误当成高优先级的命令；作者报告，用它生成的数据做对齐，能明显提高鲁棒性，同时保住正常任务的效用。

2026 年 10 月的 Right Screen, Wrong Transition: World Models as Verifiers for GUI Agents（2610.11942）抓住了一个很巧妙的漏洞：安全取决于转移，也就是动作之后的那一屏，光看当前这一屏是不够的，因为攻击者可以把一个合法的屏幕重放给只看画面的监控器。比如同一张凭证输入页，前一步点的是“登录”，它是合法的；前一步点的是一个毫不相干的按钮，它就可能是被劫持后重放的画面，可两张屏幕一模一样。作者训练了一个不带解码器、以动作为条件的世界模型 LGWM，世界模型在这里指一个学会预测“当前这一屏加上一个动作，下一屏会是什么样”的网络；它在 185 万条真实 GUI 转移上学习预测下一屏的表示，于是检查一次转移就变成了比较预测和实际两个向量。他们还构造了一个基准，让每个输入凭证的屏幕都配一条合法转移和一条被劫持的转移，只看屏幕的检测器在上面只能靠猜。作者报告这个免训练的打分达到 0.987 的 AUC，每次判断 17 毫秒，与最强的闭源视觉语言模型相当，速度快三个数量级以上。论文把“验证”提为世界模型在模拟和规划之外的第三种用途。

图的上半部分是 LGWM 的转移级验证，下排换到更长的时间尺度：SynChain 发现，恶意内容可以在任务一里被写进技能、记忆或程序这类持久产物，任务二读取它，到任务三时权限或动作已经被悄悄改变。两部分合起来读，安全检查的单位从一张屏幕扩大到了一次转移，又从一次任务扩大到了一串任务。

统一模型还会带来另一种混淆：一张图像究竟是模型新画出来的作品，还是从屏幕上读到的证据，必须标得明明白白。2609.11244 · OmniHallu: Unified Hallucination Detection for Cross-Modal Comprehension and Generation in Multimodal Large Language Models 把多模态理解与生成中的幻觉拆成一条条原子声明，交给各模态的专家去核对，再训练一个低成本的验证器去近似这个过程；PixelUMM: Encoder-Free Unified Image and Video Understanding and Generation 探索直接从像素出发统一图像视频的理解与生成。这两篇的主体在多模态理解一章，放在这里提一句，是为了提醒设计验收层的人：内容是否真实和操作是否获得授权是两件事，生成能力本身也不构成执行上的授权。

The Interface of Theseus: The Rise of Just-In-Time Interfaces 从更远的地方提出了一个问题。当软件可以在几分钟内为每个人、每个任务临时生成时，界面本身可能变成用完即弃的东西。这对 GUI agent 既是机会也是麻烦：界面可以按 agent 的需要生成，可轨迹回放时，原来的坐标可能早已失去意义。可定制性怎样和可复现、可审计兼容，是接口设计迟早要面对的问题。

6. 闭环创作：看成品的那一眼由谁来做

闭环创作把环路接到了生成工具上。agent 写脚本、调用图像或视频模型、拿到渲染结果，再决定改哪里。这和 GUI agent 很像，每一步都有新的画面回来；区别在于这里没有一个“任务完成”的程序状态可以查，好不好全凭眼睛。图谱对这一段的判断很直接：模型的视觉判断力有多强，做出来的东西就能有多好。所以这个分支真正的研究问题，是怎样把“看成品”这一眼做得可靠、可训练，并且让整个创作过程的状态留得下来、改得回去。

主线位置闭环创作

“闭环创作”阶段。接 SceneCraft 用视觉语言模型检查渲染图、BlenderAlchemy 的状态评估器，以及第 16 章“Agent 编排与可编辑交付”分支对生成工作流的讨论。

创作循环里没有一个可以直接查询的“任务完成”状态，好不好全凭那一眼。研究问题因此集中在两处：怎样把看成品这一眼做得可训练，怎样把长程创作的状态留下来。

VideoGen-Agent: Reinforcing Video Generation Agents 把这个循环拿去做强化学习。agent 在多轮交互里协调增强、生成和验证三类工具，先用教师轨迹做监督微调，再用一个按任务类别区分的混合奖励做多任务强化学习，奖励同时看工具调用是否有效、工具用法是否合适，以及最终视频的质量。作者构建了一个 600 条提示的留出基准，报告 agent 把底层文生视频模型的分数从 56.5 提到 75.6；不重新训练 agent、只把生成工具换成更强的，分数还能升到 86.1。后一个数字很说明问题：学到的是调用和检查的策略，它可以随着工具变强而直接受益。这篇论文的主类在多模态生成，本章看重的是它把“验证工具”明确放进了动作空间。

另一个难点是长程创作的状态。JarvisHub: An Open Harness for Canvas-Native Multimodal Creative Agents 指出，真实的创作涉及参考、草稿、备选、编辑、失败的尝试、版本关系、工具动作和评估信号，这些合起来是一个不断演化的项目状态，线性的对话历史很难装下。它让 agent 在一张可编辑的项目画布上工作，把状态外置成一张图，使创作过程可查看、可追溯、可由人引导。这和 VISTA 把旧画面原样存档是同一种直觉：要让模型回头看，先得把能看的东西留住。

7. 长程视觉记忆与走出屏幕

交互一长，视觉 agent 就会遇到一个人类很少意识到的问题：旧画面去哪儿了。大多数系统为了控制上下文长度，只保留最近几张截图，更早的画面要么丢掉，要么压成一句文字描述。可很多任务恰恰需要回头核对：三十步之前那个弹窗里写了什么，游戏第一关的墙在哪个格子。与此同时，agent 的活动范围也在走出屏幕，进入需要主动探索的三维场景。这个分支收录的工作一头连着长程记忆，一头连着本章的两个出口。

主线位置长程视觉记忆两个出口

“长程视觉记忆”与“两个出口”。接 VISTA 的无损帧存档、Qwen-CUA 的历史折叠，以及第 10 章世界模型和第 11 章具身智能。

这个分支放了两件事：怎样让旧画面留得住、找得到，怎样让 agent 靠自己的动作去看见还没看到的东西。把 VISTA、SpatialScout 和 LGWM 放在一起，会得到三种时间方向上的“看到结果”。

VISTA: A Visual Harness for Reasoning in an Interactive World（2610.02200）的设计很克制。项目页写明，模型拿到的是原始的 512×512 PNG 画面，用自由形式的语言推理，通过查看和读像素两类调用去访问无损的视觉记忆，没有程序合成，也没有针对具体游戏的逻辑。论文摘要报告 Claude Opus 5.0 的相对人类动作效率从 40.68 提到 100，作者称据他们所知这是第一个不靠程序合成就拿到满分或接近满分的系统。读这组数字时要记住两点：项目页给出的官方最小接口基线与摘要里的起点数字并不相同，引用时要注明出处；公开游戏可能出现在模型的训练数据里，私有测试集才是真正的泛化检验。它和三.3 里 Qwen-CUA 的历史折叠正好构成一组对照：一个把旧画面压缩掉以控制成本，一个把旧画面原样留下以便回查，哪种更合适，取决于任务里关键信息出现和被需要之间隔了多久。

走出屏幕的第一步，是让 agent 自己去看它还没看到的东西。SpatialScout: Can VLM Agents Actively Explore and Map 3D Scenes?（2610.26659）给视觉语言模型 agent 一份物体清单、RGB 观察、相机标定和位姿，让它在有限的交互预算内控制相机去探索 80 个室内场景，估计 3140 个目标物体在统一坐标系里的中心位置，考察选视角、跨视角关联、几何估计和地图修正这几项能力。作者报告最强的模型平均重叠得分只有 41.71%，超过 0.5 IoU 的目标占 47.23%，超过 0.9 的只有 3.25%。粗略的物体布局和完整精确的度量地图之间，还隔着很大一段路。这件事在屏幕上不太明显，因为截图总是完整的；一旦视野要靠自己的动作去换，主动观察就成了 agent 的基本功，这也是具身智能一章反复讨论的问题。

另一个出口是把世界模型用作 GUI 动作的验证器：三.5 收录的 Right Screen, Wrong Transition 训练了一个预测“点击之后下一屏应该是什么样”的模型 LGWM，再和真实的下一屏比对。把它和 SpatialScout、VISTA 放在一起看，三者补的是同一件事的不同时间方向：VISTA 让过去的结果重新可见，SpatialScout 测 agent 能不能主动让眼下未知的部分变得可见，LGWM 则让还没发生的结果提前可见。本章开头那个问题，模型能不能看到自己行动的结果，在这里有了三种时间方向上的回答。

五、负面结果与开放问题

本章的几个负面结果放在一起，指向同一条方法论：用干预实验找出收益从哪里来。开放问题集中在四处：把三种能力绑在一起考的基准，独立的验收信号，可以重放的轨迹，以及创作里“好不好”的可检查性。

这一章里有好几个负面结果，单看每一个都像是给热闹的方向泼冷水，放在一起却能读出一条很实在的方法论。Thinking With Tools, Not With Pixels 把工具返回的图片换成占位文本、只保留调用文字，在所测的数据分布上，返回图片的必要性受到了挑战，工具调用带来的收益未必来自返回的像素，也可能来自调用文字本身搭起的推理结构。Video-DeepResearch 发现视频 agent 会绕开视觉工具直接搜文字，还会拿参数里记住的知识假装自己查过。OSReward 发现学习型裁判普遍偏宽松，会把没做完的任务判成完成。Echoverse 发现只在浅的合成环境里训练，模型在真实网站上反而变差。Right Screen, Wrong Transition 发现，攻击者把一张合法的凭证输入页重放出来，只看屏幕的监控器就分辨不出这一屏是不是被劫持后才出现的。再加上主线里的两条：Epoch 发现 OSWorld 将近一半任务几乎用不着界面，OSWorld-Verified 发现基准本身有大量需要修补的问题。它们共同要求我们去做干预实验，光换更大的模型是解释不了收益来源的：屏蔽返回的图像，移除历史，替换裁判看到的证据，换掉环境的深度，然后观察收益从哪里来。每次只改变一个关键因素，才能把因果关系讲清楚。

未解决的问题主要有四组。第一，有没有一个基准，同时要求细粒度的新观察、长期视觉记忆和真实执行，把三种能力真正绑在同一个任务里考？OSWorld 2.0 的长流程任务往这个方向走了一步，最好的配置完整完成率也只有 20.6%。第二，当奖励器和执行器共享同样的视觉偏差时，怎样得到独立的验收信号？第三，任务、界面和权限都在持续变化时，怎样保留可以重放的轨迹，同时避免记忆里的旧假设继续支配动作？第四，闭环创作里那一眼“好不好”的判断，能不能像 GUI 任务的程序状态那样变得可以检查，至少在一部分维度上？这些问题，都没法靠一个总成功率来回答。

六、研究机会

回到开头那次报销，还没被做好的四件事对应四个研究方向：贴近真实工作的跨应用环境，主动选择观察，长程视觉证据的留存，以及界面变化之后的可靠执行。

回到开头那次报销。要让一个 agent 真正替你办完，它得先看懂三种不同来源的票据，这是多模态理解解决的事；然后在一个老旧网页里找到正确的输入框、填对数字、等页面加载完、确认提交真的成功，这是本章主线正在解决的事；它还得记得半小时前在邮箱里看到的那张小票上写着什么，知道自己哪一步不确定、该停下来问你，而且不能被网页上的一段奇怪文字带偏。下面四个方向，分别对应这个例子里还没被做好的四件事。

1. 如何构造覆盖真实跨应用工作的多模态交互环境？

静态截图和孤立的点击，很难表达软件工作里的状态依赖、等待、权限和跨应用的交接。报销这件事，就要在邮箱、PDF 阅读器、相册和网页之间来回切换。这里的研究机会是构建可以复位、又保留真实约束的桌面或网页环境，让任务覆盖自然的工具组合和失败分支。OSWorld-Verified 的经验说明，这类环境最贵的部分是可靠的结果检查；Echoverse 的消融说明，环境的深度和是否被修好，会直接决定训练出来的模型好不好。Epoch 的审计还提醒我们，设计任务时要想清楚它究竟在测界面操作，还是在测终端技能。

2. 如何让 agent 主动选择需要观察的视觉信息？

全屏高分辨率输入、历史截图和工具返回的图像之间，存在成本与证据覆盖的取舍。读一张手机拍的小票，可能需要放大好几次；扫一眼报销系统的首页，低分辨率就够了。可以研究怎样根据当前的不确定性，选择裁剪、放大、重新观察或者调用视觉工具，把“观察”本身当作一种可以学习的动作。关键是衡量这些选择是否保留了后续任务需要的信息，并把观察缺失和推理错误区分开；Thinking With Tools, Not With Pixels 那组“保留文字、替换像素”的对照，是一个很好的实验模板。

3. 如何让长程交互里的视觉证据留得住、找得到？

报销做到一半，系统要求填写发票号，而那张小票是二十步之前在相册里看过的。VISTA 证明了原样存档加按需回查在二维游戏里非常有效，Qwen-CUA 则选择折叠旧历史以控制成本。一个有价值的方向是系统地刻画“关键信息出现的时间”和“被需要的时间”之间的距离怎样影响这两种做法的优劣，以及怎样让模型自己学会决定哪些画面值得留、什么时候该回头看。评价时要构造信息相隔很远、只有回查原图才能答对的任务，只看总分会掩盖记忆是否真的起了作用。

4. 如何从局部感知与操作能力走向跨界面、长流程的可靠执行？

界面一变，语义目标、空间定位和已经形成的操作习惯会同时受到影响。报销系统哪天改了版，按钮挪了位置，agent 就得重新建立对应关系。研究机会在于把任务记忆、状态确认和恢复策略连接起来，让系统在布局变化或动作失败之后，能重新找到正确的对应；Right Screen, Wrong Transition 那种转移级的验证，可以成为状态确认的一块现成积木。评价时要主动改变界面、工具和任务组合，观察单项能力能否组成完整的工作；只扩充静态的定位样本，回答不了这个问题。OSWorld 2.0 里那些“忘了约束”“漏看中途信息”“做完不检查”的失败，都是很好的起点。
